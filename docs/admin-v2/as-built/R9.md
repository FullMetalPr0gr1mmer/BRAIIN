## Plan (written before building)

**Scope.** The R8 seam gets its one entry: the `/admin/preview` branch of `src/middleware.ts`,
after the session gate. It answers GET and HEAD only; gates on `assertAnyCap(session,
PREVIEW_READ_CAPS, ['full', 'view', 'meta'])`; refuses when `pageAccess()` is set; maps the
path to a Tier A route (`src/lib/preview/routes.ts`, EN and AR, unknown paths a preview 404);
builds `createPreviewSource({ supabase: locals.supabase, session: locals.session, only })`;
renders the PUBLIC route through Astro's rewrite (`next(publicPath)`) inside
`withContentSource`, so the preview runs the very code the public page runs; then reads the
verdict and injects the ribbon. Private, no-store, no Cache-Tag, `X-Robots-Tag: noindex,
nofollow`, strict CSP with the per-request nonce. `frame-src 'self'` on `/admin/**` only.

**Files.**
- `src/lib/preview/routes.ts` (the Tier A route map), `src/lib/http/preview.ts` (the
  middleware branch, testable), `src/lib/preview/ribbon.ts` (the ribbon's HTML from the verdict,
  the page's visibility and the links; escaped; injected after `<body>`).
- `src/middleware.ts` (the branch; every private response loses `Cache-Tag` and gains
  `noindex`), `src/lib/http/securityHeaders.ts` (`frameSelf`).
- `src/layouts/BaseLayout.astro` (preview mode: no consent banner, RUM, page view or error
  reporter; robots `noindex,nofollow`; the bridge), `src/components/SectionRenderer.astro`
  (`data-pv-section` in preview only), `src/lib/data/pageSections.ts` (keeps the section id).
- `packages/schemas/previewMessage.ts` (the envelope), `src/lib/admin/preview/bridge.ts` (the
  in-preview side), `src/lib/admin/preview/paths.ts` (public path ↔ preview path, shared),
  `src/lib/admin/previewChannel.ts` (the parent side, for E2),
  `src/components/preview/AdminPreviewBridge.astro` (loads the bridge; its chunk is `Admin*`).
- `public/styles/preview.css`, `src/pages/admin/preview/[...path].astro` (the preview 404).
- `astro.config.mjs` (an `admin-preview` group), `scripts/admin-bundle.mjs`.

- Help: the guide, `PAGE_GUIDES`, the spec's claims (written ahead of H11; once the catalog

## What was built

**The branch** (`src/middleware.ts` step 2a, `src/lib/http/preview.ts`). After the session gate,
a request whose path or matched route is `/admin/preview…` goes to `handlePreview`: GET and
HEAD only (405 otherwise; a mutation meets the CSRF check first); `canPreview` then
`assertAnyCap(session, PREVIEW_READ_CAPS, ['full', 'view', 'meta'])` (`canPreview` first, so a
role the matrix does not know, a future Sales token, is a 403 and never indexes the matrix);
403 inside a page-access scope (U14b); the route map (below): a malformed `only` is a 400, an
unknown path renders the route Astro matched (`src/pages/admin/preview/[...path].astro`, a 404
inside the admin that reads nothing); `createPreviewSource({ supabase: locals.supabase,
session, only })`; the live visibility snapshot into `locals.visibility` (the menus read it);
`withContentSource(source, () => next(publicPath))`; `assessPreview(source.report())`, an
untrusted verdict logged once to `system_logs` (`source: 'preview'`, the route, the reasons,
`previewLogFields`); a 30x the public page answers is kept inside the preview (same origin, a
Tier A path, the `only` selection carried); the ribbon spliced after `<body>` and `preview.css`
before `</head>`. The middleware secures the answer with the nonce, and a preview render gets
`form-action 'none'`.

**Headers, every private response.** `Cache-Control: private, no-store, max-age=0,
must-revalidate` (as before), `Cache-Tag` deleted and `X-Robots-Tag: noindex, nofollow` added
(the public page's `setTierA` tags would otherwise ride a preview out). `frame-src 'self'` on
every `/admin/**` page response (`buildCsp`'s `frameSelf`), never on a public one; `noForms`
(`form-action 'none'`) on a preview render only.

**The route map** (`src/lib/admin/preview/paths.ts`, client-safe, and
`src/lib/preview/routes.ts`). The Tier A routes, EN and AR: `/`, about, contact, join, services
and `/services/[slug]`, portfolio, `/portfolio/all` (before `[slug]`), `/portfolio/[slug]`, the
blog and its posts, search, the three legal pages and `/404`. A slug is letters, digits and
hyphens, so nothing but a known pattern reaches Astro's rewrite (no `%`, dot segment,
backslash or second slash). The query string goes along but `only`.
`tests/lib/previewRoutes.spec.ts` holds the list to `src/pages` (every public page file is
previewed or named; the Arabic catch-all is named).

**BaseLayout's preview mode** (`Astro.locals.preview`, set by the branch only): robots
`noindex,nofollow`; no `ConsentBanner`, `WebVitals`, `PageView` or `ErrorReporter`;
`AdminPreviewBridge` in the `<head>`, before every script the page renders. Module scripts run
in document order (each deferred until the document is parsed), so the bridge has replaced
`fetch` and `sendBeacon` before any page script runs; rendered after the footer, as first
built, it came after the search page's script, whose initial `?q=` reached `/api/search`
before the bridge was installed (`tests/render/previewLayout.spec.ts` holds the order). **Section markers**: `SectionRenderer` hands SectionBoundary a
`previewId` (the row's id, or `default-<n>` for a built-in composition) in a preview only, and
SectionBoundary puts `data-pv-section` on the section's own first element
(`src/lib/sections/previewMarker.ts`), not on a wrapper, so a preview lays out as the public
page does. The public `page_sections` read now selects `id` (whole-table anon grant, 0016).

**The bridge** (`src/lib/admin/preview/bridge.ts`, chunk `admin-preview`, loaded only by
`src/components/preview/AdminPreviewBridge.astro`, whose script chunk is `Admin*`).
`packages/schemas/previewMessage.ts`: version 1, strict objects. Parent to preview: `jump`,
`highlight` (a section id or null), `scroll`, `reload`, `tokens` (`ThemeTokensSchema`, at most
200, applied with `style.setProperty`; the schema moved to `packages/schemas/themeTokens.ts`
and is re-exported by `admin.ts`, so the bridge does not pull the admin schemas). Preview to
parent: `ready` (path, locale, sections with their anchors), `scroll`, `navigate`. Posted with
`location.origin` as the targetOrigin; accepted only from that origin AND from the parent (the
preview side) or the frame's window (`src/lib/admin/previewChannel.ts`, E2's side), and only
if it parses. In the page: a click on a same-origin link to a previewable page is rewritten
into the preview (the `only` selection kept) and reported; every `submit` is stopped in the
capture phase before the page's own handler, with a polite notice; `fetch` refuses any method
but GET and HEAD, and any read of the site's own `/api/**` but `READ_ONLY_ENDPOINTS`
(`/api/apply/status`), because a GET can write: `/api/search` records every query for the SEO
report, so a search in a preview, typed or an initial `?q=`, finds nothing and is not recorded;
`sendBeacon` sends nothing. `READ_ONLY_ENDPOINTS` lives in `src/lib/admin/preview/paths.ts`, read
by the bridge and the server alike.

**The render's CSP, the second layer.** A preview render's `connect-src` is exactly
`READ_ONLY_ENDPOINTS` at the request's origin (`previewConnectSources`, `src/lib/http/preview.ts`;
`buildCsp`'s `connectOnly`), not `'self'`: the browser refuses every other request from the first
byte, whether or not a script ran before the bridge. A listed source that is not an exact
`http(s)` URL with a path is left out, and an empty list is `'none'`, so the directive fails
closed. The preview's own 404 is an admin page and keeps the admin policy. A preview has nothing
else to connect to: the consent banner, RUM, page view and error reporter are not rendered, the
contact and Join forms' POSTs are refused by the bridge, and video is `media-src`.

**Ordering ties (R8's D10).** Every loader query ordered by `sort_order` (and the blog by
`published_at`) adds `.order('id')`: 12 queries in 9 files, plus `page_sections`. PostgREST
returns tied rows in heap order, the preview in key order, and the seed has ties (the
placeholder and the real clients share 1 to 6). Publicly this changes only the order of rows
whose order was unspecified (heap order moves after an UPDATE, so it was never stable).

**The design-sample gap (R8 item 19).** The dataset counts a change it shows that leaves an
`is_placeholder` row live (status published or scheduled on portfolio, testimonials,
team_members, statistics, service_cases; `visible` on clients and page_sections: 0025, 0028)
in `report.samples`, and the ribbon says the live site refuses that unless the owner allowed
samples there (0027). The change is still shown: the Worker cannot tell production from
staging (`app.is_production()` is unreachable by API roles, by design), nor read the override.

**Help.** The guide `previewing-changes` (the nine keys, EN and AR block for block,
`sort_order` **95**, R9's assigned place: U7 holds 45, C10a 65, C9a 75; 3 minutes, tags content
and site; caps = `PREVIEW_READ_CAPS`, twelve, the catalog's CHECK limit; screens
`/admin/preview`, `/admin/pages`, `/admin/visibility`) was written ahead of H11 as a JSON file.
With the catalog on `main` it is the slice's migration: one top-level
`select app.put_help_guide($guide$ {…} $guide$::jsonb, 0);` (a new guide, revision 0), with
postconditions (in the catalog once at revision 1, place 95, twelve caps; every tenant holds it
as the catalog renders it; the set lists it at 95). The JSON file is gone: the migration is the
one source, read by the tests through `tests/fixtures/helpSet.ts`. Its `PAGE_GUIDES` entry
offers it on `/admin/preview` (so on the preview's own 404 page) to the roles that may preview.
A capability `PREVIEW_READ_CAPS` gains cannot simply join the guide (the put would fail, 23514):
the guide's caps would be narrowed to the areas.
`tests/admin/routes.ts` `pageFileFor` learned the rest route that answers `/admin/preview`.

**The preview's 404 under the browser.** Chromium reports every document that answers 404 as a
console error about that document ("Failed to load resource: the server responded with a
status of 404 (Not Found)", located at the document's URL; reproduced locally with the repo's
Playwright Chromium). The page must answer 404, so the isolation spec expects exactly that
report, once per load (three widths), and nothing else: any other console error, a page error
or a CSP violation still fails it. Its watcher records the URL a console error names, as the
sweep does.

## Departures from the design, and why

1. **No page refactor into load functions and views** (releases.md §6.3 item 5 and the R9
   slice). The preview renders the public route itself through Astro's rewrite (`next(path)`
   from the middleware, which Astro does not run again) inside the content scope. The page
   files stay the one implementation of each page, so parity holds by construction, and the
   public pages and their lhci and layout-shift gates are untouched. The README (which wins)
   asks for the route, the seam and the parity e2e.
2. **The ribbon is spliced by the middleware, not rendered by BaseLayout.** Only after the
   render is the report final (a section component reads late); BaseLayout would draw the
   ribbon before the reads that decide it. The same splice serves the password prompt, which
   has no BaseLayout.
3. **A page behind a password previews as its prompt** (R8 asked R9 to choose). The seam reads
   its sections as a visitor does (0061's fence), so the page behind it would be the built-in
   composition, not the page. Lifting the fence for previews needs a second mirror rule: left
   for E2 if editors need it.
4. **A hidden or link-only page renders** (staff preview it) with a line saying what visitors
   get; listings use the live snapshot (pending visibility changes stay not previewed, R8).
5. **`form-action 'none'` and the request guard** go beyond "form submits are blocked": the
   CSP holds without the bridge, and the guard covers a form a script sends with `fetch`.
6. **The parity e2e compares markup, not text, order and hrefs**: stronger, with named
   normalisations. It does not assert the ribbon's state: R8's tripwire is isolate-wide (D1),
   and a public spec served by the same `wrangler dev` isolate can mark a render untrusted.
7. **The bridge lives at `src/lib/admin/preview/bridge.ts`** (P-4: under `src/lib/admin`), not
   `src/scripts/previewBridge.ts`; its loader is an Astro component so its chunk is `Admin*`.
8. **`/admin/preview` is not in the per-role sweep** (`EXTRA_LINKS`): it renders a public page
   with no admin sidebar, which the sweep would fail; its own e2e covers every role, axe, CSP
   and headers. The preview's own 404 is an admin screen, but the sweep expects a 200, so the
   isolation spec runs the sweep's checks on it instead (axe, overflow at three widths, CSP,
   console, no `style=` in the server HTML).
9. **The guide ships in a migration after all.** The slice was planned with none; H11's
   catalog landed while it was in review, and a guide is put by a migration, so R9 carries one
   (the put alone). Its page-guide entry moved from `PENDING_PAGE_GUIDES` (gone) into
   `PAGE_GUIDES`.
10. **No `?v=<n>`** (R10's).

11. **`connect-src` narrowed on a preview render** (not in the design): the bridge alone
    could not stop a request a page sends before it runs; the CSP holds from the first byte.

## O-16, measured (not on staging)

Home, the heaviest route, run as its loaders in one preview scope over the R8 fixture in Node
(`fakeStaffClient`, one call per `range()` page): **18 subrequests** (17 tables: Home's content
closure with its embeds and the media rule, plus one drafts read), 13 overlay reads, about
**5 to 6 ms** warm (about 90 ms on the first run of an isolate) for the reads, the overlay, the
mirror and Zod, before Astro renders a byte. Add the session (`getUser` and the profile, 2 to
3) and the visibility snapshot (memoised KV): about 21 subrequests, under the Free plan's 50.
CPU: the public Home render's own cost comes on top, so a preview of Home is likely over the
Free plan's 10 ms. To measure on staging before R12 makes the preview a daily tool.

## Self-review

- **Security.** A role `ROLE_CAPS` does not know (a future Sales token) made `assertAnyCap`
  index the matrix with it and throw a TypeError (a 500, not a 403): `canPreview` now answers
  first (`previewHandler.spec`, "refuses an inactive session and a role that reads no area",
  fails without it). The public page's `Cache-Tag` rode out on a preview: now stripped from
  every private response. A preview form could still send by `fetch` from a page script:
  the bridge's request guard and `form-action 'none'`.
- **Correctness.** Rows tied on `sort_order` (the seeded clients) would have failed parity
  (R8's D10): `id` tiebreakers. A wrapper per section would have changed layout between preview
  and public: the marker goes on the section's own element. `/services/` with a slash is a
  page (trailing slashes are ignored), not a refusal.
- **Bundle.** Public JS 25.51 KB gz (no public chunk changed: the bridge and its loader are
  `admin-preview` and `Admin*`). The admin sum is 315.17 KB against `main`'s 312.91 (C4c):
  +2.26 KB, the bridge and the envelope. The pre-merge review found the bridge importing
  admin-ui for zod, which pulled admin-ui and React (admin-vendor) into every preview render,
  about 120 KB gz loaded and never run: zod and the envelope are now their own group,
  `admin-zod`, above admin-ui, and `admin-bundle.mjs` check 7 fails a build whose bridge
  reaches admin-ui or admin-vendor. Measured after: the bridge's own graph is 15.6 KB gz (its
  script 0.2, `admin-preview` 2.1, `admin-zod` 13.3); `admin-bundle.mjs` reports 123.6 KB
  because it adds the admin shell, which a preview does not load; the admin sum is 315.71 KB.
- **After review.** A preview of `/search?q=…` still wrote a `search_queries` row: the search
  page's script runs its initial `?q=` at once, and its module script came before the bridge
  (rendered after the footer), so `fetch` was still the browser's. Fixed in two layers: the
  bridge in the head, and the render's `connect-src` narrowed to `READ_ONLY_ENDPOINTS`
  (`previewHandler.spec` and `previewLayout.spec` fail without each). The preview 404's e2e
  failed on Chromium's own report of the 404 status: it now expects exactly that report per
  load and nothing else.
- **Open, by design.** R8's tripwire is isolate-wide (its D1): under public traffic in the
  same isolate a preview can be marked untrusted and logged. Measure on staging (owner
  question below) before demoting `anon-lookup` to a log line.
