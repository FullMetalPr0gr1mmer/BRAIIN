## Plan (written before the build)

A custom page is a `pages` row whose slug is not one of the seven route slugs (`PAGE_PATHS`).
No kind column: the slug says it, and the route map is the one list both halves read. Everything
it writes goes through the resource kernel's existing routes (`POST /api/admin/pages`, the
section routes), so releases off it is a live save and releases on the kernel stages it (R3a);
there is no second write path.

1. **The slug rules, one pure module** (`packages/schemas/pageSlug.ts`): the route slugs (equal to
   `PAGE_PATHS`' keys, test), the reserved words (every top-level segment of `src/pages` and
   `public/`, the Worker's own paths, `admin`, `api`, `ar`, `media`, `styles`, `en`, …; a test
   walks both directories so a new top-level route cannot ship without its word), the custom
   shape (lowercase kebab-case, at most 64 characters), `isCustomPageSlug`,
   `CustomPageSlugSchema` and the plain-words refusals. `PageWriteSchema` (create) takes a custom
   slug only; the update schema refuses a reserved word.
2. **Migration 0123 (expand only):** one trigger on `pages`, `app.tg_pages_slug_rules()`, BEFORE
   INSERT OR UPDATE OF slug: the shape, every reserved word refused for every writer (the service
   role and the migration role included), and a route slug refused on INSERT for a staff token (a
   role claim; seeds and migrations carry none). 23514 with its own constraint names, which the
   Worker maps to the slug field. The literals equal the TypeScript lists (test). No grant, policy
   or registry change: `pages_write` (Admin + Content Creator), the archive and delete RESTRICTIVE
   policies (Admin) and 0038's registry row already cover a custom page. pgTAP over admin,
   content_creator, seo, developer, anon, other_tenant; a production read-back.
3. **The public routes** (`src/pages/[slug].astro`, `src/pages/ar/[slug].astro`, Tier A): the
   slug is checked against the custom shape and the reserved words before anything is read
   (a probe costs no query), then `getPageComposition(slug)` (published, under RLS; a password
   page's unlocked read as U14b built it). Unknown, unpublished or reserved: the 404 page by
   rewrite (as `/ar/[...path]` does), so authored redirects still answer after it. Rendered:
   SectionRenderer over the sections a custom page may hold (E10's blocks and the generic types;
   any other type stored on it is not rendered), the first hero as a banner (no intro plate, the
   CTA to Our Work, matching its built-in label), and a floor: with no visible heading section
   the page opens with a banner hero titled with the page's title (one `<h1>`, always).
   `BaseLayout` (SeoHead: the page's SEO override, else its title and a description from its
   first text; per-language self-canonical, reciprocal hreflang + x-default, from the layout),
   JSON-LD `WebPage` + `BreadcrumbList` (Home > page), `setTierA` with `route:page`,
   `page:<slug>`, `media:all` and `sectionTags`. Both languages.
4. **The readers that hold paths:** `src/lib/visibility/routes.ts` learns custom pages
   (`targetForRoute` takes the route's params: `/[slug]` with a custom slug is that page;
   `targetForPath` reads one custom segment; `localizedPagePath` and the redirect target accept a
   custom slug), so page visibility (hidden, link only, password, the window) and maintenance
   hold for a custom page exactly as for a route page, before the render. `pagePath` (SEO list,
   pages list, editor), the sitemap (both languages, `<lastmod>` from `updated_at`, visibility and
   indexability filtered), llms.txt (a Pages list), the preview route map (`/[slug]`, reserved
   words excluded by the pattern), the nav editor's link picker, the Tier A route table
   (`route:page`, within 30 tags) and the release purge (`page:<slug>` already, through the
   registry's page row).
5. **The admin:** "New page" on the pages list for `pages.write` (Admin, Content Creator): a
   dialog (title in English and Arabic, the address, suggested from the English title, the rules
   said under the box), POST through the kernel (`stagedUrl` in release mode, R12b), then the
   editor opens on the new page with a hero titled with the page's title. The editor takes a
   custom page: "Add section" offers the custom set, the hero carries an honest note, the live
   preview frames `/<slug>` and `/ar/<slug>`, and with releases on a pending page opens from its
   draft and the list shows it. The section routes refuse a type a custom page cannot hold
   (422), so the set holds at the API too. Page visibility lists custom pages.
6. **Seeds:** one sample custom page (`how-we-work`: a hero and a text block), a placeholder:
   published locally, in CI and on staging (lhci, axe, served-html, preview parity), a draft in
   `production.sql`.
7. **Tests:** vitest for the slug rules (shape, reserved words, the directory walk, SQL parity),
   the loader's pure parts (allowed types, the heading floor, the hero data, the JSON-LD), the
   route map, the preview map, the sitemap and llms filters, the section refusal, the pages list
   (pending creates), the library; pgTAP; e2e (CI): the custom page in both languages (status,
   h1, canonical, hreflang, JSON-LD, Cache-Tag), an unknown slug and a reserved word 404, axe,
   served-html and share-image through `publicRoutes.ts`, preview parity, lhci on both routes,
   and the New page dialog signed in as Admin.

**Not built (said in the as-built):** site search does not index custom pages (`search_content`
covers services, posts and projects); a custom page's slug is set once in the dialog (the
editor's page panel has no address field, as on every page).
