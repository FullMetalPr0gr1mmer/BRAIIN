## Plan (written before the build)

A custom page is a `pages` row whose slug is not one of the seven route slugs (`PAGE_PATHS`).
No kind column: the slug says it, and the route map is the one list both halves read. Everything
it writes goes through the resource kernel's existing routes (`POST /api/admin/pages`, the
section routes), so releases off it is a live save and releases on the kernel stages it (R3a);
there is no second write path.

1. **The slug rules, one pure module** (`packages/schemas/pageSlug.ts`): the route slugs (equal to
   `PAGE_PATHS`' keys, test), the reserved words (every top-level segment of `src/pages` and
   `public/`, the Worker's own paths, `admin`, `api`, `ar`, `media`, `styles`, `en`, …; a test
   walks both directories so a new top-level route cannot ship without its word), the custom
   shape (lowercase kebab-case, at most 64 characters), `isCustomPageSlug`,
   `CustomPageSlugSchema` and the plain-words refusals. `PageWriteSchema` (create) takes a custom
   slug only; the update schema refuses a reserved word.
2. **Migration 0123 (expand only):** one trigger on `pages`, `app.tg_pages_slug_rules()`, BEFORE
   INSERT OR UPDATE OF slug: the shape, every reserved word refused for every writer (the service
   role and the migration role included), and a route slug refused on INSERT for a staff token (a
   role claim; seeds and migrations carry none). 23514 with its own constraint names, which the
   Worker maps to the slug field. The literals equal the TypeScript lists (test). No grant, policy
   or registry change: `pages_write` (Admin + Content Creator), the archive and delete RESTRICTIVE
   policies (Admin) and 0038's registry row already cover a custom page. pgTAP over admin,
   content_creator, seo, developer, anon, other_tenant; a production read-back.
3. **The public routes** (`src/pages/[slug].astro`, `src/pages/ar/[slug].astro`, Tier A): the
   slug is checked against the custom shape and the reserved words before anything is read
   (a probe costs no query), then `getPageComposition(slug)` (published, under RLS; a password
   page's unlocked read as U14b built it). Unknown, unpublished or reserved: the 404 page by
   rewrite (as `/ar/[...path]` does), so authored redirects still answer after it. Rendered:
   SectionRenderer over the sections a custom page may hold (E10's blocks and the generic types;
   any other type stored on it is not rendered), the first hero as a banner (no intro plate, the
   CTA to Our Work, matching its built-in label), and a floor: with no visible heading section
   the page opens with a banner hero titled with the page's title (one `<h1>`, always).
   `BaseLayout` (SeoHead: the page's SEO override, else its title and a description from its
   first text; per-language self-canonical, reciprocal hreflang + x-default, from the layout),
   JSON-LD `WebPage` + `BreadcrumbList` (Home > page), `setTierA` with `route:page`,
   `page:<slug>`, `media:all` and `sectionTags`. Both languages.
4. **The readers that hold paths:** `src/lib/visibility/routes.ts` learns custom pages
   (`targetForRoute` takes the route's params: `/[slug]` with a custom slug is that page;
   `targetForPath` reads one custom segment; `localizedPagePath` and the redirect target accept a
   custom slug), so page visibility (hidden, link only, password, the window) and maintenance
   hold for a custom page exactly as for a route page, before the render. `pagePath` (SEO list,
   pages list, editor), the sitemap (both languages, `<lastmod>` from `updated_at`, visibility and
   indexability filtered), llms.txt (a Pages list), the preview route map (`/[slug]`, reserved
   words excluded by the pattern), the nav editor's link picker, the Tier A route table
   (`route:page`, within 30 tags) and the release purge (`page:<slug>` already, through the
   registry's page row).
5. **The admin:** "New page" on the pages list for `pages.write` (Admin, Content Creator): a
   dialog (title in English and Arabic, the address, suggested from the English title, the rules
   said under the box), POST through the kernel (`stagedUrl` in release mode, R12b), then the
   editor opens on the new page with a hero titled with the page's title. The editor takes a
   custom page: "Add section" offers the custom set, the hero carries an honest note, the live
   preview frames `/<slug>` and `/ar/<slug>`, and with releases on a pending page opens from its
   draft and the list shows it. The section routes refuse a type a custom page cannot hold
   (422), so the set holds at the API too. Page visibility lists custom pages.
6. **Seeds:** one sample custom page (`how-we-work`: a hero and a text block), a placeholder:
   published locally, in CI and on staging (lhci, axe, served-html, preview parity), a draft in
   `production.sql`.
7. **Tests:** vitest for the slug rules (shape, reserved words, the directory walk, SQL parity),
   the loader's pure parts (allowed types, the heading floor, the hero data, the JSON-LD), the
   route map, the preview map, the sitemap and llms filters, the section refusal, the pages list
   (pending creates), the library; pgTAP; e2e (CI): the custom page in both languages (status,
   h1, canonical, hreflang, JSON-LD, Cache-Tag), an unknown slug and a reserved word 404, axe,
   served-html and share-image through `publicRoutes.ts`, preview parity, lhci on both routes,
   and the New page dialog signed in as Admin.

**Not built (said in the as-built):** site search does not index custom pages (`search_content`
covers services, posts and projects); a custom page's slug is set once in the dialog (the
editor's page panel has no address field, as on every page).

## What was built

The plan held, with three departures (listed after the parts).

### The address rules (`packages/schemas/customPages.ts`)

- `ROUTE_PAGE_SLUGS` (equal to `PAGE_PATHS`' keys), `RESERVED_PAGE_SLUGS` (28 words: every
  top-level route of `src/pages` that is not a CMS page and its folders, every top-level folder
  of `public/`, `cdn-cgi`, `en`, `www`, `assets`, `static`, `feed`, `rss`, `preview`),
  `CUSTOM_PAGE_SLUG_MAX` (64), `PAGE_SLUG_PATTERN`, `customPageSlugProblem` (plain words),
  `isCustomPageSlug`, `suggestPageSlug` (the dialog's suggestion from the English title) and
  the section set, `CUSTOM_PAGE_SECTION_TYPES` (hero, textBlock, gallery, video, cta, slogan,
  social, statistics, testimonials, clientsMarquee, certifications) with its refusal sentence.
  Dependency-free, like `sectionTypes.ts`: the dialog, the routes, the preview map and the
  middleware's route map all import it.
- `PageWriteSchema` (create) takes a custom page's address only; the update schema refuses a
  reserved word and a long address and keeps the route slugs (`packages/schemas/admin.ts`).

### Migration 0123 (`0123_custom_pages.sql`, expand only)

`app.tg_pages_slug_rules()`, BEFORE INSERT OR UPDATE OF slug on `public.pages`, per row,
SECURITY INVOKER with `search_path = ''`, no API role executing it: on an insert, and on an
update that changes the slug, the shape (23514 `pages_slug_shape`) and the reserved words (23514
`pages_slug_reserved`), for every writer, the service role and the migration role included.
The Worker maps both constraint names, and 0001's unique key, to the address field
(`src/lib/admin/resources/pages.ts constraintFields`). No grant, policy, column or registry row
changes; the postconditions check that the policies, RLS, the registry's page row and anon's
privileges are as before and that releases stay off.

pgTAP `supabase/tests/custom_pages.test.sql` (34): the trigger and function shape, every refusal
and the 64-character bound, the service role refused a reserved word, admin and content_creator
create and edit a custom page, neither renames one onto a reserved word, content_creator
archives and deletes none, admin does; seo, developer, sales and anon create none; other_tenant
reaches nothing. Production read-back: scratchpad `readback_e11.sql` (replayed in PGlite over
every migration and `seed.sql`: every line as expected, with the seeded sample counted, 8 / 1).

### The public routes

- `src/pages/[slug].astro`, `src/pages/ar/[slug].astro` (Tier A), one loader,
  `src/lib/sections/customPage.ts` `loadCustomPage`: the address is checked before any read
  (`/wp-login`, `/feed` or `/Our-Story` cost no query), then `getPageComposition(slug)`
  (published, anon under RLS, a password page's unlocked read) beside the head's reads (its SEO
  override is keyed by the page id, so the page is one round trip); anything else is the 404
  page by rewrite, so authored redirects still answer after it.
- `customSections`: only the custom set renders; the first hero is a banner
  (`CUSTOM_HERO_DATA`: no intro plate, Contact's loop window, its button to Our Work); with no
  visible heading section the page opens with a banner hero of its own title (clipped to the
  hero's ladder, ten words of fourteen letters), so it always has one `<h1>`.
- `CustomPage.astro`: `BaseLayout` with the overlay header (SeoHead: its SEO row, else its title
  and `customDescription`, its first words in its own language only, never the other's;
  per-language self-canonical, reciprocal hreflang + x-default), SectionRenderer, JSON-LD
  `WebPage` (`buildWebPageSchema`: name, URL, `inLanguage`, the site, a description and the
  row's `updated_at` only when real) and `BreadcrumbList` (Home > the page).
- Cache-Tags: `route:page`, `page:<slug>`, `media:all` and `sectionTags` (`customPageCacheEntities`,
  in `TIER_A_ROUTES`, within 30 with every section a custom page may hold). A release that
  touches the page or a section purges `page:<slug>` through the registry (R7); the sitemap and
  llms.txt keep their hour (their own KAN-20 TODO).
- Visibility and maintenance: `targetForRoute(route, params)` reads the `[slug]` routes' param
  (a target only when it is a custom page's address), `targetForPath` one custom segment,
  `pagePathOf` and `localizedPagePath` take a custom slug, and a hidden page may redirect to a
  custom page (`decide`); the middleware passes `context.params`. So hidden, link only, the
  password, the window and maintenance hold for a custom page before the render, as for a route
  page.
- Discovery: `getPublishedCustomPages()` (`src/lib/data/customPages.ts`: anon under RLS through
  the content seam, custom addresses only, 200 at most); the sitemap lists both twins with the
  row's lastmod, llms.txt each by its English title under the sections (20 at most), both after
  the visibility and indexability filters (`indexability`'s page lookup finds a custom page's
  SEO row by its `/<slug>`).

### The admin

- "New page" (`AdminNewPage`, `src/components/admin/screens/newPage/`): on `/admin/pages` for
  `pages.write` (Admin, Content Creator); a dialog with the title in English and Arabic (each a
  banner headline: ten words of fourteen letters) and the address (suggested from the English
  title until typed in, the rules and the resulting `/x` and `/ar/x` said under it). It POSTs the
  draft page, then its banner hero titled with the title (`stagedUrl` on both, R12b), and opens
  the editor; a refusal is said on its field in the server's words. `/admin/pages/new` is a 302
  to `/admin/pages?new=1`, which opens the dialog.
- The pages list orders the route pages first, then custom pages by slug, each with its path
  and its Open links; with releases on, a pending create is a card from its draft. The editor
  opens a pending create from its draft (`pendingCreate`), offers the custom set in Add section
  (the rest say why, `CUSTOM_PAGE_TYPE_REFUSED`), notes the banner on the hero, previews `/<slug>`
  and `/ar/<slug>` (the preview's route map takes `/[slug]` last, by a pattern held equal to
  `isCustomPageSlug`), and its page details say "Address /x, chosen when the page was made."
  (`addressNote`).
- The section routes refuse a type outside the set joining a custom page (422 on `type`,
  `sectionResource.assertWritable`, read through the overlay-aware database, so a pending page
  counts; an edit that keeps a row's type and page reads nothing).
- A release answers that rule from its batched read of the links (`primeLinks` reads a linked
  page's `id,slug` and primes `sectionPageQuery`), so it costs a publish no request of its own
  (`tests/lib/releasePublish.spec.ts`'s six-read tripwire fails without it).
- Page visibility, the nav editor's link picker and the SEO list's paths know custom pages.
- GA4 (U15): `/[slug]` and `/ar/[slug]` are listed in `GA4_ROUTES`, as About is: a custom page
  holds no form (`tests/lib/customPages.spec.ts` scans every component of the set, one import
  deep, for a `<form>`), so the U15 rule ("every public page but the form pages, search and
  404") puts it in. With the switch off (production) nothing changes.

### Departures

1. **The module is `packages/schemas/customPages.ts`**, not `pageSlug.ts`: it holds the section
   set too.
2. **0123 does not refuse a route slug on insert by role.** The unique key already refuses one
   while its page exists, and a missing route page recreated (a release's restore) must be that
   route's page again; a role check in a trigger would also have been the first to read the
   claim there. The Worker's create schema and the dialog refuse a route slug.
3. **`/admin/pages/new` is a 302 to the list's dialog** rather than a second create form: the
   old form made a page no route rendered and knew none of the rules.

**Not built:** site search does not index custom pages (`search_content` covers services, posts
and projects); a custom page's address is set once (the editor's page panel has no address
field, as on every page); the sitemap and llms.txt are not purged by tag on publish (they keep
their hour, as for every page, until KAN-20).
