- **`src/lib/release/registry.ts`** (server only): `RELEASE_REGISTRY`, one entry per row of

## Departures from the design, and why

- **`toRow` is not rebuilt on the `fields` maps** (the design rebuilds it; brief D1). The
  two are declared side by side from one key-map constant, and the legacy write path is
  proven unchanged by a snapshot recorded from main 23ce829 before anything moved
  (`tests/lib/releaseOffWrites.spec.ts`: every resource config's `toRow` over the full
  sample, each key alone and each key cleared, errors included, and the values the
  site-profile, SEO-defaults and entity-SEO routes hand the database on an insert, an
  update and a partial update, driven through the real routes). The brief asked for "a
  test per config"; this is that test, one snapshot entry per config and route.
- **`fields` is checked harder than the brief's "each key alone"**: every pair of keys
  must write only the two keys' columns (the statistic value rule needs both the number
  and the suffix), and every column a key declares must be written by some input carrying
  it, so `fields` is exact rather than a safe superset. Entity SEO is a full replace (its
  `toRow` writes all six meta columns whatever the payload), so it is checked on the full
  write instead of key by key.
- **The TS allowlist (`columns`) is derived, not a second literal:** the union of `fields`,
  less `published_at`, `scheduled_for` and the immediate columns, plus restore-only
  columns. The parity spec holds it equal to the SQL, so a missing derived column fails
  twice (registry and fields specs) rather than at publish.
- **`page_sections.style` is a restore-only column.** 0038's allowlist has it, but no
  payload key writes it (`SectionWriteSchema` dropped `style`: nothing could apply it under
  the nonce CSP). The registry lists it as restore-only so the TS and SQL allowlists stay
  equal; see Open.
- **`seo-defaults`' `toRow` copies through its key map** instead of six `if`s: the same
  writes (snapshot), and its `fields` can no longer drift from it.
- **`requiredCaps` returns null** for a removal of a type a release never removes (the
  singletons, entity SEO) instead of throwing: `canPublish` is then false for everyone
  and `waitingFor` empty, which a pending list can show. The drafts policies refuse to
  stage such a removal anyway (empty `delete_roles`).
- **`publishableByArea` and `publishableAreas`** both exist (the brief names each once).
- **`mergePayload` drops keys the entity does not know** and keys that write only immediate
  columns (`acceptingApplications`): a draft is untrusted, and edge case 20 says the
  intake switch never appears in a site-profile draft. `derivePatch` still splits it into
  `exempt` when a payload carries it, so R3 can route a live PATCH's switch to its endpoint.
- **`derivePatch` lets the schema's ZodError through** (the kernel already answers it with
  a 422) rather than wrapping it. A `scheduledFor` date or `status: 'scheduled'` is refused
  with `ValidationError('Schedule the release instead', 'scheduledFor')`; `scheduledFor:
  null` (a form clearing the field) is not a schedule and is simply dropped, since the
  column is never a release's. A singleton create merges the config's defaults limited to
  the allowlist, so `accepting_applications` takes its column default (closed).
- **`overlayRow` on an update whose live row is gone** returns `row: null` with
  `draft.liveMissing` (the design's "This item was removed on the live site" → Discard). A
  pending create carries the draft's `created_at`/`updated_at`, so the newest-first lists
  (blog, service cases) show it at the top.
- **`overlayList` details** (D3 as recommended): updates keep their live page even if the
  change no longer matches the filter (they show their badge); creates join page 1 only
  and `total` counts every matching create; the page can then hold more than `limit` rows.
  Overlaid and created rows carry the list's columns only (a pending body never reaches a
  list). Order follows PostgREST's NULL placement (last ascending, first descending);
  text compares by code unit, not the database collation. A draft whose payload no longer
  parses is left out and named in `invalid`.
- **No-op and conflict equality** compares canonical JSON and reads an ISO timestamp as
  the instant it names (PostgREST's `+00:00` against the form's `.000Z`), so a consent date
  saved back unchanged is a no-op. Display only: R4's typed check is the gate of record.
- **Labels are English fallbacks** where the row has no bilingual text (singletons,
  sections, entity SEO, redirects); the publish dialog's copy is R12's (P-12).
- **The apply-order link check classifies every `*_id` column** in a table in the spec
  (registry type, self-reference, or outside the registry) instead of reading
  `assertLinkInTenant` calls: a new link column fails until it is classified.
- **"Server only" is a static check in `tests/lib/releaseRegistry.spec.ts`** (no file under
  `src/components` or `src/lib/admin/client` mentions the registry or the overlay; `areas.ts`
  and `caps.ts` import only the matrix, the role list and the release schemas).
  `tests/lib/adminBundle.spec.ts` is unchanged: no island imports either module yet.

## Open

- **`page_sections.style` in the allowlist.** A release can write it only through a
  restore (R10) of a row that still carries an old value. R4 (or the migration that next
  touches the registry) decides whether to keep it or drop it from 0038's allowlist; the
  registry's restore-only entry and the fields spec's exception go with it.
- **The statistic's suffix alone does not recompute `value`** (`toRow` recomputes only when
  the number is in the same payload). That is today's behaviour and the form always sends
  both; `fields.valueSuffix` declares `value` because the pair writes it. R3's staged
  patch inherits the same rule.
- **Parallel registry rows.** U14 (page visibility) and later U7, E3, E5 and E8 add rows in
  their migrations; `tests/lib/releaseRegistry.spec.ts` fails until the TS entry (and its
  config's `fields`) lands with them.
- **R3** still needs the staff-callable flag reader R1 left open (`public.releases_enabled()`).
