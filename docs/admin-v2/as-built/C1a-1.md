## Departures from the design, and why

- **CRM-1 is three slices, not one.** The design put the whole leads v2 schema in one expand
  migration. It shipped as C1a-1 (0033, this slice), C1a-2 (0034, the pipeline) and C1b (0035,
  ingest), so the one migration that takes access away could land on its own.
- **Code first.** 0033 removes staff read access (a contraction), so the code merged and
  deployed first: it reads the gated columns as the service role and works on both schemas.
  0033 was applied once that deploy was live. This merge is the Worker rollback floor (launch
  runbook §10).
- **What 0033 holds.** SELECT on `leads` is a column grant: `leads_safe`'s columns plus
  `tenant_id`. The contact ciphertext, budget, timeline, notes, IP address and retention date
  are unreadable by every staff token; the per-lead reveal and the export read them as the
  service role, after `assertCap`, a live recheck and a fail-closed audit row. Staff still
  write notes (0030's UPDATE grant). Policies are FOR SELECT and FOR UPDATE only, so RLS
  refuses API inserts and deletes too.
- **`app.live_role()`** generalises 0029's `is_live_admin`, behind a RESTRICTIVE `leads_live`
  policy with its own tenant predicate: a demoted, deactivated, locked or moved token reads and
  changes no lead, even through PostgREST directly (D5, for leads).
- **One SQL helper so far.** `app.role_works_leads` is the only `app.role_*` helper; the
  design's other five (`role_lead_pii`, `role_crm_contacts`, `role_crm_tasks`,
  `role_crm_settings`, `role_crm_erase`) do not exist yet. `tests/authz/sqlHelpers.spec.ts`
  holds the helpers equal to `ROLE_CAPS`.
- **The PATCH response** carries the safe columns only; `leadColumnsFor` is gone.
- **Found in review.** Since 0033 the PII export reads as the service role, so its tenant
  filter is the only fence on that query: a test runs the real route for Admin and Developer
  and fails if the filter goes. CLAUDE.md §3 and §7 now name the signed `notify-lead` hook as
  a server-side reader that returns nothing to a person.
- **Docs.** `leads_safe` is granted to all `authenticated` and is SECURITY INVOKER (D7); the
  false sentence saying otherwise is gone.
- **Tests.** `rls_leads.test.sql` rewritten around real profiles (six principals, five
  stale-token shapes, the column grant, the write layer); unit specs enforce the grant in their
  mock client, pin the reveal's order and name every service-role reader of `leads`
  (`tests/lib/leadGrants.spec.ts`).
