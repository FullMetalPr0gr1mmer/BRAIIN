# H7: a singleton's first save is accepted

- **Lane:** hotfix (a live 422)
- **Design:** none
- **PR:** #50
- **Migrations:** none

## As built

**Why.** SEO defaults, integrations, AI config, site settings and maintenance are per-tenant
rows created on their first save. Until then GET answers `version: 0`, and the editor sends
that 0 back. The singleton kernel (`src/lib/admin/singleton.ts`) and the maintenance route turn
0 or 1 into the INSERT, but the five schemas used `VersionSchema` (`min(1)`), so Zod refused
every first save with a 422 before the kernel ran.

**What shipped.** The five schemas in `packages/schemas/admin.ts` (`SeoDefaultsSchema`,
`IntegrationsSchema`, `AiConfigSchema`, `SiteSettingsSchema`, `MaintenanceSchema`) take
`SingletonVersionSchema` (`min(0)`), as `SiteProfileSchema` already did. A version the missing
row never had is still a 409. `tests/lib/singletonFirstSave.spec.ts` drives the six real
singleton routes over a tenant with no row: version 0 creates it, version 2 is a conflict.
Five of the six failed before the change.
