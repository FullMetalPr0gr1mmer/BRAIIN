# U15: Google Analytics 4 behind analytics consent, held off until the notice is signed off

- **Lane:** UI (Wave 3, after U11)
- **Design:** README "Slice sequence" U15 ("GA4 behind `hasConsent('analytics')`: same-origin
  loader, CSP sources only while an id is set (Report-Only cycle), GA tab via the Data API");
  README O-18; [verification.md](../verification.md) (the GA4 proposal: a same-origin loader
  after consent, the CSP sources only while an id is set, the Data API server-side); ui.md
  AV-20's risk ("GA4 is stored but never injected"); [U11](U11.md) "Notes for later slices";
  CLAUDE.md §2 (GA4 secondary, behind consent; first-party analytics the single source of
  truth, no double-write), §3 (CSP), §7 (one `hasConsent` gate)
- **Migration:** `0109_ga4.sql` (placeholder number, renumbered at its merge train)
- **PR:** at review (branch `feat/u15-ga4`)

## Plan (written before the build)

**Scope.** Load GA4 on the public site, from a same-origin loader, only for a visitor who
accepted analytics, only while an id is saved AND a code-owned switch says the privacy notice
names Google; the CSP gains Google's hosts only on those responses. The GA tab (Data API)
is weighed against "built honestly, Not set up, the secret named": O-18's service account is
not provisioned.

**Why a switch.** The privacy notice (`src/lib/legal/content.ts`) says the site's analytics
are first-party. GA4 sends visit data to Google, so it must not load in production until the
owner signs off the notice text (drafted below). A saved id alone loads nothing:
`GA4_NOTICE_READY` (astro:env, server, public, default false, read like `AUTH_EMAIL_READY`) is
required too, and it is not in `wrangler.jsonc`'s `vars`, so production builds with it off.
The switch-on PR adds it there with the notice text, and a test refuses that PR unless the
notice, the cookie policy and the banner name Google in both languages and the consent
version moved.

**Migration (0109).** Anon gets SELECT on `site_integrations.ga4_measurement_id` (the
column-grant pattern of U11's Search Console code: a measurement id is public by nature, every
page that loads GA4 carries it). Nothing else changes: the anon policy fences anon to the
launch tenant already. Postconditions under both grant regimes (anon's exact column set, no
table privilege, no write; authenticated and service_role unchanged; the policy set unchanged;
releases off).

**Server.**
1. `src/lib/data/ga4.ts`: the public loader, the one column through `contentClient()`, never
   throws, a value the CHECK's pattern refuses is no id.
2. `src/lib/http/ga4.ts`: the switch, the routes that load it (every public page route, EN
   and AR, but search and the 404s; held to `src/pages` by a test) and the decision.
3. `src/middleware.ts`: on a public GET or HEAD of one of those routes, with the switch on,
   it starts the read before the render (one subrequest; none with the switch off) and hands
   the promise to the layout in `locals.ga4`; after the render, an HTML response whose read
   found an id gets the GA sources in its CSP. A password-unlocked page and a maintenance
   bypass (private answers) never load it; the preview never does (its branch returns first).
4. `src/lib/http/securityHeaders.ts`: `GA4_CSP_SOURCES` (script-src, connect-src, img-src:
   exactly what gtag.js needs without Ads features, nothing wider), joined only when asked.
5. The Report-Only cycle is defined against `CSP_REPORT_ONLY` as it is today (recorded below).

**The page.** `public/scripts/ga4.js`, a classic same-origin script with the id and the
consent version in `data-*` attributes (no inline script, no JSON: strict CSP), rendered by
`src/components/Ga4Loader.astro` at the end of BaseLayout's consent-gated block, only when the
middleware's read found an id. It loads nothing from Google until analytics consent (the
gate's own reading of the cookie, at the current consent version), then gtag.js with consent
mode (analytics granted, ads denied), Google signals and ad personalisation off, page
addresses without their query; on withdrawal: consent mode denied, `ga-disable-<id>`, no
further loading, the `_ga` cookies cleared as far as a page can.

**Admin.** The GA4 tile says why a saved id does not load yet (the notice is not signed off);
with the switch on it says Set up.

**Tests.** pgTAP `ga4.test.sql` (new: the grant over admin, content_creator, seo, developer,
sales, anon and other_tenant), and the anon pins in `integrations`, `grants_app_schema` and
`preview_dataset`. Unit: the loader (`vm`, a fake DOM: nothing before consent, gtag after,
withdrawal), its consent reading equal to `hasConsent`, the middleware (reads, CSP, the routes),
the CSP sources, the data loader, the route list against `src/pages`, the switch-on guard, the
tiles. Render: BaseLayout to the byte with no id (snapshot taken before the change), with an
id the loader tag only. E2E (own project, run alone): EN and AR, switch on and an id saved,
zero requests to Google before consent, gtag after (route-intercepted), withdrawal stops it,
zero CSP violations. The CI e2e build turns the switch on; Lighthouse and deploys stay off.

**Docs.** CLAUDE.md §3 CSP and §7 consent bullets, the cookie inventory, the UI lane bullet;
architecture §4.12; deviations; the runbook's switch-on steps; the notice drafts.

## What was built

**The read (0109, `src/lib/data/ga4.ts`).** Anon gets SELECT on one more column,
`site_integrations.ga4_measurement_id`, beside U11's Search Console code. Anon's grants on the
table are stated whole (revoked, then exactly `tenant_id, search_console_token,
ga4_measurement_id`); staff, the service role and 0105's tenant-fenced anon policy are
untouched. The loader reads that one column through `contentClient()`, never throws, and
answers null for no row, no id, a refused or failed read, or a value outside the CHECK's pattern
(the last three reported to `system_logs`). Postconditions: RLS forced; the exact policy set,
and the anon policy the tenant predicate alone; anon's exact column set and no write or table
privilege (MAINTAIN under a `server_version_num` CASE); PUBLIC nothing; staff still read the
id; the service role S/I/U/D and nothing more; the CHECK still the measurement id's shape; the
table not in the release registry; releases off. The preview's anon mirror (`ANON_COLUMNS`)
learns the column, so a preview read stays a faithful anon read (a preview never loads GA4).

**The decision (`src/lib/http/ga4.ts`, `src/middleware.ts` step 2b).** Three conditions, all
needed, decided before the render: the switch (`GA4_NOTICE_READY`); the request (a GET or HEAD
of a listed public page route, answered publicly: not the admin, an API, `/healthz`, `/_image`,
a password-unlocked page or a page seen past maintenance; the preview branch returns before
this); and the data (an id, read once). `GA4_ROUTES` is every public page route, EN and AR,
except search (its address carries what a visitor typed) and the 404s; `ga4Routes.spec.ts`
holds the list to `src/pages` both ways, so a new page needs a decision. The read starts before
the render and its promise rides `locals.ga4`, so the layout and the CSP share one answer.

**The CSP (`GA4_CSP_SOURCES` in `securityHeaders.ts`).** On an HTML response whose read found an
id, and only there: `script-src https://www.googletagmanager.com`; `connect-src
https://www.googletagmanager.com https://*.google-analytics.com https://*.analytics.google.com`;
`img-src https://www.googletagmanager.com https://*.google-analytics.com`. That is Google's own
GA4 list without the Ads features (no `*.g.doubleclick.net`, no `pagead2.googlesyndication.com`,
no `frame-src`), with `script-src` narrowed to the one host gtag.js loads from and Google's
`https://*.google.com` for `connect-src` narrowed to `*.analytics.google.com`. Never beside a
preview's exact `connect-src`; never on the admin; the Worker backstop never adds them.

**The page (`src/components/Ga4Loader.astro`, `public/scripts/ga4.js`).** One classic
same-origin script tag at the end of BaseLayout's consent-gated block (never in a preview), with
the id and `CONSENT_VERSION` in `data-*` attributes: no inline script, no JSON. The script reads
the consent cookie exactly as `hasConsent` does (held equal, value by value, in
`ga4Loader.spec.ts`) and also requires the choice to carry the current consent version, so a yes
given to the first-party notice never loads Google once the switch-on PR moves the version.
- With a yes: consent mode default all denied, then analytics granted (every ad signal stays
  denied); `allow_google_signals` and `allow_ad_personalization_signals` false; cookies
  host-only (`cookie_domain: 'none'`), `SameSite=Lax;Secure`, 180 days (the consent cookie's
  own lifetime, not Google's two years); `page_location` and `page_referrer` without query or
  fragment. Then one `gtag/js?id=` request, made only once the page has loaded: a visitor who
  said yes on an earlier page never fetches Google's script while this page paints (CLAUDE.md
  §6: third-party code after LCP, as `hls.js`). The queue keeps every call made meanwhile.
- Without one: nothing from Google, no `dataLayer`, and any `_ga` cookies cleared (host-only,
  then this host and each parent domain).
- On withdrawal (the banner's `consent-updated`; a choice changed in another tab, followed when
  this tab is shown again; a back-forward cache restore): consent mode denied, `ga-disable-<id>`
  set, nothing more loaded, the `_ga` cookies cleared. A no before `load` means gtag.js is never
  asked for; a yes again on the same page resumes with at most one request.

**The admin.** The page reads the switch on the server and passes `ga4Live` to the island.
Off: the GA4 tile shows "Saved", the id, and "Not loading yet. It waits for the privacy notice
to name Google, which the site owner approves."; its drawer says the same at more length. On:
"Set up", and the drawer says it loads only for visitors who accept analytics cookies.

**Tests.**

- Unit: `ga4Data.spec.ts` (the read); `ga4Routes.spec.ts` (the decision, the route list against

## The switch, and where it is on

`GA4_NOTICE_READY` is an astro:env public server variable, default `false`, read like
`AUTH_EMAIL_READY`: `astro build` inlines it, and `wrangler.jsonc`'s `vars` win over the build
environment. It is not in `vars` (a `"false"` there would also win over the e2e build's `true`).

| Build | Switch | Why |
|---|---|---|
| Production deploy (`ci.yml`) | off | no `vars` entry, no env |
| CI build-test, Lighthouse | off | as production |
| CI e2e (`perf-seo-a11y.yml`, job `e2e`) | on | proves the loader against the real Worker; no id is saved outside `ga4.e2e.ts`, so every other spec sees production's pages |

`tests/lib/ga4Switch.spec.ts` holds all three, and holds the switch-on PR to its contents: once
`wrangler.jsonc` says `"GA4_NOTICE_READY": "true"`, it fails while any of these is missing
(today it names all twelve): the privacy notice naming Google Analytics, the cookie policy
naming the `_ga` cookies, both with a new date, the banner naming Google, each in both
languages; `CONSENT_VERSION` moved to 2; the integrations guide no longer saying the site does
not load Google Analytics (EN and AR: a put through H11's catalog, at revision 1 today); and a
control that reopens the consent banner on every page (`data-consent-open`). It also refuses the
opposite: notices naming Google while the switch is off.

## The Report-Only cycle, defined against today

`CSP_REPORT_ONLY` is `false` today: the policy has been enforced on every response since the
foundation (2026-06-11), and the 2026-10 backstop kept it so. Report-Only suits a TIGHTER policy;
adding GA4's hosts loosens a page's policy, and only on the pages that load GA4, so turning the
whole header to Report-Only for a cycle would weaken every other directive of those pages and
learn nothing. U15's cycle is therefore: the GA4 hosts ship enforced, exactly the list above; a
request gtag.js makes to a host the list lacks is refused by the browser (GA4 loses that hit,
nothing else on the page is affected), and the loader reports the directive and the host's
origin (never the URL, whose query carries the visitor's GA identifier) to `/api/clientlog` as
`source: 'ga4-csp'`, at most five a page, from the moment gtag.js is requested. The cycle closes
after one release cycle in production with the switch on: no `ga4-csp` rows means the list is
complete; a row names exactly the host to review, and a host joins only in a reviewed PR
(CLAUDE.md §7). Nothing is ever loosened to find out.

## Departures from the design, and why

- **The GA tab via the Data API is not built (deferred; owner item O-18).** README U15 lists
  it, and the brief allowed it only "if it can be built honestly with Not set up and the secret
  named". Not yet: (1) it has nothing to show until GA4 loads, which waits on the notice
  sign-off, so in production it could only say "Not set up" or show zeros; (2) the Data API
  reads a property by its numeric property id, a second identifier the schema does not hold (a
  column, a grant, a field and pgTAP for a tab with nothing to show); (3) its credential is a
  service-account private key, a long-lived Worker secret whose scope (Viewer on one property)
  and rotation are the owner's to decide with O-18; (4) Google's token exchange and `runReport`
  could only be tested against mocks of Google's shapes, never once against the API. Proposed:
  a slice after the switch-on, with O-18 provisioned: `GA4_PROPERTY_ID` and
  `GA4_SERVICE_ACCOUNT_KEY` as astro:env server secrets (never `PUBLIC_*`), an RS256 JWT signed
  with WebCrypto, one token exchange and one `runReport` per view (two subrequests), the tab
  under `analytics.read` saying "Not set up" until both are set.
- **The switch is not in `wrangler.jsonc` yet.** The brief said "a wrangler.jsonc var such as
  GA4_NOTICE_READY, default off, read like AUTH_EMAIL_READY". `AUTH_EMAIL_READY` is read
  exactly this way: declared in `astro.config.mjs` with `default: false` and absent from `vars`
  until its switch-on PR adds `"true"`. A `"false"` in `vars` would win over the CI e2e build's
  `true` and leave the loader unproven against the real Worker. The switch-on PR adds the line.
- **The loader requires the current consent version; `hasConsent` does not.** Stricter on
  purpose: consent given to the first-party notice must not load Google once the notice
  changes (the switch-on PR moves `CONSENT_VERSION`, and the banner asks everyone again).
- **gtag.js waits for `load`.** Not in the design: added so a consented visitor's page loads as
  Lighthouse measures it (CI runs without consent and would never see the cost).
- **Search and the 404 routes never load GA4.** Search's address and box carry what a visitor
  typed (the first-party search log keeps the counts); `/404`, `/ar/404` and the Arabic
  catch-all have nothing to measure. A slug that does not exist on a GA4 route
  (`/services/nope`) renders the 404 page through `Astro.rewrite` inside that route's request,
  so it carries the loader and the GA hosts together (the read is the route's), and GA4 counts
  the address like any other page: harmless, and consistent (never a loader without its CSP).
- **The integrations guide is unchanged.** It says the site does not load Google Analytics yet,
  which stays true in production until the switch-on, and the tile says why. The switch-on PR
  puts the guide (revision 1 today, after U11's 0105); the guard refuses that PR without it.
- **No "Cookie settings" control yet.** Architecture §4.12 asks for a persistent link that
  reopens the banner; none exists (the cookie policy promises "you can change your choice at any
  time", and today only clearing cookies does it). Adding one changes every public page's HTML,
  which this slice must not do while no id is set; the guard makes it a switch-on prerequisite.
  The e2e withdraws as the banner's no does (the cookie rewritten, `consent-updated`).
- **Architecture §4.12 said GA4 needs `marketing` consent.** The README's U15 row, CLAUDE.md §7
  and `gate.ts` say `analytics`, and GA4 here runs with every advertising signal denied, so §4.12
  is amended to `analytics`.
