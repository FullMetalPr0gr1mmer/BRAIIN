## Plan (written before the build)

**Scope.** Load GA4 on the public site, from a same-origin loader, only for a visitor who
accepted analytics, only while an id is saved AND a code-owned switch says the privacy notice
names Google; the CSP gains Google's hosts only on those responses. The GA tab (Data API)
is weighed against "built honestly, Not set up, the secret named": O-18's service account is
not provisioned.

**Why a switch.** The privacy notice (`src/lib/legal/content.ts`) says the site's analytics
are first-party. GA4 sends visit data to Google, so it must not load in production until the
owner signs off the notice text (drafted below). A saved id alone loads nothing:
`GA4_NOTICE_READY` (astro:env, server, public, default false, read like `AUTH_EMAIL_READY`) is
required too, and it is not in `wrangler.jsonc`'s `vars`, so production builds with it off.
The switch-on PR adds it there with the notice text, and a test refuses that PR unless the
notice, the cookie policy and the banner name Google in both languages and the consent
version moved.

**Migration (0109).** Anon gets SELECT on `site_integrations.ga4_measurement_id` (the
column-grant pattern of U11's Search Console code: a measurement id is public by nature, every
page that loads GA4 carries it). Nothing else changes: the anon policy fences anon to the
launch tenant already. Postconditions under both grant regimes (anon's exact column set, no
table privilege, no write; authenticated and service_role unchanged; the policy set unchanged;
releases off).

**Server.**
1. `src/lib/data/ga4.ts`: the public loader, the one column through `contentClient()`, never
   throws, a value the CHECK's pattern refuses is no id.
2. `src/lib/http/ga4.ts`: the switch, the routes that load it (every public page route, EN
   and AR, but search and the 404s; held to `src/pages` by a test) and the decision.
3. `src/middleware.ts`: on a public GET or HEAD of one of those routes, with the switch on,
   it starts the read before the render (one subrequest; none with the switch off) and hands
   the promise to the layout in `locals.ga4`; after the render, an HTML response whose read
   found an id gets the GA sources in its CSP. A password-unlocked page and a maintenance
   bypass (private answers) never load it; the preview never does (its branch returns first).
4. `src/lib/http/securityHeaders.ts`: `GA4_CSP_SOURCES` (script-src, connect-src, img-src:
   exactly what gtag.js needs without Ads features, nothing wider), joined only when asked.
5. The Report-Only cycle is defined against `CSP_REPORT_ONLY` as it is today (recorded below).

**The page.** `public/scripts/ga4.js`, a classic same-origin script with the id and the
consent version in `data-*` attributes (no inline script, no JSON: strict CSP), rendered by
`src/components/Ga4Loader.astro` at the end of BaseLayout's consent-gated block, only when the
middleware's read found an id. It loads nothing from Google until analytics consent (the
gate's own reading of the cookie, at the current consent version), then gtag.js with consent
mode (analytics granted, ads denied), Google signals and ad personalisation off, page
addresses without their query; on withdrawal: consent mode denied, `ga-disable-<id>`, no
further loading, the `_ga` cookies cleared as far as a page can.

**Admin.** The GA4 tile says why a saved id does not load yet (the notice is not signed off);
with the switch on it says Set up.

**Tests.** pgTAP `ga4.test.sql` (new: the grant over admin, content_creator, seo, developer,
sales, anon and other_tenant), and the anon pins in `integrations`, `grants_app_schema` and
`preview_dataset`. Unit: the loader (`vm`, a fake DOM: nothing before consent, gtag after,
withdrawal), its consent reading equal to `hasConsent`, the middleware (reads, CSP, the routes),
the CSP sources, the data loader, the route list against `src/pages`, the switch-on guard, the
tiles. Render: BaseLayout to the byte with no id (snapshot taken before the change), with an
id the loader tag only. E2E (own project, run alone): EN and AR, switch on and an id saved,
zero requests to Google before consent, gtag after (route-intercepted), withdrawal stops it,
zero CSP violations. The CI e2e build turns the switch on; Lighthouse and deploys stay off.

**Docs.** CLAUDE.md §3 CSP and §7 consent bullets, the cookie inventory, the UI lane bullet;
architecture §4.12; deviations; the runbook's switch-on steps; the notice drafts.
