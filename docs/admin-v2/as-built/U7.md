## What was built

### U7a: `faq_items`, one loader, the FAQ screen

**The table (0070).** `public.faq_items`: bilingual `question` and `answer` (plain text, one
paragraph), `status` (the one `content_status` lifecycle), `published_at`, `scheduled_for`,
`sort_order`, `version`, the stamps and actors; no slug (D3: an item is never addressed by
URL). Both texts are held by `app.faq_text_ok(jsonb, int)` as a CHECK (IMMUTABLE, invoker,
`search_path ''`, executable by authenticated and the service role only): exactly `{en, ar}`,
strings, 1 to 200 (question) or 1200 (answer) characters, already trimmed, and no C0/C1 control
character. That refuses a newline on purpose: the band's HTML folds a newline that the FAQPage
JSON-LD would keep, a visible/structured mismatch. `<` and `>` are words (text nodes; the
JSON-LD is escaped by `serializeForScript`).

- **RLS**, ENABLE + FORCE: `faq_items_read` (published, or staff), `faq_items_write`
  (`app.can_write_content()`: Admin + Content Creator, the holders of `pages.write` and
  `content.publish`), RESTRICTIVE `faq_items_delete_admin` and `faq_items_archive_admin`. The
  tenant predicate is the first conjunct of every USING and every WITH CHECK, the RESTRICTIVE
  pair included (0021's archive gate leaves it out of its WITH CHECK; this one does not).
- **Grants**, stated for both regimes: anon SELECTs six columns (`id, tenant_id, question,
  answer, sort_order, status`), never the version, schedule, publish date or stamps;
  authenticated and the service role SELECT, INSERT, UPDATE, DELETE; no TRUNCATE (R5's rule),
  REFERENCES, TRIGGER or MAINTAIN for anyone; no column grant beyond anon's.
- **Triggers:** `faq_items__release_guard` (created exactly as 0066's loop gives every registry
  table, so R5's postcondition and `snapshot_coverage`/`release_guard` hold), the actor,
  `updated_at` and version triggers, the history snapshot (`faq_item`) and the release capture
  (built as 0051's loop builds it, the generated columns read from the catalog).
- **Registry:** `('faq_item', 'faq_items', 'id', 'collections', '{admin,content_creator}',
  '{admin}', '{question,answer,status,sort_order}', …, 10, true, null)`; the TypeScript twins
  (`RELEASE_ENTITY_TYPES`, `RELEASE_REGISTRY` with the `faq:all` tag, `RELEASE_ENTITY_META`).
- **`app.publish_scheduled()`** restated from 0066's body (R5: `search_path ''`, a tenant with
  releases on skipped) with `faq_items` added (D12, D16); no API role executes it.
- **Postconditions** (ten blocks): RLS forced; the exact policy set; tenant first; privileges
  table-wide and per column for PUBLIC, anon, authenticated and the service role (MAINTAIN
  under a `server_version_num` CASE); the six triggers with their arguments; the registry row
  and its columns real; `publish_scheduled`; `faq_text_ok`'s shape, grants and that it refuses
  what it must; the guard first on every registry table; releases still off.
- **No live check** (D17): public content, no PII, the same posture as every content table.

**One loader (D4, D5).** `src/lib/data/faq.ts` `getFaq(locale)`: `contentClient()`,

renders nothing without items. `faq:all` joins `CONTACT_CACHE_ENTITIES`. The R8 preview mirror
knows the table (anon's six columns, published rows, its two policies).

**Byte-identical public output.** The render fixture reads the seeded questions from

**The seed (D11).** `supabase/seed-data/56-faq.json`: today's ten questions, both languages,

## Departures from the brief, and why

1. **One PR, not two** (D1): the owner approved folded PRs; the commits stay separable (U7a's,
   then U7b's).
2. **The help guide ships as a file and a TODO, not a restated set** (the computed task and
   H11). H11's catalog retires the restatement rule: a slice puts its own guide with
   `app.put_help_guide(jsonb, revision)`. H11 is landing first, so the guide is
   `docs/admin-v2/guides/collections-and-faq.json` and the migration carries a marked
   `TODO(H11)` where the one top-level put (revision 0) goes, plus its postcondition, once H11
   is on `main`. Until then `tests/lib/helpCentre.spec.ts` reads filed guides (`FILED`) beside
   the seeded set and holds them to every rule (schema, caps, screens reached, Arabic block for
   block, P-12, no brand) and to the code (the claims test); once a migration seeds the slug, the
   file must equal what it seeds. **The PR must not merge before the put is wired.**
3. **`saving-and-publishing` is not edited** (the brief adds `/admin/faq` to its screens). Under
   H11 a slice changes only its own guide; that guide still names the five collection screens,
   so the help drawer lists it among their guides, and `PAGE_GUIDES` offers
   `collections-and-faq` as their page head's guide.
4. **The lists show the collection's icon, not a thumbnail.** The list endpoints return media
   ids, not URLs; a thumbnail per row needs a media read per screen (and the 0024 public-media
   fence does not cover staff-only assets). Deferred; the drawer's media field shows the image.
5. **Three list projections widened** (the brief says the resource configs are unchanged): the
   testimonials list now returns `quote` and `consent_obtained_at` (the row's words and the
   "Needs consent" badge), clients `logo_media_id` ("Logo" or "Text only"), certifications
   `issuer`. Without them every real quote read "Needs consent" and every client "Text only".
   `tests/lib/collectionScreen.spec.ts` runs every definition over a recording row and fails on
   any key its list does not return. The consent record (`consent_reference`) stays out of the
   list. The same caps read them already (the item GET returns the whole row).
6. **Copy changes beyond the brief:** the testimonial lock's three refusal messages name the
   drawer's switch instead of the old Placeholder box; the em dashes in the five forms' help
   lines are gone.
7. **e2e, the public side of U7b is not asserted in the admin suite.** The public suites pin the
   seeded rows (eight marquee names and three quotes on Home), and the admin project runs beside
   them on one database, so `collections.e2e.ts` works on its own unpublished rows (the quote is
   scheduled for 2099 with no placement, the client stays out of the marquee, the numbers are
   drafts) and checks the stored rows through the service role. What `visible` and a published
   quote do on the site is `home-sections.e2e.ts`'s and pgTAP's.
8. **e2e, the FAQ:** the 201-character question became an answer with a line break (the
   question input's `maxlength` stops typing at 200, so the refusal could not be reached by
   typing); the move is up with the keyboard, then back down with its arrow (the row is added
   last and moved one place at most, so the Contact suite's pinned first question holds).
9. **`orderChanges` numbers only the rows the list holds** (an unknown id took a place before).
10. **The `[id]` route answers 404 for a path that cannot be a uuid**, with the list and a note,
    rather than an empty drawer.
