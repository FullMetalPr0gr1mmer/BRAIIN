# F7: sign-in v2, keep me signed in, forgot and reset password

- **Lane:** UI (Wave 1)
- **Design:** README "Slice sequence", F7 [AV-06]; [ui.md](../ui.md) "Login, forgot and reset
  (AV-06)" and "AV-06: Sign-in v2, keep me signed in, forgot and reset password"
- **PR:** not opened yet (branch `feat/f7-sign-in-v2`)
- **Migrations:** none

## What was built

- **Three screens, zero JavaScript.** `/admin/login` (Welcome back, Email, Password, "Keep me
  signed in", "Forgot password?"), `/admin/forgot` and `/admin/reset` are plain HTML forms in
  their own shell, `src/layouts/AuthLayout.astro`: the prototype's split layout (the rider
  still under a midnight gradient, the quote with the host from `PUBLIC_SITE_URL`, the logo with
  the brand from `site_profile` as its alt). `login.astro` lost its `<script>` and its
  grandfathered entry in `tests/lib/adminConventions.spec.ts`; the shell carries no script
  either, and the test says so.
- **The sign-in page's script, before and after** (`npm run size`, gzip, KB = 1,000 B): F4a had
  already taken it from 168.4 KB (admin-ui) to **2.2 KB** (the login script and `admin-client`);
  with AdminLayout's own script the page loaded 2.9 KB. Now **0 B** on all three screens. The
  gate (`scripts/admin-bundle.mjs`) weighs every sign-in screen and their shell against the
  10 KB budget and reports the 0. The admin bundle sum went 225.37 → 224.93 KB.
- **Endpoints.** `POST /api/admin/auth/login` (extended), `/forgot` and `/reset` (new). A form
  post gets a 303 (back to its page with an outcome code, or on to `next`); a JSON post gets
  JSON. `src/lib/auth/body.ts` reads both; `src/lib/auth/messages.ts` holds the fixed copy a
  page renders for a code, so nothing typed and nothing written into a link is echoed. The
  middleware's pre-auth paths are these three pages and three endpoints (two before).
- **Keep me signed in** (owner item O-14: on by default). `LoginSchema.remember` (default
  true; a form sends the box only when ticked). Ticked: the session cookie carries Max-Age 7
  days and is written again at each token refresh, so a session ends **7 days after its last
  use**. Unticked: session cookies, which end **when the browser closes**. The choice is a
  third `__Host-` cookie, `__Host-braiin-session-only`, because a browser never sends a
  cookie's attributes back and a refresh must know which kind to write.
- **Forgot.** One answer for every address: status, body, page, and time (the call to Supabase
  runs after the response, `waitUntil`). Limits per IP (5 an hour), per e-mail as an HMAC (3)
  and per tenant (50), on EXC-004's Postgres counter with new scopes, failing closed. One audit
  row per accepted request (`auth.password_reset_requested`), service role, no actor.
- **Reset.** The page carries the e-mail's `token_hash` to the endpoint, which in one request
  verifies it, sets the password, signs the account out everywhere (`signOut({ scope:
  'global' })`), clears this browser's session cookies, and audits `auth.password_reset`
  against the account. Per-IP limit (10 an hour), failing closed.
- **Tests.** `tests/authz/login.spec.ts` (form answers, `next`, remember, the six pre-auth
  paths), `tests/authz/recovery.spec.ts` (forgot and reset end to end over stubs),
  `tests/lib/session.spec.ts` (Set-Cookie headers from Astro's own cookie jar),
  `tests/lib/authScreens.spec.ts`, `tests/schemas/auth.spec.ts`; e2e
  `tests/e2e/admin-sign-in.e2e.ts` (no session) and `tests/admin/signin.e2e.ts` (its own
  account: remember on and off, `next`, a full reset that signs a second device out, a spent
  link), CSP and axe on all three screens. The F0 harness still signs in through the form.

## Departures from the design, and why

1. **Zero-JS forms, not an island.** CLAUDE.md §8 allowed either. A page reached without a
   session that loads no code has nothing to attack and nothing to download, and "the no-JS
   form" was something the design meant to keep. It did not work before: the endpoint read
   JSON only, so a post without JavaScript got a 400. Now it is the only path a browser takes.
2. **Their own layout.** AdminLayout's one script (sign-out, menus, the sidebar popover) would
   load on the sign-in screens for nothing, and the split layout shares nothing with the
   shell. AdminLayout keeps its `bare` mode (no page asks for it now; it is what a page gets
   with no session), so this slice changes only a comment there.
3. **A form post's failure is a 303 with a code, not a 401 or 423 status.** Post, redirect,
   get, as `/api/apply` already does; the address never goes into the URL. JSON callers keep
   the generic 401 and the lockout 423 exactly as before.
4. **The token is verified at submit, not when the page opens.** Mail scanners fetch links: a
   GET that spent the token would leave the person with a dead link, and holding the verified
   session between the GET and the POST would need it in a cookie, which would open the admin
   to whoever has the link before any password is set. So the page only checks the token's
   shape; the endpoint verifies it, sets the password and signs everything out in one request,
   on a client made for that request.
5. **The link carries `token_hash`, which needs the recovery template changed** (runbook §2b,
   the design's "PKCE vs hash" risk). Supabase's default link puts a session in the URL
   fragment, which no server reads; such a link shows "not valid" and offers a new one.
6. **A new password is 12 to 128 characters** (OWASP ASVS 4.0.3 V2.1.1, V2.1.2), stricter than
   sign-in's 8 to 256, which must still accept existing passwords. Checked before the token is
   spent, so a short or mismatched password keeps the link. If Supabase then refuses it (its
   own policy, or the same password as before), the token is already spent: the recovery
   session is signed out and the page asks for a new link, plainly.
7. **"Not set up" is a switch, `AUTH_EMAIL_READY`** (astro:env server var, default false),
   not a detection: nothing the Worker can reach says whether Supabase has SMTP. While it is
   off the forgot screen shows "Not set up" and no form, and the endpoint answers every
   request `503 not-set-up` and counts, sends and audits nothing. The reset side works either
   way: its token can only come from a real e-mail (or, in e2e, GoTrue's admin API).
8. **The rate limits' numbers and failure mode** were not in the design: 5/h per IP, 3/h per
   e-mail, 50/h per tenant for forgot, 10/h per IP for reset, all failing closed (the counter
   shares Supabase's database, so when it is down a reset could not complete anyway). The
   tenant cap bounds what a crowd of addresses can make the endpoint do: each accepted
   request is a GoTrue call, maybe an e-mail, and a hash-chained audit row.
9. **The forgot audit row names no one.** The answer must not depend on whether an account
   exists, so the row has no actor and an empty detail, and holds no address and no IP (an
   anonymous visitor's address kept forever in an append-only log would be personal data with
   no purpose). The reset row is the account's, written by the service role too: the recovery
   session is never trusted with a write. Sign-in's own audit row gains `remember`.
10. **Two cookie defects, found and fixed.** The session cookie carried @supabase/ssr's
    Max-Age of 400 days, not the 7 the code said: the library passes its own default on every
    write and `setAll` forwarded it (`src/lib/auth/session.ts` now decides every lifetime).
    And `clearSessionCookies` deleted the `__Host-` cookies without `Secure`, a deletion a
    browser refuses, so sign-out left the (revoked) cookie in place; deletions now carry the
    prefix's attributes.
11. **No length hint under "Keep me signed in"**, as in the prototype; the lengths are in
    CLAUDE.md §3 and the UI lane.
12. **The art panel** is lazy and hidden below 900px, so a phone never downloads it; its widths
    and the logo's (the sidebar's 104 and 264, drawn at 140 CSS px) are on the `/_image`
    allow-list. The quote's second line is the sidebar's text token, not white at 70% (an AA
    pair, `scripts/contrast-audit.mjs`), and the gate gained `primary` on `bg`, the links on
    the light panel.
