## Plan (written before the build)

Releases are off in production until R14. The preview column adds no write: it frames R9's
preview route, which with releases off renders the live page (no pending change exists), and
with them on lays the role's pending changes over it. Every write the editor sends is E1's,
byte for byte (`tests/lib/releaseModeWrites.spec.ts`, `releaseOffWrites.spec.ts` unchanged).

**Scope (E2 only).**

1. **The column** (`src/components/admin/screens/pagePreview/PreviewColumn.tsx`, loaded through
   `import()` on first need, its own lazy chunk group `admin-page-preview`):
   - an iframe of `/admin/preview<path>` (`toPreviewPath`, R9) for the page's English or Arabic
     address, titled "Live preview of <page>";
   - Desktop / Tablet / Phone (1280 / 834 / 390 px), rendered at that width and scaled to the
     column through the CSSOM after hydration (no `style=`, CSP §3);
   - the language follows the editor's (English, العربية; Both keeps the last one), with its own
     English / العربية switch in the column's bar; a change swaps the frame's address;
   - Reload preview; a note while it loads, and one when the frame answers without the bridge
     (an error page);
   - the bar's words, honest per mode: releases on "Your edits are saved as drafts. Nothing
     changes on the site until you publish." (ui.md); releases off the page as visitors see it,
     each save changing the site and the preview reloading after it.
2. **Following the editor.** On the bridge's `ready` the column sends `jump` and `highlight` for
   the open section; selecting another section sends both again; after each save the editor
   makes (a field save or autosave, the eye, a move, Add section, a removal, the page details, a
   History restore) the column sends `reload` once (debounced, so an autosave burst is one
   reload), then jumps back on the next `ready`. A section the preview does not show (hidden,
   or not on that page) gets a plain note instead of a highlight.
3. **Clicking a section in the preview selects it** (ui.md). The envelope gains one
   preview-to-parent message, `select` (a section id), sent by the bridge for a click inside a
   `data-pv-section` element that is not on a link; the editor takes it only for a row it lists,
   through E1's own `select` (so unsaved work is asked about first).
4. **A link followed inside the preview** (R9 keeps it in the preview and reports `navigate`):
   the column says it shows another page and offers "Back to <page>".
5. **Layout** (ui.md "Responsive"): 1280 px and up, three columns (sections, fields, preview);
   below, an "Edit | Preview" switch shows the fields or the preview beside the sections list
   (E1's departure 12 keeps the list stacked above below 1024 px). The frame is mounted only
   while it is on screen, so a narrow screen that never opens the preview never asks the Worker
   for one (P-15).
6. **Who.** Admin and Content Creator (`pages.write`, the roles that get E1's columns). SEO opens
   the editor's SEO card only (E1), so no preview column. Developer and Sales are refused by the
   editor (E1). The preview route keeps its own gate (R9, `PREVIEW_READ_CAPS`).
7. **The bridge** (P-4): the parent half stays `src/lib/admin/previewChannel.ts` (R9), the
   preview half `src/lib/admin/preview/bridge.ts`; both keep the explicit same-origin
   targetOrigin, the origin AND source checks, and the Zod envelope.
8. **CSP.** No policy change: `/admin/**` already sends `frame-src 'self'` (R9's `frameSelf`),
   every response `frame-ancestors 'self'` and `X-Frame-Options: SAMEORIGIN`, and a preview
   render its own policy (R9: `form-action 'none'`, `connect-src` of `READ_ONLY_ENDPOINTS`).
   The column's sizes are CSSOM writes after hydration.
9. **Bundle.** `admin-page-preview` (the column and the parent channel), reached only through
   `import()` from the editor: `scripts/admin-bundle.mjs` gains it in its lazy-only and
   off-screen lists; `admin-ui` no longer claims `previewChannel.ts`. If the build's admin sum
   crosses the 400 KB tripwire, `.size-limit.json` moves to 450 KB with the CLAUDE.md §2
   amendment the owner decided on 2026-10-28 (the per-screen eager graph ≤ 300 KB stays the
   binding budget).

**Files.** `packages/schemas/previewMessage.ts` (`select`), `src/lib/admin/preview/bridge.ts`
(the click report), `src/components/admin/screens/pagePreview/{PreviewColumn.tsx,model.ts}`,
`src/components/admin/screens/pageEditor/PageEditor.tsx` (the third column, the save signal),
`public/styles/admin/pages.css`, `astro.config.mjs`, `scripts/admin-bundle.mjs`, maybe
`.size-limit.json` and CLAUDE.md §2.

**Tests.** Vitest: the column's pure model (addresses, device fit, copy, which messages it
takes), the envelope's `select`, the bridge's click report, the parent channel (wrong origin or
source ignored, malformed dropped), the editor's first paint per role (the column for Admin and
Content Creator, none for SEO), the chunk plan (`adminBundle.spec.ts`). E2E (CI only):
`tests/admin/page-preview.e2e.ts`, signed in, releases off: Admin and Content Creator see the

the preview open; zero CSP violations in the editor and in the frame.

## What was built

The plan held; what differs is under Departures.

### The column (`src/components/admin/screens/pagePreview/`)

- **`PreviewColumn.tsx`** (lazy, `admin-page-preview`): the bar (Preview size: Desktop, Tablet,
  Phone; Preview language: English, العربية; Reload the preview), then the frame area. The
  iframe (`title="Live preview of <page>"`) frames `/admin/preview<path>` or
  `/admin/preview/ar<path>`; its width, height and scale, and its box's size, are CSSOM writes in
  a layout effect, refitted by a ResizeObserver on the area (no `style=` anywhere). Notes: the
  open section not in the preview ("… is hidden, so the preview does not show it", or "… does
  not show on this page"), "The preview shows another page" with Back to <page> after a link
  followed inside it, "The preview could not show this page" (the frame loaded and no `ready`
  came since its previous load by 1.5 s after: an error page, another site, or a link followed
  out of a ready preview to a page without the bridge; `bridgeMissing`) with Show <page> again;
  "Loading the preview…" while a page loads.
- **While the column is hidden** (below 1280 px with Edit chosen) it gives the frame nothing:
  a new address (the language), a reload after a save and the jump to a newly opened section
  are owed, and paid once it is shown again (`frameStep`; a new address covers a reload and a
  jump, a reload covers a jump, since each new document is followed on its `ready`). A frame
  in a `display: none` box still loads and takes messages, but a jump there scrolls nothing.
- **The bridge** is R9's parent half, unchanged (`createPreviewChannel`): the channel reads the
  frame's window when it posts or checks a source, so a remounted frame needs no new channel.
  `ready` → `jump` + `highlight` for the open section when the preview lists it on the editor's
  page, else `highlight: null` (`followUp`); another section opened → the same; a save →
  `reload` after 250 ms (one per burst; a frame that never said `ready` is remounted instead);
  `select` → the editor's `select` only for a listed row on the editor's page that is not
  already open (`mayOpen`); `navigate` → loading; `scroll` ignored. Each `ready` is counted, so
  a load with none since the previous load is a page without the bridge.
- **`model.ts`** (lazy): addresses (`previewSrc` through R9's `toPreviewPath`), the widths, the
  fit, `showsPage`, `followUp`, `mayOpen`, `missingNote`, what a hidden column owes
  (`frameDebt`, `frameStep`) and `bridgeMissing`. **`editorSide.ts`** (in the same folder, but
  with the editor in `admin-pages`, not the lazy chunk): the heading, the lead per mode, the
  Edit | Preview options, `previewLangAfter`.
  Nothing the editor loads eagerly imports the column, its model, the channel or R9's paths
  (`adminBundle.spec.ts`).

### The editor (`screens/pageEditor/PageEditor.tsx`, `model.ts`)

- The third column, `<section class="pe__preview" aria-labelledby="pe-preview-h">` ("Live
  preview" and the lead), drawn on the server; the column itself is `lazy()` inside `Suspense`,
  mounted the first time it is on screen (1280 px and up from `matchMedia`, read after
  hydration, or Preview chosen below), then kept.
- **The save signal**, `revision`: every write the screen makes reports itself through
  `wrote(kind)`, and one table in `model.ts`, `PREVIEW_RELOADS`, says which move it: the eye, a
  move, a removal, a History restore, a row the open form read or saved whose version or
  pending change moved (`rowMoved`; the form's first read and a rebase after a column write are
  not saves), and the page details' row likewise (`pageMoved`, after its first read). A rename
  and Add section (a hidden section) do not: neither changes what a visitor sees. `rowStamp`
  replaces the screen's local `stamp` (the same rule).
- **The preview's language**: the editor's on English or العربية, unchanged on Both; the
  column's own switch sets it too.
- **Edit | Preview** (`Segmented`, "Show"): drawn when the page has an address; CSS shows the
  fields or the preview below 1280 px (`.pe__cols[data-view]`) and hides the switch from 1280 px.

### The envelope and the bridge (R9's files)

- `packages/schemas/previewMessage.ts`: `FromPreviewMessageSchema` gains `{ v: 1, type:
  'select', sectionId }` (strict, the section id pattern). Parent-to-preview is unchanged.
- `src/lib/admin/preview/bridge.ts`: `sectionOfClick(target)` (the marked section a click landed
  in, never through a link or another of the page's own controls, `PAGE_CONTROLS`: a button
  such as the Leadership slider's arrows, a form field or its label, a `summary`, `audio` or
  `video` with controls, an editable box and their ARIA roles; not `[tabindex]`, which the
  layout's `#main` and the slider's scroll track carry; never a marker that is not an id) and
  one click listener that posts `select` to the parent, with this origin as the targetOrigin,
  only when framed. The page's own handling of the click is untouched, and so is R9's link
  handling.

### CSS (`public/styles/admin/pages.css`)

Three columns from 1280 px (`minmax(14rem, 17rem)`, then fields and preview at
`minmax(0, 1fr)` each: a rem minimum follows the browser's default font, which the admin does
not fix, and pushed the grid past the window at a 20 px root), the preview sticky below the
topbar (`top: calc(var(--ad-top-h, var(--ad-top)) + 16px)`, as maintenance.css's side
column); the switch rules below 1280 px; `.pe__preview` and `.pv-col*` (the prototype's
`.ed__col--preview`, `.pv__bar`, `.pv__frame`, on admin tokens only). The frame area is
`clamp(22rem, 100vh - 16rem - <topbar>, 56rem)` tall, so the stuck column still fits the
viewport. Contrast audit: PASS.

### Bundle (`astro.config.mjs`, `scripts/admin-bundle.mjs`)

`admin-page-preview` (priority 13.3: below `admin-pages`, so what both use stays in the
editor's chunk or higher, and above `admin-screens`, whose path rule would claim it):
`PreviewColumn.tsx`, `model.ts` and `src/lib/admin/previewChannel.ts`, which `admin-ui`'s path
rule no longer claims. `editorSide.ts` joins `admin-pages`. The script: the new group is
lazy-only and off-screen for `admin-ui`; `admin-pages` may not import it or `admin-preview`
statically; it may import `admin-pages` (it loads only on the editor).

## Departures from the design, and why

1. **One bridge and one envelope, R9's** (P-4 wins over AV-26's `previewBridge.ts` names); the
   envelope gains `select` for ui.md's click-to-select (the verification's "keep one" note).
2. **No CSP change** (AV-26 planned a `buildCsp` option): R9 already sends `frame-src 'self'` on
   `/admin/**` only, `frame-ancestors 'self'` and `X-Frame-Options: SAMEORIGIN` everywhere, and a
   preview render's own policy.
3. **Edit | Preview below 1280 px at every width**, not only 1024 to 1279 px: below 1024 px the
   sections stay a list (E1's departure 12), so the same switch serves.
4. **The column has its own language switch** besides following the editor's: on Both the
   person still picks the preview's language.
5. **Releases off, the lead is not ui.md's** ("Your edits are saved as drafts…" is untrue while
   each save is live); with releases on it is ui.md's, word for word.
6. **SEO gets no preview column**: E1 gives SEO the SEO card only; Open page stays.
7. **Kept once mounted, and given nothing while hidden** (P-15): a reload, a new address (the
   language) and a jump asked for while the fields show wait until Preview shows again, so no
   Worker request is made for a preview nobody sees, and switching back to Preview does not
   load it again unless something changed.
8. **Added**: Reload (the prototype's refresh button) and the notes above.
9. **No help guide change**: the `editing-pages` guide (E1) does not mention the preview; a
   sentence would need a migration (H11's put) and a help-set restatement, kept out of this
   slice (Owner questions).
10. **A click on the page's own controls in the preview does not select its section** (ui.md:
   "clicking a section in the preview selects it"): using the Leadership slider's arrows, a
   disclosure or a field in the preview would otherwise switch the editor to that section, and
   with unsaved words ask "Leave without saving?".

All of these are in the deviations register ([deviations.md](../deviations.md), "The page
editor's live preview column").

## Self-review (two lenses)

- **Security.** The frame's address is built from the page's server-read slug through
  `PAGE_PATHS` and R9's `toPreviewPath`, never from a message. Messages both ways keep R9's
  rules (same-origin targetOrigin, origin AND source, Zod), and `select` opens only a section the
  editor lists, through the editor's own select (unsaved work is asked about). The preview route
  keeps its own gate (`PREVIEW_READ_CAPS`), its `form-action 'none'` and its narrowed
  `connect-src`. Residual, unchanged by E2: the preview is same-origin with the admin by design
  (P-4), so a script injected into a public page could reach its parent, as it could already
  open an admin window from a preview tab. Public pages run under the nonce CSP with no
  `'unsafe-inline'`, and a sandbox without `allow-same-origin` would break the bridge, the module
  scripts and the session.
- **Correctness.** Found and fixed in this pass: Add section reloaded the preview for a hidden
  section (no visible change, one Worker request wasted); a hidden preview reloaded on every
  save (P-15), now deferred until it shows; the column unmounted when the screen narrowed, so
  returning to 1280 px loaded the page again and axe could meet a frame mid-load: now kept.
- **Not covered by a unit test:** the frame's timers and the ResizeObserver (browser only; the
  e2e covers the fit, the reloads and what waits while hidden). What the timers and the observer
  decide is pure and held by vitest (`frameStep`, `bridgeMissing`).
