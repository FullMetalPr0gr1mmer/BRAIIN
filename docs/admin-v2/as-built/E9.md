## Plan (written before the build)

Releases stay off in production. Everything here is a page section column, written through the
resource kernel's existing section routes (`/api/admin/sections`, `/sections/[id]`), so with
releases off a save is the live save it is today, and with releases on it is staged with the
section like every other section column (the registry row restated). No new route.

### What a section may choose (one code map, `packages/schemas/sectionAppearance.ts`)

Each choice is a closed bucket stored on the row; null is the section's own look, and a section
with nothing chosen renders byte for byte as today.

| Choice | Values | Which sections take it | Why that set |
|---|---|---|---|
| Background | `mist` (light grey), `ink` (black), `klein` (Primary) | Text block, Gallery (E10's paper blocks) | Their every colour is read through the variant's scoped rules, which the contrast gate checks pair by pair. A designed band's colours are its design: each would need its own variant rules, pairs and baselines. |
| Spacing | `compact`, `roomy` | Text block, Gallery, Video | The blocks' padding is one rule each; a designed band's spacing is its layout. |
| Reveal | `fade`, `rise` | every section except the page-opening kinds: Hero, Story, Who we are, Page head (the heading group), Project banner (Our Work's LCP poster) and Slogan (its own scroll animation) | §6: an LCP element or anything that starts visible is never reveal-gated. |
| Anchor | lower-case words joined by single hyphens, 1 to 40 characters | every section whose component does not already name its own anchor (`#inquiry`, `#apply`, `#projects`…, shown read-only as today) | The code anchors are links other code points at. |

- **Reveal is also ignored, server-side, on the first two sections a page shows** (whatever their
  kind): a banner hero is short, so the section under it is in the first screen (Contact's and
  Join's measured LCP is that section's heading). The editor says so on those sections.
- **Anchors:** unique per page; never one of the ids the site's code renders (`#main`, the skip
  link's target, `#content`, every code anchor, the forms' and headings' ids, by name or by
  pattern: `*-heading`, `*-error`, `*-h`, `cf-*`, `af-*`, `svc-*`, `cs-*`, `tm-*`,
  `site-footer-*`), and never a discipline's slug (the Services explorer's panels are ids named
  by their discipline). A test reads every id the render snapshots contain, so a component that
  adds an id cannot ship without the rule knowing it.

### Layers

1. **Database (0127):** four nullable text columns on `page_sections` (`background`, `spacing`,
   `reveal`, `anchor`), each with a CHECK holding its bucket and the kinds that take it (the
   anchor's shape, length and reserved names); a UNIQUE (tenant, page, anchor) constraint,
   DEFERRABLE INITIALLY DEFERRED so a release that swaps two anchors applies; the release
   registry's `page_section` row restated with the four columns; `public.page_sections_unlocked`
   (a password page's read) restated to return them. No grant or policy change: staff write
   under `page_sections_write` (`app.can_write_content()`: Admin, Content Creator), anon reads
   them with the row (0016), which the public render needs.
2. **Worker:** `SectionWriteBase` gains the four keys (closed enums, the anchor's rules, '' is
   null); `sectionResource.assertWritable` refuses a choice the merged row's kind does not take,
   an anchor on a section that names its own, a duplicate on the page (through the overlay-aware
   database, so a staged save sees pending anchors) and a discipline's slug; `constraintFields`
   puts a database refusal on its field.
3. **Render:** the loaders carry the four values as `SectionData.appearance` only when one is
   set; SectionRenderer turns them into `data-bg`, `data-space`, `data-reveal` and `id` on the
   section's own first element (SectionBoundary, as the preview's marker is added): no wrapper,
   no `style=`, no class merge, CSP unchanged. A value the kind does not take, a reveal in the
   opening two, an anchor that is taken (reserved, used earlier on the page, a discipline's slug
   in the route's data) or an element that already has an id is dropped at render too. The CSS
   is `global.css`'s (E9 block): scoped colour rules per background, padding per spacing, and a
   CSS-only reveal (a scroll-driven animation inside `prefers-reduced-motion: no-preference` and
   `@supports (animation-timeline: view())`, the theme's reveal-off tokens honoured, undone by
   `:focus-within`), so no script changes and content is visible wherever it is not supported.
4. **Editor:** an Appearance card in the section's form (`AppearanceCard.tsx`, the page editor's
   own file), offering only what the kind takes, with the reasons for what it does not; the
   header's anchor line follows the stored anchor; changing an anchor warns that links to the
   old one stop working. Saved with the section (one Save, one version, staged with releases on).
5. **Link picker:** `loadLinkables` adds each published page's stored section anchors
   (`/<path>#<anchor>`, group anchor), read under the caller's RLS.
6. **Contrast:** the audit gains every pair each background carries (text, secondary text, link,
   kicker, heading accent, focus ring); those with a theme colour are pairs the theme gate
   already checks on every save (E4), so a theme cannot break them.
7. **Visual baselines:** a CI-only spec (`tests/visual/sectionAppearance.e2e.ts`) on the seeded
   custom page in both languages: each variant set on its Text block, its computed colours and
   padding read, the contrast measured in the page, axe, and a picture of each variant in the
   design capture.

## Departures from the design, and why

- **Background and spacing on the blocks only** (Text block and Gallery; spacing also the
  Video), not on every section: every colour on them is read through the variant's scoped rules
  and gated pair by pair under any theme the gate takes. A designed band's colours and padding
  are its design. Recorded in deviations.md.
- **No white and no colour picker:** three closed backgrounds; white is the blocks' own.
- **The reveal follows the scroll both ways** (a scroll-driven animation): scrolled back up, the
  section fades as it leaves at the bottom. CSS only, so no script and no layout shift; where a
  browser does not run scroll-driven animations the section is simply there.
- **The opening:** a reveal is never offered on the six page-opening kinds, and is stored but
  not played on the first two sections a page shows (a custom page's floor hero counts, as the
  renderer sees it). The rule counts sections, not pixels: on a route that draws a code banner
  above its sections, the first two sections are under it and still covered.
- **Discipline slugs** are refused in the Worker and dropped at render, not by a database CHECK
  (a CHECK cannot read another table). The other anchor rules (shape, length, reserved names,
  one per page) are in both layers.
- **An anchor on a code-anchored kind** is refused in the Worker and ignored at render; the
  database allows the column there (the Numbers band depends on its content's look), so a row
  written around the Worker renders nothing wrong.
- **No help guide change:** a sentence on the Appearance card needs a migration restating the
  help set (H11), as E2 and E10 left theirs.
- **Visual baselines** are the repository's visual regression (computed styles, contrast
  measured in the page, axe, the design capture's pictures), not a pixel diff. CI only.

  the four keys and columns, every earlier entry unchanged), and by counting the page editor's
  Appearance fields (`appearanceFieldNames`) as the section form's: they ride the section's own
  save.
- **Self-review, security:** an anchor cannot inject markup (the write schema, the CHECK, the
  loader's `max(64)`, the render's plain-token re-check, React's escaping in the link picker);
  both layers hold the kind rules and the anchor rules; no grant or policy change; every Worker
  read is tenant-scoped (the overlay database, an explicit `tenant_id` in the link picker); the
  unlocked read keeps its tenant predicate and its pinned search path. No target-less
  `ON CONFLICT` and no upsert touches `page_sections` (a deferrable unique cannot be an
  arbiter, so one would now fail).
- **Self-review, correctness:** the default renders byte for byte (render snapshots unchanged,
  and the render spec checks every page); the editor's opening rule (`inOpening`, the floor hero
