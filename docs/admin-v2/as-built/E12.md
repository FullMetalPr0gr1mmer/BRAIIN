## Plan (written before the build)

Releases are off in production until R14: a theme save is live with them off and a pending
change of the registry's `custom_theme` row with them on, exactly as E4 left it. Nothing about
the save path, the delivery, the cache or the staged path changes but the settings' shape and
the closed token set.

**What a theme can now set**, each a closed choice (no free CSS, no number box):

| Setting | Choices (brand first) | Token (written only when not the brand's) |
|---|---|---|
| Corners (cards, images, inputs) | brand, square, soft, round | `--bs-radius-scale`: 0, 0.5, 1.5 |
| Buttons | pill, rounded, square | `--bs-btn-radius`: 10px, 0px |
| Heading weight | 800 (extra bold), 700 (bold) | `--bs-heading-weight`: 700 |
| Heading case | uppercase, as written | `--bs-heading-case`: none |

ui.md: heading weight 700/800 only ("Archivo has no 900"; the prototype's Black is not
offered). The prototype's corner slider (0 to 24 px over its own mock site) becomes a scale over
the site's own radii, which differ by component (10 px inputs, 16 to 24 px cards): one closed
multiplier keeps each component's proportion.

1. **Settings v2** (`packages/schemas/theme.ts`): `v: 2` adds `shapes {corners, buttons}` and
   `type {headingWeight, headingCase}`, strict at every level. `ThemeSettingsSchema` reads a v1
   row too (the E4 shape, strict as before) and answers it as v2 with the brand's shapes and
   type, so every reader (the editor, the resource's `toRow`, a release's publish that
   re-derives through `toRow`) sees one shape, and the next save stores v2. The contrast gate is
   unchanged (shapes and type add no colour).
2. **Tokens** (`packages/schemas/themeTokens.ts`): four more keys in the closed set, each with a
   pattern that accepts only its non-brand values. `compileTheme` writes them only where the
   theme differs from the brand, so a v2 theme at the brand's shapes and type compiles to the
   same tokens as its v1 twin (a theme of the brand's everything still compiles to none and is
   linked by no page). `themeCss` writes the closed set in its fixed order, as before.
3. **The public CSS** (global.css and the route sheets, the wide churn ui.md names): every
   component radius that is a card, an image frame, a panel or an input reads
   `calc(<its radius> * var(--bs-radius-scale, 1))`; the buttons (`.cta`, the header's call to
   action, the consent buttons, the filter's apply, the explorer's buttons, the case pill, the
   service page's floating button) read `var(--bs-btn-radius, 999px)`; the headings and display
   lines set in the brand's 800 read `var(--bs-heading-weight, 800)`, and those set in capitals
   `var(--bs-heading-case, uppercase)` (Arabic keeps its `none` overrides: no case in Arabic).
   Each fallback is today's value, so an unthemed page computes exactly what it did. Chips,
   tags, dots, circles, numbers, labels and the admin stay as they are.
4. **Contrast and legibility gates** where the tokens touch text:
   - heading weight: only bold weights (700, 800) are offered, so the WCAG "large text" reading
     every 3:1 text pair of the gate and the audit relies on still holds; a test holds every
     3:1 text pair to display size or bold;
   - corners: a rounded corner must never cut into the text inside the box: for every rule the
     scale reaches, the box's padding is at least `r × (1 − 1/√2)` at the largest choice (the
     point where the curve crosses the padding's diagonal), held by a spec over the stylesheets;
   - case: uppercase only ever applied where it is today (as written is the more legible
     choice); the Arabic overrides stay, held by the same spec;
   - colours: E4's gate, unchanged.
5. **Database** (0121): `app.theme_row_ok` restated: a v1 row as E4 holds it (no shape or type
   token), a v2 row with the closed `shapes` and `type`, the closed key set grown by the four
   keys, and each shape and type token exactly what the settings say. Generated blocks from
   `packages/theme/sql.ts` as E4's (token rules; the new shape/type table). The CHECK keeps its
   name and calls the function, so every write is judged by the new rules; a postcondition
   proves every existing row still passes (a production v1 theme stays valid and served). The
   `theme` guide is put again (shapes and type; its tip no longer says they are fixed).
6. **Delivery and preload**: unchanged route and cache rules. The Arabic hero face (the one
   preload, CLAUDE.md §6) follows the theme: a route that preloads Almarai 800 for its heading
   preloads 700 when the theme sets the heading weight to 700, so the heading's own face is the
   one preloaded.
7. **Editor**: two new cards on `/admin/appearance/theme`, Shapes (Corners, Buttons) and
   Typography (Heading weight, Heading case), segmented controls like Motion; the site sample
   (SVG by attributes) draws them; the read-only facts no longer say shapes are fixed. Reset
   brings back the brand's shapes and type too.
8. **Visual regression over the themed output, EN and AR**:
   - a new assertion suite, `tests/visual/theme.e2e.ts` (the public e2e project, every PR): on
     the public routes in both languages it records the computed radii, weights and case of
     every element, sets the four tokens to the BRAND values through the CSSOM (as the editor's
     preview does, no stylesheet, no CSP change) and requires nothing to change, then sets a
     themed set and requires the probes to follow it (a button square, a card square, the
     headings 700 and as written in English, unchanged case in Arabic), with no horizontal
     overflow and zero axe violations at desktop and phone widths;
   - the design capture (`tests/visual/capture.e2e.ts`) also captures each route themed, in
     both languages, for the side-by-side comparison;
   - the themed Lighthouse run's fixture (`tests/fixtures/themedRun.json`) gains shapes and
     type, so lhci's axe, CLS and TBT read them through the real stylesheet;
   - `tests/admin/theme.e2e.ts`: the new cards, a save, the stylesheet's new tokens, a
     visitor's page wearing them, the Arabic preload following the weight, Reset.

Owner questions kept open from E4 (not re-asked, not answered here): the swatches, the framed
preview, theming the dark ground and the literal glows (E4 Departure 14 stays: this slice
themes no ground and no glow), the accent glow's strength.
