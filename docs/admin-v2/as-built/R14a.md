## Plan (written before the build)

Releases stay OFF in production and in the required e2e job. Nothing below changes what a page,
route or write does while they are off: the product change sits under the shown savebar, which
AdminLayout renders only with releases on, and every test change either holds in both modes or
branches on `releasesOn()`. The required job's projects stay main's
(`tests/ci/releasesRehearsal.spec.ts`).

Each item of the prediction pass (`r14a_predicted.json`, 52 items) is checked against the code
before anything is changed; refutations are recorded below.

### The four failures

1. **integrations.e2e.ts:178** (R14A-1, RM-01). `page.locator('dialog.admin-dialog')` also
   matches the closed "Publish to the website" dialog the savebar island always mounts (kit
   Modal, `admin-dialog mdl`). Fix: the suite's own pattern,
   `page.getByRole('dialog').filter({ hasText: … })`, which skips a closed dialog in both modes.
2. **media.e2e.ts:289** (R14A-2, RM-02). Not a timing flake: in release mode the service editor
   saves a pending change when focus leaves a changed control (P-5, EditorForm's `onBlur`
   flush), and the service GET answers live with that change laid over it, so `now` read the
   test's own draft. The retry "passed" by comparing draft with draft, and the draft leaked
   ("1 in Services") into every later spec, which is what put the savebar over style-finder's
   Save. Fix: the claim in both modes is "leaving publishes nothing": the live poster is read
   with the service role before and after and must be unchanged (with releases off this is the
   same value the API answered, so the releases-off test is unchanged in meaning); the API
   check stays for releases off; in release mode the test removes its own unclaimed pending
   change at the end (service role, this service only), so nothing leaks.
3. **page-preview.e2e.ts:238** (R14A-3, RM-05). The column's lead is per mode by design
   (`previewLead(release)`). Fix: assert `previewLead(releasesOn())`; header comment says both
   modes. Plus RM-06: the "nothing is written" guard (`done()`) also checks, in release mode,
   that no pending change exists for the section (a staged save would never move the live
   version, so the version check alone is blind there).
4. **style-finder.e2e.ts:116** (R14A-4, RM-03, RM-04, R14A-5): a real product bug. The space the
   admin reserves for the fixed savebar is a guess (`--ad-savebar: 64px`, scroll padding 80 px,
   main padding 96 px) while the bar is about 109 px tall on two rows and sits 22 px above the
   window's bottom, so the last control of a page (EditorForm's Save row, a table's pager) can
   sit under it even scrolled to the end, and a keyboard user's focus can be hidden (2.4.11).

### The savebar's space (product; nothing changes while releases are off)

- `Savebar.tsx`: while the bar is shown and not inline (the kit's gallery), a ResizeObserver
  writes its border-box height to `--ad-savebar-h` on the root through the CSSOM (as
  AdminLayout does for `--ad-top-h`; style-src allows the CSSOM, no style attribute in the
  markup), set before paint, removed when the bar hides or unmounts. The logic is a small pure
  helper (`savebarSpace.ts`) a unit spec drives with a fake observer.
- `admin.css`: a gap token `--ad-savebar-gap: 22px` (the bar's own inset); under the existing
  gate `:has(.savebar[data-shown]:not([data-inline]))`: the scroll padding is the measured
  height plus the gap plus 8 px, the main column's end padding the height plus the gap plus
  16 px, the sticky bulk bar (R14A-6, RM-08) and the toasts (R14A-7) are lifted above the bar.
  The fallbacks before the first measure are raised to the probe's worst cases (112 px, and
  200 px at 640 px and below). Logical properties only, so RTL is the same.
- Releases off: no `.savebar` element exists (the island is not rendered), so no gated rule
  matches and the measured property is never set; main's padding, the bulk bar and the toasts
  are exactly main's.
- Guards: a unit spec on the helper (measures, rounds up, follows a resize, removes the
  property on stop, does nothing inline); `adminStyles.spec.ts` rules (every rule that reads
  the measure is under the gate; padding and scroll padding cover the height plus the gap; the
  bulk bar and the toasts are lifted under the gate; nothing outside the gate moves); a
  release-mode e2e in the drill's project (alone, so its pending change is seen by no parallel
  spec): with the bar shown, at 1280, 768, 390 and 320 px, `/admin/ai-config`'s last Save,
  scrolled to the end and focused from the top, is the hit target at its centre and ends above
  the bar; on `/admin/kit` the stuck bulk bar's Clear selection is too. The style-finder test
  is left as it is.
- `contrast-audit` and `adminStyles.spec.ts` run (no colour changes).

### The drill's test bugs

- **DRILL-1**: `wrangler dev --test-scheduled` adds `/__scheduled` only as an esbuild middleware,
  and the adapter's build is `no_bundle`, so the drill's `GET /__scheduled` reached Astro (a
  404) and the release never fired (a 120 s poll timeout). Fix: miniflare's own trigger,
  `GET /cdn-cgi/local/scheduled?cron=*+*+*+*+*` (wrangler's documented local path), whose answer
  (`ok`, 200) is asserted, so a broken trigger fails loudly. The flag stays (the workflow is the
  e2e job step for step plus it); comments corrected.
- **DRILL-2, RM-11**: a scheduled release left by a failed attempt (or an earlier local run)
  survives the draft cleanup and doubles the "Scheduled" card on the retry. Fix: before the
  drill and after it, every release still `scheduled` on the e2e tenant is unscheduled through
  `public.unschedule_release` as the e2e Admin (the database's own path: drafts released,
  status `cancelled`, audited), then the drill's drafts are removed.
- **RM-12**: the drill names what other specs left pending (entity type, id, author) as a test
  annotation before removing it, so a leak points at its spec instead of at a far-away click.
- **DRILL-3, RM-13**: covered by the savebar fix (the real click is kept).

### Other items from the sweep

- RM-09 (kit's raw mouse clicks): the target is centred before it is measured (both modes).
- RM-10 (preview-isolation's transient raw draft): left as it is, see Refuted or deferred.
