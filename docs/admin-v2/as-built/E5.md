### Storage: `public.site_appearance`, a staged singleton

One row per tenant (key `tenant_id`, created on the first save, as `seo_defaults` and E8's
`form_settings`), typed columns, one per option, each a closed set held by a CHECK (two layers
with the Worker's Zod). The header's columns are prefixed `header_`; E7 adds `intro_` columns to
the same row (AV-28: no second table), so the registry row's column list grows, nothing else.

| Column | Values | Default (= today's header) |
|---|---|---|
| `header_logo_position` | start, center | start |
| `header_logo_size` | s, m, l | m |
| `header_menu_align` | start, center, end | center (today's space-between) |
| `header_sticky` | boolean | true |
| `header_hide_on_scroll` | boolean | true |
| `header_solid_after_hero` | boolean | true |
| `header_tint` | none, light, medium, dark | none |
| `header_blur` | none, soft, strong | soft (today's 14 px) |

Plus `version`, stamps and actors. CHECKs: the CTA shown needs its label and link; the tint's

### The public header (Tier A, zero hydration)

- `getSiteAppearance()` (`src/lib/data/appearance.ts`) reads anon's columns through the content
  seam (so the preview overlays a pending change), parses each option on its own (a bad value
  costs that option its default, never the page) and never throws: no row, no database or a
  failed read give today's header.
- `SiteHeader.astro` emits a `data-*` attribute only for an option that differs from its default,
  so with no row (or a row equal to the defaults) the markup is byte-identical to main's. The
  CTA is a link (escaped text, href checked twice), drawn in the bar on wide screens and as the
  last item of the small-screen menu.
- `global.css` maps each bucket to a fixed rule: logo presets set `--bs-logo-w` on the root (so
  `--bs-header-h` and every offset built on it follow) and the `<Picture sizes>` attribute is the
  same preset; alignment and logo position are wide-screen only; tint over the hero is the
  backdrop layer's opacity (no blur over the hero: the intro plate's perf rule stands); blur
  applies to the solid state; the full-screen menu is the same zero-JS `<details>` panel.
- The scroll script reads `data-hide`, `data-solid` and `data-sticky`; with none set it does
  exactly what it does today. CSP unchanged (no inline style, no new origin).

### The admin screen: `/admin/appearance/header`

- Appearance › Header in the sidebar, for `theme.edit` or `nav.edit` holders (Admin, Developer,
  Content Creator); each card renders for its own capability (P-9, the design's split):
  - **Layout** and **Behaviour** (`theme.edit`): segmented controls and switches over the buckets,
    the CTA's bilingual label and link, the read-only facts (the language switch always shows,
    the small-screen menu stays the zero-JS disclosure), and two small previews ("Over the hero",
    "After scrolling") drawn from the form with classes and `data-*` buckets (no `style=`).
    Saved through the singleton kernel (`PATCH /api/admin/site-appearance`, version and 409),
    marked in release mode like every staged editor (R12b), with its History button
    (R14-prep's singleton rule).
  - **Menu items** (`nav.edit`): the header menu's top-level links in order, with move up and
    down, the key star (one per menu: the old key is cleared first) and the eye, each one
    versioned PATCH (or the reorder route) through the navigation API that already exists, and
    links to edit a link or add one on the Menus screen (the existing editor keeps the drawer's
    job: no second navigation editor).
- A help guide for the screen, the page guide entry and the sidebar link (rule 4).
