## Plan (written before the build)

Releases stay off in production until R14. With releases off every save is live, as every
staged editor saves today; with releases on the singleton kernel stages it (R3b). There is no
second write path.

### Storage: `public.site_appearance`, a staged singleton

One row per tenant (key `tenant_id`, created on the first save, as `seo_defaults` and E8's
`form_settings`), typed columns, one per option, each a closed set held by a CHECK (two layers
with the Worker's Zod). The header's columns are prefixed `header_`; E7 adds `intro_` columns to
the same row (AV-28: no second table), so the registry row's column list grows, nothing else.

| Column | Values | Default (= today's header) |
|---|---|---|
| `header_logo_position` | start, center | start |
| `header_logo_size` | s, m, l | m |
| `header_menu_align` | start, center, end | center (today's space-between) |
| `header_sticky` | boolean | true |
| `header_hide_on_scroll` | boolean | true |
| `header_solid_after_hero` | boolean | true |
| `header_tint` | none, light, medium, dark | none |
| `header_blur` | none, soft, strong | soft (today's 14 px) |
| `header_mobile_menu` | drawer, full | drawer |
| `header_cta_show` | boolean | false |
| `header_cta_label` | `{en, ar}`, 1 to 40 characters each, or null | null |
| `header_cta_href` | a site path (`/…`, never under `/ar`) or an `https://` link, at most 300 characters, or null | null |

Plus `version`, stamps and actors. CHECKs: the CTA shown needs its label and link; the tint's
minimum: a bar that stays on screen and does not turn solid after the hero keeps white links over
the page's light sections, so it must use the darkest tint (`dark`, black at 62%, the solid
state's own: AA for white text over white, which needs at least 54%).

- RLS ENABLE + FORCE, the tenant predicate first everywhere: everyone reads the tenant's row (it
  is the public header's settings), the non-staff block (0097) for signed-in non-staff tokens,
  insert and update by the token's role AND, RESTRICTIVE, by the live profile through one new
  helper, `app.role_edits_theme` (`theme.edit`: Admin, Developer), held to `ROLE_CAPS` by
  `tests/authz/sqlHelpers.spec.ts`; nobody deletes (no policy, no grant).
- Grants under both regimes (P-14): anon SELECTs the option columns and `tenant_id` only;
  authenticated SELECT, INSERT, UPDATE; service_role SELECT, INSERT, UPDATE, DELETE; no
  TRUNCATE, REFERENCES, TRIGGER or MAINTAIN for anyone. Postconditions check both what must and
  must not be granted.
- Triggers: `site_appearance__release_guard` first, actor, updated_at, version; AFTER the history
  snapshot (`app.tg_snapshot_singleton('site_appearance')`) and the release capture keyed by
  `tenant_id`.
- Registry row: `site_appearance`, area `appearance`, authors `{admin,developer}`, never removed,
  apply order 110. Tags: `tenant:default` (the header is on every page, so a change purges every
  page, as the theme does until E4's ALWAYS tag).

### The public header (Tier A, zero hydration)

- `getSiteAppearance()` (`src/lib/data/appearance.ts`) reads anon's columns through the content
  seam (so the preview overlays a pending change), parses each option on its own (a bad value
  costs that option its default, never the page) and never throws: no row, no database or a
  failed read give today's header.
- `SiteHeader.astro` emits a `data-*` attribute only for an option that differs from its default,
  so with no row (or a row equal to the defaults) the markup is byte-identical to main's. The
  CTA is a link (escaped text, href checked twice), drawn in the bar on wide screens and as the
  last item of the small-screen menu.
- `global.css` maps each bucket to a fixed rule: logo presets set `--bs-logo-w` on the root (so
  `--bs-header-h` and every offset built on it follow) and the `<Picture sizes>` attribute is the
  same preset; alignment and logo position are wide-screen only; tint over the hero is the
  backdrop layer's opacity (no blur over the hero: the intro plate's perf rule stands); blur
  applies to the solid state; the full-screen menu is the same zero-JS `<details>` panel.
- The scroll script reads `data-hide`, `data-solid` and `data-sticky`; with none set it does
  exactly what it does today. CSP unchanged (no inline style, no new origin).

## Departures

1. **The prototype's sliders are buckets** (Track UI; the deviations row §6.1 header). Tint
   0-100 is none, light, medium, dark (black at 0, 25, 45, 62%); blur 0-30 is none, soft (14 px,
   as built), strong (24 px); logo size 80-180 px is S, M, L. Reason: closed sets the CSS maps
   to fixed rules (CSP, no inline style), whose box sizes the CLS and LCP gates have seen.
2. **The tint's minimum** (README: "tint has a minimum when transparent"): a sticky bar that
   stays see-through after the hero must take the darkest tint, in the schema and a CHECK. White
   text over white needs black at 54% or more for 4.5:1; 62% is the solid bar's own.
3. **No blur over the hero.** The blur applies to the solid bar only. Reason: global.css's own
   rule (a backdrop-filter over the intro plate repaints every frame, Pillar 2).
4. **Logo position and menu alignment are wide-screen only**; the bar under 900 px stays logo,
   key link, menu button and language switch (it fits at 320 px, as today). The button moves
   into the phone menu as its last item. **The centred logo applies from 1280 px**; from 901 to
   1279 px the logo stays at the start. Reason: half the bar cannot hold the six links there,
   so they wrapped onto a second row and the bar outgrew `--bs-header-h`, under which every
   offset built on it fell short (review finding E5-C1). The bar is one row, exactly
   `--bs-header-h` tall, for the seeded menu with a short button (two or three words, the
   field's help) at every wide width; a longer authored menu or button label can still wrap, as
   a longer menu does on main.
5. **The preview is two sketches, not the REL iframe** (ui.md: "the REL iframe, using a scroll
   op"). Reason: with releases off (production until R14) the iframe shows only what is saved,
   so it could not follow the form; the sketches follow every change before it is saved, as the
   prototype's own `opsHeaderPreview` does, cost no Worker render (P-15), and carry no text but
   the button's (contrast). "Open the site" is in the page head.
6. **The Menu items card does order, the key star and the eye**; a link's words and address,
   its sub-links, adding one and removing one open the Menus screen (Edit, Add a link), which
   keeps the one navigation form (and Admin-only removal, `navigation_delete_admin`). Reason:
   one navigation editor, not two; the footer's links (E6) are edited there too. The order
   moves by Move up and Move down, with no drag handle: the buttons are the single-pointer
   path WCAG 2.5.7 asks for, and each press is one reorder write.
7. **Tags: `tenant:default`**, not a `site:chrome` ALWAYS tag: the header is on every page, so a
   release that changes it purges them all, as `custom_theme` does until E4's tag lands.
8. **Browsers without `:has()`** (Firefox before 121) render every logo size as M, the header
   and every offset consistently.
9. **The language switch always shows** (O-13, already in the register).
10. **Nothing for the loading screen**: E7 adds its `intro_` columns to this row and restates the
    registry row with them appended.
11. **A star moved by two PATCHes** (the old key cleared, then the new one set): the unique index
    (0019) allows one key per menu, and there is no transaction across two kernel writes. If the
    second fails, the menu is left with no key link (the bar then shows no key link on phones)
    and the card says the save failed; pressing the star again finishes it.
12. **Typed columns, not jsonb.** ui.md's `site_chrome` held "header, footer and intro jsonb";
    `site_appearance` has one typed column per header option. Reason: each option is a closed
    set held by its own CHECK (the second layer under the Worker's Zod), anon's read is a
    column grant, and the release registry merges and restores per column. The footer is not
    here at all: its settings are columns of `site_profile` under `settings.general` (P-9).
13. **The options are drop-downs, not segmented controls** (the plan above said segmented).
    The singleton editor draws its fields from the field kit, which has no segmented field
    kind; a native `select` is a keyboard-accessible closed set, and a new kind in the shared
    kit is outside this slice. The switches are the kit's `role="switch"` buttons. A select
    also offers "Not set", which leaves that option as it is (formPayload.ts).

## Review fixes (2026-11-01)

Two review lenses (security, correctness) reported eleven findings; each was checked against the
code before it was fixed, and all eleven held. None was refuted (the skeptics refuted none
either). Every fix has a test that fails without it, shown on a `git archive` copy of the branch
(red with the fix taken out, green with it). The e2e runs only in CI, so its new assertions were
run first against `SiteHeader`'s markup with the real `global.css` and the self-hosted fonts in
Chromium (Playwright 1.61), against the CSS before and after the fix.

- **E5-SEC-1 (medium), the live INSERT policy was never exercised.** Fixed in
  `site_appearance.test.sql` (`plan(45)` → `plan(53)`): the demoted Developer, the deactivated
  Admin and the locked Admin each INSERT into a tenant whose row exists, so a refusal by RLS
  (42501) is told apart from the key's (23505); SEO and Sales INSERTs are refused; a live
  Developer's first save into a tenant with no row is taken. Red: with
  `site_appearance_live_insert` restated to read the token's role, the new suite fails 3 of 53
  (`have: 23505 want: 42501`), while the old 45 still pass under the same mutant.
- **E5-SEC-2 (low), the singleton's second link check was untested.** `headerOptions.spec.ts`
  now feeds `toRow` `https://a:b`, `https://%zz` and `https://[::1` (each matches the pattern
  and the CHECK; `new URL()` throws) and expects a `ValidationError`. The public read applies
  the same allowlist: `headerFromRow` keeps a link only when `sanitizeHref` also accepts it, so
  a row written straight through PostgREST renders no button. Red: either `sanitizeHref` call
  removed fails its test.
- **E5-C1 (medium), the centred logo wrapped the menu onto two rows at 901 to 1280 px.** The
  centred grid now applies from 1280 px (`@media (min-width: 80rem)`, with a 1 rem column gap
