## Plan (written before building; kept current)

Status: planned (2026-11-10).

### SQL (0134)

- `app.role_crm_tasks(r)`: `crm.tasks`, Admin only (the one helper per capability;
  `tests/authz/sqlHelpers.spec.ts` holds it equal to `ROLE_CAPS`).
- `public.crm_tasks`: id; tenant_id; title (1 to 200, no control characters); type
  (`call`, `email`, `whatsapp`, `meeting`, `todo`); contact_id and lead_id (optional, composite
  keys to the task's own tenant, ON DELETE CASCADE); owner_id (composite key to profiles,
  ON DELETE SET NULL (owner_id), trigger-checked: an active `crm.tasks` holder of the tenant);
  due_at (timestamptz, not null); done_at and done_by (stamped by the server, never
  client-chosen); note (at most 2000); version and actor columns. Indexes per crm.md §5.4
  (tenant, owner, done, due), (tenant, contact), (tenant, lead), and the open tasks by due.
  RLS ENABLE + FORCE; permissive policies per command through `app.role_crm_tasks`
  (tenant predicate first); a RESTRICTIVE `crm_tasks_live` for ALL commands
  (`app.live_role()`, H16's rule). Grants stated (P-14): authenticated SELECT, INSERT and
  UPDATE on named columns, DELETE; the service role all; anon and PUBLIC nothing.
- `app.tg_crm_task_row` (BEFORE): who and when, the version (moves on an edit of the title,
  type, links, owner, due or note; never on done), done_at/done_by from the server, the owner
  rule, no link to a merge tombstone. `app.tg_crm_task_events` (AFTER, a definer):
  `task_created` and `task_done` on the lead's timeline and the contact's (task id and type,
  never the title or note); a task done on a contact is the contact's activity (crm.md §5.1;
  on a lead it already is, through C5's lead-event trigger).
- Time in the studio's zone, in SQL only (`app.studio_time_zone`, U9): `app.crm_local_at`
  (a local date and time to an instant), `app.crm_task_bucket` (overdue, today, upcoming,
  done for a given now and zone: pure, so pgTAP can pin the day boundary), the snooze
  (tomorrow 10:00 local).
- Readers and writers, SECURITY INVOKER (RLS, the live check and the grants decide; the Worker
  names the tenant and gets nothing unless it is the token's), executable by authenticated
  only: `public.crm_tasks_grouped(p_tenant, p_filter)` ({tz, today, counts, mine_open,
  overdue, today, upcoming, done (the last 20 within 30 days)}; an allow-listed filter: view
  mine|all, contact, lead; 22023 otherwise), `public.crm_task_create(p_tenant, p_task)`,
  `public.crm_task_update(p_tenant, p_task, p_version, p_patch)` (40001 on a moved version,
  P0002 unseen; the snooze computed here), `public.crm_task_delete(p_tenant, p_task,
  p_version)`, `public.crm_my_overdue_tasks(p_tenant)` (the badge).
- Retention (crm.md §8.1): `app.purge_crm` restated with the tasks: a done task goes
  `leads_months` after it was done; an open task with neither contact nor lead goes
  `leads_months` after its last change or due date; a linked one goes with its contact or
  lead (cascade). `app.crm_contact_is_orphan` restated: an auto-contact with a task is not an
  orphan (crm.md §8.1 "no task"). The person erasure doors (`crm_erase_preview`,
  `crm_erase_person`) restated to count the tasks that go (the "(Tasks join in C8.)" note).
  A spec holds each restated function to C5's copy plus its one change.

### Worker (all through `defineAdminRoute`, `crm.tasks`)

| Route | Notes | Audit |
|---|---|---|
| GET /api/admin/crm/tasks?view=mine\|all&contact=&lead= | `crm_tasks_grouped` | none |
| POST /api/admin/crm/tasks | {title, type, dueDate, dueTime, contactId?, leadId?, ownerId?, note?}; local date and time converted in SQL | crm.task.create |
| PATCH /api/admin/crm/tasks/[id] | version for an edit or a snooze; done unversioned | crm.task.update {fields} |
| DELETE /api/admin/crm/tasks/[id] | {version} | crm.task.delete |
| GET /api/admin/crm/tasks/[id]/ics | text/calendar; attachment; no-store; nosniff; the title and the admin link only | crm.task.ics (queued) |

Strict Zod in `packages/schemas/crmTasks.ts` (a module of its own so C7's edits to `crm.ts` and
this slice's never meet). The `.ics` is built by `src/lib/crm/ics.ts` (RFC 5545 escaping,
75-octet folding, UTC; UID `<task id>@<host of PUBLIC_SITE_URL>`, PRODID from
`site_profile.brand_name.en`).
