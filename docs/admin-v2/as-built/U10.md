## What was built

### The data (U10a, 0073)

- `media_assets_tenant_id_id`, `UNIQUE (tenant_id, id)` (U9 reuses it for the site icons).
- `entity_seo.og_media_id` and `seo_defaults.default_og_media_id`: nullable uuids, each a
  composite foreign key `(tenant_id, <column>)` to `media_assets (tenant_id, id)` ON DELETE
  RESTRICT (MATCH SIMPLE: null is not checked), each indexed where set. A share image is always
  an asset of the row's own tenant, and a picture in use cannot be hard-deleted even before
  the Worker's `media_usage` gate. The legacy URL columns stay, read as the fallback.
- `media_assets_public_read`: 0045's text word for word, plus an asset a visible `entity_seo`
  row names (anon's own RLS on `entity_seo` applies, so only a published parent's row
  matches) and one the tenant's `seo_defaults` names. **The recursion rule:** this policy now
  reads `entity_seo` and `seo_defaults`, so no policy on either may ever read `media_assets`
  (42P17 on every public image and head otherwise): a postcondition, a pgTAP assertion, the
  read-back and CLAUDE.md §8 Media hold it. That is also why the tenant fence on the new
  references is a foreign key, not a policy term (D3).
- `public.media_usage` v5: R5's v4 word for word (the `pending` column kept, still four
  columns), plus `entity_seo` (the entity is the page the row describes, labelled
  "service: logo", "project: …", "post: …", "page: …") and `seo_defaults` (the tenant,
  "site default"), both `pending false`. INVOKER, `search_path ''`, EXECUTE authenticated only.
- The two release registry rows restated with the new columns appended, so a release stages
  and publishes a share image like any other SEO column. `apply_release` builds its
  statements from the registry and the snapshot, capture and guard triggers are row-generic,
  so nothing else is restated.

### The rules and the public head (U10a)

- **The pair rule (D4).** Each of the title and the description may be left blank (the page's
  default); a pair written in one language needs the other, refused on the missing half
  (`metaTitle.ar`, …) by the schema and `ENTITY_SEO.assertBilingual` (the staged path calls it
  too). A save that sets nothing on a target with no row creates none and answers the defaults.
- **Caps (D14):** title 120, description 320 per language (`packages/schemas/seoRules.ts`, a
  zod-free module the island reads; `@schemas/admin` re-exports it).
- **Robots (D5):** closed values: per page `null` (follow the site), `index,follow`,
  `noindex,follow`; the site `index,follow`, `noindex,follow`, `noindex,nofollow`. Legacy free
  text is read leniently (`src/lib/seo/robots.ts`: anything naming `noindex` hides the page).
- **Canonical (D6):** a site path only, never `/ar…`, `//host`, a backslash, a query or a
  fragment, at most 2,048. SeoHead localizes it (`src/lib/seo/canonical.ts`: `/x` on the
  English page, `/ar/x` on its twin); a legacy absolute URL on this origin is read as its path,
  anything else is ignored. One equal to the page's own path is stored as null
  (`normalizeCanonical`, one read only when an override is sent).
- **The share image (D2):** the public loaders embed the asset in the same query
  (`og_media:media_assets(PUBLIC_MEDIA_COLUMNS)`, no new round trip); `loadHead` makes it an
  absolute `/_image` JPEG at the picture's own aspect, at most 1,200 px wide
  (`src/lib/seo/shareImage.ts`, which the service and case-study pages now use for their own
  posters too, with the same output). Precedence: the row's picture, its legacy link, the
  page's own image, the default picture, the default link, the logo card. A provider a page
  cannot render, or a row anon may not read, embeds nothing and the next candidate is used.
- **Sitemap and llms.txt (D8):** a URL whose effective robots is noindex (its row's, else the
  site default), or whose canonical names another path, is left out
  (`src/lib/seo/indexable.ts`, after U14a's visibility filter); one extra anon read in the same
  round (`getSeoRules`). A failed read lists as before (the head still says noindex).
- `GET /api/admin/entity-seo/list` (`seo.entityMeta` at full: Admin, SEO): pages, services,
  projects or posts, 50 a page (at most 100), a bounded "contains" search over the slug and the
  English title (LIKE wildcards escaped, quoted for the `or` filter), archived left out, with
  Custom/Default per field, Index and Arabic complete. Its defaults are the routes' own
  fallbacks (`src/lib/admin/seo/defaults.ts`: `PAGE_META`, `serviceTitle`/`serviceDescription`,
  `caseTitle`/`caseDescription`, BlogDetail's reads), held to `loadHead` per type and language
  by `tests/lib/seoList.spec.ts`.
- `useEntitySave` gains the `entitySeo` target (GET by target, PUT of the whole meta with the
  version it loaded; `saveModeFor` answers `live`, R12 adds draft).
- The old singleton form's config (`seoUi`) gains the default share image (a media field),
  shows the legacy link only while one is stored, offers robots as the closed choices, and no
  longer offers `organization` (D11; the column stays).
- Site health: `seo.arabic` links to `/admin/seo` for `seo.entityMeta` holders (D16); the
  sitemap fact says "open to search engines".

### The screen (U10b)

- `/admin/seo` is server-rendered with in-page tabs (`?tab=pages|redirects|site`, as Site
  health), each gated by its own capability; a role holding none of `seo.entityMeta` (full),
  `seo.globalDefaults` and `redirects.manage` gets the layout with the refusal and a 403, and
  nothing is read (`LOCKED_SCREENS` `render: 'server'`). Pages reads its first page on the
  server, so the island makes no fetch on first paint.
- `AdminSeo` (one island, `src/components/admin/screens/seo/`): **Pages** (type chips, search,
  Custom/Default badges with the words the head shows, Indexed/Hidden, Complete/Arabic missing,
  "Edit SEO for <page>" opening `SeoDrawer`; a save refreshes the list where it stands);
  **Redirects** (the redirects `ResourceTable` with "Edit <rule>" and "New redirect" opening a
  drawer that hosts the resource's own form through `useEntitySave`; a save closes it and
  re-reads the list and the edge line; "Sync to edge" kept, `resourceSync.spec` unchanged);
  **Site wide** (the defaults form, with the typed confirmation for a noindex default, beside
  the server-rendered "Built in" rows, `SEO_BUILT_IN`, one list with Site health, and the
  prototype's hreflang note).
- **`SeoPanel`, the shared editor** (for U5, U6, U8 and E1). Its API, kept small:
  `<SeoPanel target context readOnly? canAdvanced? onSaved? />`; `target` and `context` come
  from `loadSeoPanelSetup(sb, auth, type, id)` (`src/lib/admin/seo/list.ts`) on the editor's
  server page. It carries every column of the full replace (shown: title, description, share
  image; carried: the legacy link, robots, canonical, schema type), rewrites legacy values into
  the closed forms before a save (`legacyFixes`), shows the defaults as placeholders and in the
  two previews (`GooglePreview`: the template and brand, the address under `/ar` for Arabic,
  `lang="ar" dir="rtl"`, plain text, the admin's own tokens), the Index switch with its confirm,
  Advanced (the canonical path) for `canAdvanced`, the legacy link with "Remove the link", and
  "Structured data: <type> (set by the page type)". `readOnly` renders the values as text.
- Kit additions (additive): `FieldDef.placeholder` and `FieldDef.multiline` for a bilingual
  field; `EditorForm`'s `after` slot (between the fields and the action bar); `ResourceTable`'s
  `onEdit`, `onCreate` and `epoch`.
- `/admin/redirects` is a 302 to `/admin/seo?tab=redirects` (inside the admin, never a 404);
  `/admin/redirects/new` and `/admin/redirects/<id>` stay as the no-JS twins. In the same
  commit (corrections 16b): `tests/admin/routes.ts` (the locked screen is `/admin/seo`; the
  extras are the three tabs and `/admin/redirects`, which `REDIRECT_PAGES` keeps from being
  swept as a screen while its create and edit pages still are), `refusals.e2e.ts` reads that

  covers the no-JS pages by prefix), `UNSEEDED_LISTS` keeps redirects, and `nav/settings.ts`

- Styles: `public/styles/admin/seo.css` (the tabs' sections, the table's cells, Site wide, the

## Rule 5: the deployed parsers and the push-to-deploy window

0073 is pushed before the merge, so the deployed Worker reads the new shapes for a while:

- `media_usage` v5 keeps v4's four columns; only rows of two new `entity_type` values appear.
  The deployed parsers are `src/pages/api/admin/media/[id]/usage.ts` (`UsageRowSchema`:
  `entity_type: z.string()`, `entity_id` a uuid, `label` nullable, `pending` defaulted; a
  non-strict `z.object`) and `src/pages/api/admin/media/[id].ts` (`UsageSchema`, the same
  shape). Both entity ids are uuids (the target's id; the tenant's id). The old drawer words an
  unknown kind as "Entity seo: service: logo" and links nothing; the old hard-delete gate counts
  the rows and refuses, which is right (the FK refuses anyway). This build words them "Share
  image (service: logo)" and "Default share image" and links them to the SEO screen for the
  roles that open it.
- The public loaders select columns by name: the old Worker never selects the new columns, so
  its heads are unchanged until the deploy. `getEntitySeo`/`getSeoDefaults` in this build
  embed `media_assets`, which needs 0073's foreign keys: deploying this build BEFORE 0073 is
  applied would fail those two reads (each fails closed to "no row", so the head falls back to
  the page's own words and the defaults in code; no page breaks). Push first, as rule 5 says.
- The admin's entity-SEO GET selects `ENTITY_SEO.COLUMNS` (now with `og_media_id`): the old
  Worker's list does not name it, so it reads as before. Its PUT writes the six columns it
  knows; a full replace from the old Worker leaves `og_media_id` as it was (it never names
  it), so nothing set by the new screen is wiped by an old one.

## Departures from the design, and why

- **One PR, one migration** (the owner's folded-PR decision): the brief's two files are one,
  and U10b's migration is only the help guide's TODO (H11 owns how a guide ships now).
- **The help guide is filed, not seeded** (the 2026-10-18 instruction: H11's
  `app.put_help_guide` lands first; no slice restates `app.help_article_set()`). Until the
  wiring, production's guide still describes the old form.
- **No 1200x630 crop (D2):** the share image is the picture's own aspect at most 1,200 px wide;
  the `/_image` guard refuses a height off the asset's aspect, and posters already ship so.
  Owner to confirm.
- **Schema type is not editable (D7):** a read-only row; JSON-LD types are code-owned and
  CI-validated. The column is carried unchanged by every save.
- **The drawer's Save is inside the drawer's body**, at the end of the form (EditorForm's own
  action bar), not in the drawer's fixed footer: EditorForm owns its bar (Ctrl/⌘+S, the
  status, the version) and the SEO panel is the same component the editors' tabs show.
- **The Pages and Redirects tabs are sections with a heading**, not cards: the kit's DataTable
  draws its own card, and a card inside a card doubled the frame.
- **`listEntitySeo` lives in `src/lib/admin/seo/list.ts`**, beside its defaults module, not in
  `entitySeo.ts`: R3b's staged route imports `entitySeo.ts` on every request, and the list's
  page fallbacks (PAGE_META and the page modules) need not ride along.
- **`releaseOffWrites` snapshot updated on purpose**: the legacy write path now writes
  `og_media_id`, and the sample canonical is a site path (an absolute URL is refused now).
- **The sweep's derivation**: a page that only redirects is no longer pushed as a screen but
  still derives its create and edit pages (`tests/admin/routes.ts`), so `/admin/redirects/new`
  and `/admin/redirects/[id]` stay swept; `adminRoutes.spec` says so.
