## Plan (written before the build)

- **Scope.** The Worker stops reading and writing every column C14b drops: `leads.status`,
  `leads.internal_notes`, `leads.ip_inet`, `leads.timeline_band` and `crm_settings.timezone`.
  The legacy routes go: `GET /api/admin/leads` (the old list; the POST that adds a lead by hand
  stays) and the `?pii=1` alias of `GET /api/admin/leads/[id]` (the CRM's audited
  `POST /api/admin/leads/[id]/reveal` is the one reveal). The legacy panel island is already
  gone (C4b); the PATCH's refusals of `status` and `internalNotes` (422s naming the field) stay,
  since they write nothing.
- **Both schemas.** Every query the code makes must work on today's production schema (the
  columns present, the legacy sync and the notes mirror still running) and on C14b's (the
  columns gone), because C14b is applied while this code is live. A query that names none of
  the five columns does both.
- **Files.** `src/lib/admin/leadFields.ts` (the safe, gated and sensitive lists without the
  legacy columns), `src/lib/crm/reveal.ts` (no legacy field set), `src/pages/api/admin/leads/
  index.ts` (POST only), `[id].ts` (no `?pii=1`), `[id]/reveal.ts` and `LeadContactCard.tsx`
  (no `timeline_band`), `export.ts` and `packages/schemas/crm.ts` (no status column or filter,
  no band column; note bodies still never exported, the count from the thread), `src/lib/crm/
  exportRead.ts`, `src/pages/api/hooks/notify-lead.ts` (the timeline from the encrypted field
  only), `src/lib/crm/indexBackfill.ts` (the cron reads no band), `src/lib/crm/settings.ts` and
  the CRM settings screen's types (no time zone), `packages/schemas/admin.ts` (the unused legacy
  lead schemas), `scripts/bench-lead-export.mjs` (the export's shape).
- **Tests.** A static gate, `tests/lib/leadsContract.spec.ts`: no code under `src/`,
  `packages/`, `scripts/` or `supabase/functions/` names `timeline_band` or `ip_inet`;
  `internal_notes` only in job-application code; no lead query (a `.from('leads')` chain, its
  continuations, the crud helpers on `leads`) names `status` or any dropped column, and no
  `crm_settings` query names `timezone`; no string asks for `/api/admin/leads…?pii=1`; the
  leads list route exports no GET. Behaviour: a stand-in PostgREST that knows only the columns
  of C14b's schema (today's grant replayed, minus the dropped columns) answers every lead route,
  the export, the reveal, notify-lead and the cron; `GET …/[id]?pii=1` answers the safe row and
  decrypts nothing. The endpoint cases lose the two removed routes (`endpointCoverage` holds
  completeness); the per-role cases of the reveal and the notes thread stay as they are (Admin,
  Developer and Sales allowed; Content Creator and SEO refused). The admin e2e's locked-screen
  twin for `/admin/leads` moves off the removed GET.
- **Docs.** This note (with C14b's exact plan), the README index line, CLAUDE.md where the
  expand-window sentences describe paths this PR removes, the launch runbook's rollback floor.
