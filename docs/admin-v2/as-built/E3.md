## Plan (written before the build)

Releases stay off in production until R14. With releases off every save is live; with them on
the singleton kernel and the resource kernel stage it (R3a, R3b, R12b). There is no second
write path: the template editor's "This service" and "This project" groups save through the
same `useEntitySave` target as the full editors (`/api/admin/services/[id]`,
`/api/admin/portfolio/[id]`, the resource kernel), and the shared text through the singleton
kernel (`/api/admin/template-copy`).

### Storage: `public.template_copy`, a staged per-tenant row

One row per tenant (key `tenant_id`, created on the first save, as `seo_defaults`, E8's
`form_settings` and E5's `site_appearance`), one column per template, each a JSON object of
the keys that DIFFER from the built-in words (the F5b rule: store differences):

- `service jsonb not null default '{}'`: the service page template's shared text;
- `project jsonb not null default '{}'`: the project (case study) page template's;
- `version`, `created_at`, `updated_at`, `created_by`, `updated_by` and the standard triggers.

The slice's brief named "one row per tenant per key". The release registry keys a table by
`id` or by `tenant_id` only (releases.md §2.5): rows per key would need a surrogate id per key
(two people adding the same key before a publish stage two creates that collide at apply) or a
third key kind through `apply_release`, the overlay, the preview mirror and history. A row per
tenant with a closed map per template keeps every per-key rule (the catalogue, both languages,
the caps, a missing key is the built-in words) on machinery the singleton kernel already has,
and is the shape verification.md's challenge names. Departure 1 below.

Each key is from a CLOSED catalogue per template (`packages/schemas/templateCopy.ts`): a text
key holds `{en, ar}`, both required, plain text (trimmed, 1 to the key's cap, no `<` or `>`,
no control or line-break character); an accented heading has a sibling accent key
(`<heading>Accent`, F5b's word range per language, AccentSchema). A key that is missing (or
no row at all) is the code's built-in words, so the Tier A HTML with no row is byte for byte
what it was, English and Arabic.

The database holds the same rules as the Worker's Zod (two layers): a CHECK per column,
`app.template_copy_ok(kind, copy)` (IMMUTABLE, INVOKER, `search_path ''`): an object of at
most 16 KB whose keys are the template's catalogue, each text key exactly `{en, ar}` of
non-blank strings of at most 300 characters with no `<`, `>` or C0/C1 control character, each
accent key `{en?, ar?}` of `{from, to?}` small integers. `tests/lib/templateCopySql.spec.ts`
holds the SQL key lists equal to the catalogue.

RLS ENABLE + FORCE, the tenant predicate first in every policy: everyone reads the tenant's
row (it is public copy, and anon renders it), the non-staff block (0097's pattern) for signed-in
tokens that are not CMS staff (Sales), Admin and Content Creator insert and update by the
token's role (`app.role_edits_pages(app.current_role())`, a new helper for `pages.write`, held
to `ROLE_CAPS` by `tests/authz/sqlHelpers.spec.ts`) and RESTRICTIVE by the live profile
(`app.live_role()`); nobody deletes. Grants stated (P-14): anon SELECT on `tenant_id`,
`service`, `project`; authenticated SELECT, INSERT, UPDATE; the service role SELECT, INSERT,
UPDATE, DELETE; no TRUNCATE, REFERENCES, TRIGGER or MAINTAIN for anyone.

Registry contract (releases.md §1.3): every CMS role reads it (#1), its write policies say who
authors it (#2), it has `tenant_id`, `version` and the standard triggers (#3), the guard
(`template_copy__release_guard`), the snapshot (`app.tg_snapshot_singleton('template_copy')`)
and the capture (`app.tg_release_capture('template_copy', 'tenant_id', '')`) in the same
migration (#4), its TS entry (#5), one capability (#6). Registry row: `template_copy`, area
`pages`, authors `{admin,content_creator}`, no removal, columns `{service,project}`, apply order
110. Publishing it needs `pages.write` + `content.publish` (a content area, P-2).

### The catalogue (the template's whole shared text)

- **Service page** (`SERVICE_PAGE_COPY`, F6 gathered it): the crumb's "Services" and the
  structured data's "Home"; the hero's skip pill (kicker and link) and its button ("See the
  case study"); the service band's tag and "What you get"; the value band's tag, heading (with
  its accent) and lead; the case band's tag, "See the full project", "Where they were", "The
  problem", "What we did"; "Say hello"'s lead-in ("Let's talk", before the service's name) and
  lead; "More in {c}" (the discipline's name for `{c}`), "Everything in" (before the
  discipline's name) and "All services"; the floating "Skip to inquiry".
- **Project page** (the case-study components' words, moved into
  `src/lib/portfolio/pageCopy.ts` `CASE_PAGE_COPY`): the banner's tag; "All projects" and the
  keyword list's name; Overview, Scope of work, The goal, The result, Final film; the
  breakdown's tag, heading (with its accent), lead and its three still kinds; the gallery's tag
  and heading (with its accent); the image viewer's four control names; "Next project".
- **Not in it:** "Confidential client" (`confidential`): one wording the Our Work cards, the
  case study's facets and the service page's case block share (FacetTags), so it stays the
  code's until a slice makes it editable everywhere at once.

### The public pages (Tier A, zero hydration)

- `getTemplateCopy()` (`src/lib/data/templateCopy.ts`) reads anon's columns through the content
  seam (so the preview lays a pending change over it), parses each key on its own (a bad key
  costs that key its built-in words, never the page) and never throws: no row, no database or a
  failed read give the built-in words.
- `loadServicePage` and `loadCaseStudyPage` read it in their first round (one subrequest more,
  in parallel); the page object carries the resolved copy (both languages, because the hero's
  button takes a pair) and every component takes its words from it instead of the constants.
- An accented heading: stored words take the stored accent (none stored: no accent); built-in
  words take the built-in accent, unless an accent alone is stored (F5b: an accent kept
  without its heading colours the built-in words).
- Cache: the service and case-study routes stamp a new entity tag, `template_copy:all`, which
  the registry entry purges (R7; `tests/lib/releaseTags.spec.ts` holds it to the routes).
- In a preview render only, the template parts carry `data-pv-section` (`tpl-<part>`), so the
  editor's preview jumps to the part picked in its list; the public HTML is unchanged.

- Server page `src/pages/admin/pages/template/[kind].astro` (Admin, Content Creator:

    English / العربية / Both and "Arabic missing: N", **Full editor** (the item's own editor),
    Open page in English and Arabic;
  - the parts column: the template's fixed parts in the page's order, read only (picking one
    moves the preview to it), then the two things this screen edits: "This service" / "This
    project" and "Shared text";
  - the fields column: the item's own words (a subset of the full editor's fields, the same

## Departures

1. **One row per tenant, not one per key** (see the plan): the registry keys a table by `id` or
   by `tenant_id` only, and a closed map per template keeps every per-key rule.
2. **ui.md's read-only "Shared text" is overruled by the README's E3 row** (editable, staged,
   Arabic required, code defaults), as verification.md's challenge on UI deviation 11 asked.
   Recorded in ui.md ("Resolved departure (E3)") and deviations.md (Content; the §8.1 row).
3. **"This service" saves through the full editor's PATCH, not entity drafts of its own** (ui.md
   said "write the entity drafts"): one write path to the row. With releases off it is live with
   a 409 on a stale version; with them on the resource kernel stages it (R3a, R12b), so it is the
   entity's draft after all.
4. **"Confidential client" stays code-owned:** the Our Work cards, the case study's facets and
   the service page's case block share it (FacetTags); making it editable belongs to a slice
   that changes it everywhere at once (owner question 1).
5. **A rewritten accented heading has no accent until one is chosen:** the built-in word range
   would land on the wrong words of new text. An accent saved alone colours the built-in heading
   (F5b's rule).
6. **No purge on a live save while releases are off** (as E8 found for every staged editor):
   nothing caches Tier A until O-3, and with releases on a publish purges `template_copy:all`,
   which every service page and case study stamps (owner question 2).
7. **The picker's group labels are the disciplines' English names** (the admin chrome is
   `lang=en dir=ltr`, F1); each option is the item's English title.
