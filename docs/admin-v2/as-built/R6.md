## Plan (written before the build)

- **Scope.** `POST /api/admin/releases` (publish now) and `POST /api/admin/releases/validate`
  (the Worker's checks plus the database's dry run). Per change: `requiredCaps` through
  `assertCap` (a null is a 403), `liveRecheck`, the payload re-parsed with the entity's schema
  and `toRow` (`derivePatch`), `assertWritable` and, for a row that is live afterwards,
  `assertPublishable`, both over the state the release leaves. Cross-change checks:
  dependencies (a link to a pending create left out), a link into another tenant, a change
  whose parent the release removes, the R3b leftovers (a singleton create whose row now
  exists, an entity-SEO create whose target gained a row), warnings (a published service
  under an unpublished discipline). Then `public.apply_release` through the service client,
  its refusals mapped to items and fields; after commit, never fatal: the redirect and
  visibility KV syncs and the purge as a logged no-op (O-3). Per-area publish with every item
  ticked is the client's (R12); the server takes any selection of at most 60 changes and a
  note of at most 280 characters (O-4, P-15).
- **The overlay-aware database.** `src/lib/release/overlayDb.ts`: `exists`, `get`, `list` over
  live with a layer of changes laid over it. The domain rules that read the database
  (`assertLinkInTenant`, the redirect chain and live-route rules) read through it, so a link
  to a pending create and a redirect over a slug the same release renames pass. Releases off,
  the rules issue exactly today's queries.
- **Files.** `src/lib/release/{overlayDb,links,validate,apply}.ts`, the two routes,
  `packages/schemas/release.ts` (the report and answer shapes), the rules in
  `src/lib/admin/resources/{shared,redirects}.ts` and `src/lib/admin/redirectRules.ts`, the
  stage-time database in `src/lib/release/staged.ts`.
- **Tests.** `tests/lib/overlayDb.spec.ts`, `tests/lib/releaseValidate.spec.ts`,
  `tests/lib/releasePublish.spec.ts`, rows in `tests/authz/cases/releases.ts`; the releases-off
  proof is the existing call-for-call specs staying unchanged.
