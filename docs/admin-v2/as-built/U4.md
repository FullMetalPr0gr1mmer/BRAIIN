## What was built

**The list (0064).** `public.media_library(p_tenant, p_q, p_kind, p_needs_alt, p_limit, p_offset)`
returns `{total, rows}` as JSONB. SECURITY INVOKER (media_assets' `media_read` still decides the
rows), `search_path ''`, a 500 ms statement timeout, `authenticated` alone executes it (revoked
from PUBLIC, anon, authenticated and the service role first, both grant regimes). Empty, never an
error, for another tenant or a caller who is not staff (the belt for a first non-staff
`authenticated` principal). 22023 for a query over 64 characters or holding a C0/C1 control
character, a kind that is not one of the four, a limit outside 1..100 or an offset outside
0..10,000. The search folds both sides with `app.normalize_ar_q`, escapes `\`, `%` and `_`, is
ignored below 2 folded characters, and covers the display name, the alt text in both languages,
the tags, the folder and, for anything but an upload, the stored path (a still's file name); an
upload's random key and the size in it are never searched. `created_at desc, id desc`, the total
counted apart from the page. The columns are the media resource's list columns plus `mime_type`.
The help set is restated from 0060 with only `media-library` rewritten (minutes 3; slug, place,
tags, screens and capability unchanged) and reseeded. Postconditions: the function's shape and
callers (no PUBLIC ACL entry), the 15 guides, the guide's place, and every tenant's row equal to
the set. pgTAP `media_library.test.sql`: **plan(56)**, replayed green in PGlite (CI is the
authority), with `help_centre.test.sql` (64) and `media_uploads.test.sql` (69) unchanged and green.

**The routes.** `GET /api/admin/media/library` (`media.write` full or meta; `MediaLibraryQuerySchema`:
`q` ≤ 64 with no control character, `tab` images only, `alt=missing`, `limit` 1..100 default 48,
`offset` 0..10,000; the session's tenant named; 22023 → 422; rows through the media resource's
`fromRow`). `GET /api/admin/media/stats` adds `uploadsReady` (`uploadsConfigured()`: the Images
binding and Supabase, the one test `acceptImage` now makes before "Not set up") and `canUpload`
(that and `media.write` full); both read through `src/lib/admin/mediaLibrary.ts`, which the page's
first render uses too. `MediaMetaOnlySchema` is held to the upload's rules (D6: alt in both
languages, never null, 1..300 each, no control character; 20 tags of 40; a folder of 200, still
clearable). `fromRow` adds `preview_url` (640 px for an upload, the built still for `static`), and
`storageThumbUrl(key, base, width = THUMB_WIDTH)` takes the width (`PREVIEW_WIDTH = 640`, a listed
width). One endpoint case and its manifest line.

**The library (`/admin/media`, island `AdminMediaLibrary`, code in `screens/media/`).** The first
page is server-rendered through the same loader. Toolbar: "Search media" (debounced 250 ms, a newer
request aborts the older), Images | Videos, "Needs alt text", "Storage used: N MB of 1 GB" with the
design system's bar. The dropzone (Content Creator, Developer, Admin, uploads set up) with "Choose
images", a real button; a drop elsewhere on the page never opens the file in the tab. The page
head's Upload is a link to `?upload=1` that the island turns into a file chooser. The grid: 48 a
page, the kit Pager, tiles named by their caption first. Empty states for no pictures, no match
("Clear search") and nothing missing alt text. Videos: `SITE_CLIPS`, read-only, no player. "Not set
up": "Uploads are not set up yet." in place of the dropzone. The address follows the view (`?q=`,
`?tab=videos`, `?alt=missing`, `?page=`, `/admin/media/<id>` while a drawer is open);
`?upload=1` puts focus on "Choose images" and is never written back.

**The drawer.** Preview, facts (File, Type, Dimensions, Size, Added as an absolute Riyadh time, so
the server and client renders agree, Folder), the words through `EditorForm` + `useEntitySave`
saving through the meta door for every role (D5), "Used in" (links only to screens the role's
sidebar opens), Download (uploads), Replace file (full roles, uploads set up: the new file checked
in the browser, then "Replace this picture everywhere it is used?" with "Remove the old file from
the web now", sent with progress and the form's version; a 409 offers "Reload their version"),
Delete (Admin; off, with "This file is in use. Remove it from those places first.", while "Used
in" loads, fails or lists anything).

**The upload dialog and the picker (`fields/media/`, the `admin-fields` chunk).** "Describe your
images": a row per file with its size and decoded size, or the server's own words for a file it
would refuse (`fileFacts`: the 20 MB limit, U3's sniffer over the head, `createImageBitmap` closed
at once; no URL is ever made of the file), Alt text (English), Alt text (Arabic) and Tags. Upload
is refused, with an ErrorSummary, until every ready file is described in both languages; then the
files go one at a time (`uploadQueue`, a pure machine), each with a `<progress>`, then "Uploaded"
or the server's words and "Try again"; Cancel stops the one in flight and keeps nothing pending;
leaving while sending asks first. `xhrUpload` sends U3's contract (raw body, `x-csrf-token` from
the meta tag, the file's type, `x-media-meta`). `refusalText` shows the route's own words, the
daily cap as a day, a role, a lost race and a dropped connection. `MediaPicker` is the library's
grid in a kit Modal named "<Label>: choose", rendered at the end of `<body>` (`BodyPortal`):
search, pages, a press or Space selects (`aria-pressed`), Enter or a double click chooses, Use
image, and Upload in place (one file, described, sent and chosen) where the stats route says the
role and the Worker can take a file.

**The frozen API (for U5, U6).** `MediaField`: default export, `FieldComponentProps`, `altGap`, the
tile, and the picker's name are unchanged; a new optional `FieldDef.media?: { upload?: boolean }`
(the kit's sample sets `upload: false`, risk R9). `MediaPicker` with the brief's props exactly.
`xhrUpload.ts`: `uploadImage(file, meta, {onProgress, signal})` and
`replaceImage(id, file, meta, {...})`, each resolving `{ok: true, row}` or `{ok: false, refusal:
{status, error, detail}}` (an abort rejects with `UploadAborted`). `useEntitySave`'s resource
target gains `saveUrl?: (id) => string`, used for the PATCH only (additive; the load and a create
are unchanged; `entitySave.spec.ts`).

**Elsewhere.** `/admin/media/[id]` is the library with that drawer open (a 404 for an id that is
not one of the tenant's pictures, D3); `/admin/media/new` is a 302 to `/admin/media?upload=1`
(D4). The dashboard's "Upload media" goes to `?upload=1`; site health's alt-text fix to
`?alt=missing`. `src/lib/media/clips.ts` (`SITE_CLIPS`, one entry, 18.389 s read from the file's
`mvhd`) is created with exactly the shape F5b's brief gives (D14): F5b was not on `main`; whichever
merges second resolves the add/add (the code is identical, the header comment differs).

**The chunk rule (corrections rule 7) and O-15.** `ADMIN_EDITOR_ISLANDS` and a new
`ADMIN_EDITOR_SCREENS` are built from sorted one-a-line lists (`AdminMediaLibrary`,
`AdminResourceForm`, `AdminSingletonForm`; `media`), which admin-ui leaves. A shared
`admin-screens` group (priority 13, below `admin-fields`) claims every island entry and screen
module no other group claims, except the kit screen, the dashboard and F5a's two editor entries,
which keep their own chunks; a later slice adds its island and directory to the lists and joins the
group by path. `scripts/admin-bundle.mjs` gains two checks: admin-ui must not statically import
`admin-fields`, `admin-screens` or `admin-dashboard`; and a chunk that only admin chunks load
(statically or lazily) must be named `admin-*` or `Admin*` (the bundler's runtime helpers,
`preload-helper` and `rolldown-runtime`, excepted by name). `adminBundle.spec.ts` holds both on
fixtures and pins the group's claims. **O-15 is not decided**, so the size-limit sum stays the
tripwire and `.size-limit.json` keeps its 300 KB admin entry unchanged; CLAUDE.md §2's F4 amendment
says so with today's figure.

## Departures from the design, and why

- **The island takes `permissions`, not `role`.** What the buttons offer and which "Used in"
  entries link are computed on the server from `ROLE_CAPS` and the nav registry, so neither ships
  in the browser (the bundle note above). The routes still decide.
- **The page head's Upload is a link** (`/admin/media?upload=1`) the island upgrades to the file
  chooser: the page head is server-rendered outside the island. **`?upload=1` focuses "Choose
  images"** instead of opening a dialog: a browser opens a file chooser only on a press.
- **The sweep does not open `/admin/media/new`.** It asks each page for its own 200; a redirect is
  listed in `REDIRECT_PAGES` (`tests/admin/routes.ts`), checked to redirect where it says
  (`adminRoutes.spec.ts`) and by `media.e2e.ts`. A filtered extra of a screen no longer derives
  its create and edit screens a second time (Playwright refuses a repeated title).
- **Joining `admin-screens` is not "by path alone" for a field-kit island** (a departure from
  w3_corrections rule 7's "later slices join it by path with no config edit"): `admin-ui`
  (priority 20) still claims every island and screen module the two lists do not name, so a
  later island whose graph reaches the field kit must add one line to
  `ADMIN_EDITOR_ISLAND_NAMES` and one to `ADMIN_EDITOR_SCREEN_DIRS`; otherwise `admin-ui` would
  import `admin-fields` and `scripts/admin-bundle.mjs` fails the build (check 4). An island
  that does not reach the field kit needs no edit (it stays in `admin-ui`). Inverting the rule
  (`admin-ui` claiming only a frozen list of legacy screens) would remove the edit but move
  every existing screen's code; not done here.
- **The storage meter is in binary units** ("214 MB of 1 GB", as the plan counts its 1 GiB);
  the tile's size badge stays in KB of 1,000 B (P-10).
- **"%" alone finds everything**, not only `50%_off` (the brief's §5.4 asked both that and "one
  character is no filter"; the floor wins). pgTAP proves `%` and `_` literal with `%_` and `50%_off`.
- **The drawer's "Added" is an absolute Riyadh time**, not `relTime`: a relative time can differ
  between the server render and hydration (a console error the sweep fails on). U9a's clock work
  (plan §5.6) can take it.
- **An unknown "Used in" kind is said as its type in words** ("Entity seo: home"), no link.
- Recorded in `deviations.md`: D2 (picker images only), D4, D7, D15, the meter's bucket.
