## Plan (written before the build)

Releases stay OFF in production and in the required e2e job. Nothing below changes what a page,
route or write does while they are off; every product change is gated on the release mode the
server reports, and every test change holds in both modes or branches on `releasesOn()`.
`playwright.config.ts` keeps main's projects with `E2E_RELEASES` unset (held by
`tests/ci/releasesRehearsal.spec.ts`). The switch itself, and flipping the CI seed or the
required e2e job to release mode, are R14c (below), at the owner's go.

## What was built

### Releases off: what changes and what does not

Releases stay off for every tenant and in the required e2e job. With them off:

- **Every page, route and write is main's**, but for one release-flag read per request on the
  page-visibility routes (as R3a and R3b added to every release-managed route; a failed read is
  a 500, as there). The page-visibility PUT parses its body in the handler (a staged save also
  names its pending change, which the strict schema refuses), with the same 422 before anything
  is read (`stagedPageVisibility.spec.ts` "a bad body is still a 422 before anything is read").
  A save or a password set marked as made in release mode is refused (409 `releases-off`), as
  every other release-managed route refuses one; no screen sends the mark with releases off.
- **No screen draws anything new**: no list answer carries `pending` or `draftsInvalid`, so the
  visibility screen draws no pending badge and keeps its live words; no create's target is
  staged, so EditorForm draws main's status select and Scheduled for.
- **SaveStatus says the same words**: `savedWords` (`src/components/admin/kit/saveWords.ts`) is
  the words moved out of the component so the e2e specs can read them; output unchanged.
- **Two guides change words** (0128): each keeps every sentence true today and says which way of
  publishing it describes, then what changes once releases are on.
- **The required e2e job runs what it ran, plus the converted specs' release-mode branches,
  which do nothing with releases off**: `withDraft` is `{...values, version}` (main's body),
  `publishOwn` and `discardDrafts` return at once, `savedPattern` is main's "Saved at" pattern.
  A few releases-off assertions became mode-aware without changing what they assert off
  (the screens' status filters, templates' writes list), and theme gained a status wait
  before reading the row (true in both modes). `playwright.config.ts` unset is main's, project
  for project (`releasesRehearsal.spec.ts` unchanged for the unset shape).

### 3. The static write-path test
