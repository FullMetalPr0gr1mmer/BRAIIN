## Inert, and how that was checked

Nothing enters the preview scope until R9 adds the `/admin/preview` branch of
`src/middleware.ts`, and nothing imports `src/lib/preview` (a guard, below). On a build of this
branch against a build of the same tree with `main`'s `source.ts` (same toolchain, same env):

- `dist/client/**` is byte-identical (sha256 of every file): public JS and every static asset
  +0. `npm run size` prints the same numbers (public and admin, delta 0 B).
- In `dist/server/**`, after blanking chunk file names, exactly two files differ: the seam's
  own chunk (`contentClient()` now asks the AsyncLocalStorage store first, the
  `node:async_hooks` import, and the two module values) and the entrypoint manifest, whose
  page-to-chunk map lists the same entries in a different order (chunk hashes moved). No
  preview code is in the bundle.
- Outside a scope `contentClient()` returns `anonClient()`, the same instance
  (`tests/lib/contentScope.spec.ts`, `tests/lib/contentSource.spec.ts`), so every loader sends
  the query it sent before, with the same client; the public render suites
  (`tests/render/**`) are unchanged and green. Tier A HTML, headers and Cache-Tags are what
  they were; the parity e2e that renders both sides is R9's.

## What was built

**The scope, `src/lib/data/source.ts`.** `withContentSource(source, fn)` runs `fn` under
`als.run()` (never `enterWith`/`disable`), refuses a nested scope and a source opened twice,
and keeps a token holding a WEAK reference to the source in a module-level `openScopes` set
for the scope's life (removed in `finally`; a scope whose `fn` never settles keeps only the
token, so its rows and drafts can be collected; review L5). When `fn` resolves to a Response
with a body, the body is read to the end inside the scope and a buffered copy (status, status
text, headers) is returned, so a render that streams cannot run its components after the
scope has closed, unseen by the tripwire (review L4). `contentClient()`: the store's client
inside; outside, `noteAnonLookup()` on every open scope whose source is still alive, then
`anonClient()`. `source.ts` imports nothing of the
preview: the preview implements `ContentSource`.

**`src/lib/preview/` (server only, reached by nothing yet).**
- `select.ts`: the select parser (columns, `alias:target(...)` and `target(...)` embeds, at most
  three tables in a path, whitespace ignored). Refused with `PreviewUnsupportedError`: `*`,
  casts, hints and `!inner`, spreads, JSON paths, column aliases, quoted names, aggregates,
  empty items, unbalanced parentheses, a fourth table. Parse trees are memoised by the select
  string alone and frozen (bounded at 256 strings).
- `relations.ts`: the 21 tables, their keys (the paging order), and the 22 foreign keys between
  them with their on-delete action and migration; `resolveEmbed` (through an FK column, a
  referenced table's name, or a child table's name; ambiguous or many-to-many is refused).
- `visibility.ts`: the anon-RLS mirror, one rule per table, each naming its policy and latest
  migration, and a policy subquery mirrored as "that row is visible" (it runs under anon's RLS
  on the joined table); the eight-branch media rule (0045) built once per request, with the
  `lax $.**.mediaId ? (@ == $id)` walk checked against PostgreSQL 18's jsonpath; `ANON_COLUMNS`
  (the four column-granted tables), `MIRRORED_POLICIES` (every policy on an anon SELECT, per
  table), `HOSTED_PROVIDERS`, `VISIBILITY_DEPS` and its closure.
- `client.ts`: the emulator. `from(table)` (a known table), then `select`, `eq`, `in`,
  `contains`, `order`, `limit`, `maybeSingle` in any order after `select`, and `then`. A
  `Proxy` refuses every other property, records it in `report.unsupported`, then throws, in
  every build; `rpc(name)` answers `PV001` and records `rpc:<name>` as not previewed. Text
  comparison through R2's `matchesQuery`; numbers, booleans and ISO instants ordered natively,
  text by code unit; NULL placement and `nullsFirst` as PostgREST; a stable multi-key sort;
  `limit` after the sort; `maybeSingle` (null, the row, `PGRST116`/406); `42703` for a column
  the table's rows lack, `42501` for one outside anon's grant (an embed's join column
  included); embedded rows through the mirror (a hidden one is `null`, a one-to-many array
  drops them). The builder executes against the dataset it was made from and never reads the
  AsyncLocalStorage store (a spy test).
- `dataset.ts`: `createPreviewSource({ supabase, session, only?, now? })`. Refuses (403
  `AuthorizationError`) no session, an inactive one, or a role that reads no registry entity
  (`canPreview`, `PREVIEW_READ_CAPS`, `readsEntity`: exported for R9). Reads only through
  `opts.supabase`. Each table on first need, with its visibility closure, memoised per request:
  `select(cols, {count: 'exact'}).order(key…).range(a, b)` until the rows equal the count or the
  cap (2,000; media 5,000), never stopping at a short page; `*`, or anon's columns on the four
  tables. The drafts in one paged read (`DRAFT_COLUMNS`), the tenant's only, `only`-filtered,
  then by area (a draft of an area the role cannot read is counted, never listed, malformed or
  not), parsed lazily with `derivePatch` when its table is first read. Updates, creates
  (`CREATE_DEFAULTS` then the patch, key and tenant), deletes with their cascades and set-nulls,
  a project's link sets as `app.apply_portfolio_children` writes them, and R4's stamps.
- `report.ts`: `PreviewReport`, `assessPreview` (ok, or untrusted with its reasons),
  `previewLogFields` (counts and names only), `PREVIEW_COPY` (the ribbon's words, P-12) and
  `notPreviewedKey`.

**Guards** (`tests/lib/contentSource.spec.ts`, extending W0-d's): `withContentSource` is named
only in `source.ts` (`SCOPE_ENTRIES` is empty; R9 adds the middleware); nothing under
`src/lib/data/` imports the preview; `src/lib/preview/**` names no `anonClient`,
`serviceClient`, `contentClient`, `withContentSource`, client factory or anon key and imports
nothing from `src/lib/supabase` or `src/lib/auth/session`; the seam, the 15 loaders and the
preview create no module-level state (`let`, `var`, `new …()`, a mutated constant) but the
four allowlisted, request-free values (`MODULE_STATE_ALLOWED`: the ALS instance, `openScopes`,
the parse memo, and `pageSections.ts`'s constant `KNOWN` set), and so does every non-admin
module that reaches a loader through its imports (review L7: identity, the page composers,
the head builder, the sitemap; `CALLER_STATE_ALLOWED` holds one request-free entry, the
legal notices' token RegExp). The release registry's
client-reach walk (`tests/lib/releaseRegistry.spec.ts`) now also forbids every file of
`src/lib/preview`.

**Tests.** `contentScope` (the scope, concurrency over awaits, timers and `Promise.all`, the
tripwire, a throw), `previewSelect`, `previewClient`, `previewVisibility` (every fence, every
media branch, each fence flipped by a pending change), `previewDataset` (paging, `max_rows`

Developer's areas, foreign rows), `previewReport`, `previewLoaders` (every exported loader of
the 15 files inside the scope over the fixture tenant, with no refusal and no anon lookup, and
the static check below), `previewMirror` (the pgTAP literals both ways and its `plan`), and
`tests/authz/previewOverlay.spec.ts` (role × entity type, by hand from §5). The fixture is
`tests/fixtures/previewDataset.ts` (one made-up tenant covering every fence, and a fake staff
client with `max_rows`, failures and a call log); `tests/lib/loaderQueries.ts` reads every
query the loaders build from their source.

**pgTAP** (`preview_dataset.test.sql`, 20): the four CMS roles read every fixture row of the 21
tables with the dataset's projection; a `sales` claim and anon only the public ones;

migration (CI is the authority). No stale-token row: R8 adds no policy or definer relying on
`app.live_role()`; the dataset reads exactly what the person's token reads.

## Departures from the design, and why

1. **The emulator's surface is the README's, not releases.md's.** No `neq`, `is`, `range`,
   `single`: unused by every loader (verification claim 13); each is refused and recorded. Also
   refused: column aliases, `select()` options, `order`'s `referencedTable`, `limit` options,
   and a filter before `select` (supabase-js has none there either).
2. **Paging ends at the exact count**, not at a short page (D4), so a project whose `max_rows`
   is below 1,000 still reads every row; a truncated table marks the render untrusted (D3)
   instead of showing part of it.
3. **The anon tripwire is isolate-wide (D1).** A scope-less lookup while any preview is open
   marks every open preview, since a lost scope cannot be traced to its request. It fires
   falsely when a public request is served by the same isolate during a preview render (proved
   in `contentScope.spec`). R9 measures it on staging. It catches a scope lost on the way to
   a loader; a render that lost the scope entirely is caught by zero reads.
4. **The ribbon is rendered by R9 (D2).** R8 ships the verdict, the reasons and the copy as data.
5. **No snapshot RPC** (plan B7 item 11): the TS mirror, pinned by pgTAP and R9's parity e2e.
6. **A media cap of 5,000** (D3) next to 2,000 for every other table; media reads whole, never by
   id on demand (subrequests, P-15).
7. **`page_visibility` drafts are "not previewed"** with `redirect` and `custom_theme`: U14a's
   row (0057) made 21 registry types, 18 of them previewable. Page visibility is an edge rule,
   not row security (below).
8. **`PreviewReport` gains `pending`** (the ribbon's count from the raw list of readable
   drafts, D9), which the verdict's `ok` state carries; `notPreviewed` holds `rpc:<name>` and
   entity types, and `notPreviewedKey` maps each to its copy line.
9. **Drafts are parsed with `ContentDraftRowSchema.pick(...)`**, the columns the dataset
   selects, not the whole row schema (which requires `base`, `label` and the actors the preview
   never reads).
10. **`CREATE_DEFAULTS` is wider than "the columns visibility and order read"** (D6): it also
    carries the NOT NULL defaults the loaders' own row schemas require and a create's `toRow`
    may omit (`is_teaser`, `value_points`, `scope`, …), or a pending create would be dropped by
    its loader's Zod parse. Every value is pinned to `pg_get_expr` of the column default. A
    column a created row lacks reads `null`; `42703` is judged against the live rows' columns
    (unknown for a table with no live row).
11. **The policy set is pinned too.** Beyond the brief's two literals, a third
    (`_anon_policies`, held equal to `MIRRORED_POLICIES`) fails when a migration adds, drops or
    renames any policy on an anon SELECT of a preview table. That is how a new fence (U14b's)
    cannot pass unnoticed.
12. **`published_at` is R4's rule exactly** (D13): stamped when the patch sets `status` to
    `published` and the live value is null, on the seven tables that have the column. No table
    with a go-live flag (`visible`) has a `published_at`, so the brief's "or its go-live flag"
    has nothing to stamp.
13. **`report.overlaid` counts as tables load** (lazy, D9): a draft of a table the page never
    read is pending but not overlaid. A pending create whose key already exists is reported `invalid`; a pending delete of a row already gone is `live-missing` (offer Discard), not counted as shown; an update keeps its row's key and tenant whatever the patch holds (the self-review's two fixes).
14. **Cascades come from kept delete drafts of the parent table.** No preview table that a
    cascade removes rows from is referenced by another preview table (only `navigation`
    references itself, and its cascade is followed down every level), so a parent's own drafts
    are the whole set; `previewDataset.spec` holds that fact.
15. **`contains` on a column that is not an array is refused**, recorded, not answered.
16. **The preview's request-free constants are arrays, not Sets**, so the module-state rule can
    stay strict ("no `new` at module level") with a four-entry allowlist; `pageSections.ts`'s
    existing `KNOWN` Set is allowlisted because R8 changes no loader.
17. **The scope tests live in a sibling file**, `tests/lib/contentScope.spec.ts`, and only the
    static rules extend the shared `contentSource.spec.ts` (fewer conflicts with U14b and the
    loader-adding slices).
18. **Rows are shared within one request, not cloned per query:** the loaders parse what they
    get (Zod returns new objects) and none mutates a row; nothing crosses requests.
19. **A quote's consent is checked (review L3, security).** The dataset also reads
    `consent_obtained_at` and `is_placeholder` on testimonials (`DATASET_ONLY_COLUMNS`, staff
    read them; the emulator still answers 42501, so no loader sees them), and a change that
    would leave a quote published or scheduled with neither is reported `invalid`, not shown,
    as 0028's `testimonials_consent_gate` would refuse it. Not modelled, a gap for R9: 0025's
    production placeholder guard (with 0027's per-table override), which refuses a flagged
    design sample going live in production on all seven placeholder tables; the preview shows
    such a change as live.

## Page visibility (0057) now, and the password mode (0061) if it lands first

- **0057 is accounted for.** U14a hides a page at the edge (`src/middleware.ts`, from the KV
  snapshot) and filters the menus, sitemap, llms.txt and search through `locals.visibility`;
  it adds no anon policy and anon holds nothing on `page_visibility` (pgTAP 20; the pinned policy
  sets of `pages` and `page_sections` are unchanged). So the mirror's `pages` and
  `page_sections` rules stay 0001/0011's, and a pending page-visibility change is "not
  previewed" at the data layer. What a preview of a hidden page shows, and which listing it
  uses, is R9's (below).
- **If U14b's 0061 reaches `main` first**, it adds `page_sections_password_fence`, a
  RESTRICTIVE SELECT TO anon hiding every section of a page whose `page_visibility.mode` is
  `password`. Then: pgTAP assertion 19 fails until `_anon_policies()` lists the fence, and
  `previewMirror.spec` fails until `MIRRORED_POLICIES.page_sections` does; the
  `page_sections` rule gains "and its page is not in password mode", which needs
  `page_visibility` as a dataset-only table (staff read it, 0057) with `page_sections →
  page_visibility` in `VISIBILITY_DEPS`, and page-visibility drafts then overlaid for that
  fence; media branch 6 (sections) inherits it, since that subquery runs under anon's RLS on
  `page_sections`. U14b's `pageSections.ts` also reads an unlocked page's sections through
  `serviceClient().rpc('page_sections_unlocked')` when `pageAccess()` is set: R9 must never run
  a preview render inside `withPageAccess` (that read would bypass the overlay), and
  `contentSource.spec.ts` merges U14b's `SERVICE_ROLE_IN_LOADERS` with R8's rules as a union.

## Notes for R9

- Call `withContentSource` only after the auth gate, with `createPreviewSource({ supabase:
  locals.supabase, session: locals.session, only })`, and add `src/middleware.ts` to
  `SCOPE_ENTRIES`. Gate first on `assertAnyCap(session, PREVIEW_READ_CAPS, ['full', 'view',
  'meta'])` (it agrees with `canPreview` for every role; a test holds it).
- Return the render's Response from `fn`: `withContentSource` buffers it inside the scope
  itself. Anything the render starts that outlives `fn` (a `waitUntil`, a stream made
  elsewhere) is not seen by the tripwire: keep it out of a preview. Then
  `assessPreview(source.report())`; render `PREVIEW_COPY` (and `notPreviewedKey` lines); log
  `previewLogFields` to `system_logs` once per untrusted render.
- Measure D1's false positives on staging; if noisy, demote `anon-lookup` to a log line and
  keep zero reads, refusals and truncation as untrusted.
- Seed every fence for the parity e2e (the fixture tenant here lists them). D10: rows tied on
  `sort_order` come back in heap order publicly and in key order in preview; seed without ties
  or add `id` as a tiebreaker in the loaders (a public order change only where it was
  unspecified).
- Page visibility: decide what the preview route shows for a hidden or link-only page and whether
  listings use the live snapshot or one with the pending changes; never wrap a preview in
  U14b's `withPageAccess`.
- O-16: Home reads about 16 tables (its own, the embeds and the media closure) plus one drafts
  read, one subrequest each below 1,000 rows, so about 17 plus the session's own calls, under
  50. CPU: Zod and `toRow` per draft only for tables read, and in-memory joins over up to 2,000
  rows a table; measure on staging.
