## Plan (written before the build)

Releases stay off in production until R14. With releases off every save is live; with them on
the singleton kernel and the resource kernel stage it (R3b, R12b). There is no second write
path: the footer's basics are the identity singleton's existing PATCH
(`/api/admin/site-profile`, `settings.general`), the columns are the navigation API's existing
routes (`/api/admin/navigation`, `nav.edit`). No new API route, no new capability, no new
table.

### Storage

- **The basics** already exist (U9, 0102): `site_profile.footer_copyright` (bilingual
  template, only `{year}`, `{brand}`, `{place}` braced), `footer_style` (light, dark),
  `footer_show_email` (default true), `footer_show_social` (default false). They stage with
  the identity (the registry's `site_profile` row lists them since 0102) and keep its history
  (R14-prep). E6 adds no column there.
- **The columns** are navigation heading rows (AV-29): `navigation.is_heading boolean not null
  default false`, and `href` becomes nullable, held by one CHECK
  (`navigation_heading_shape`): a heading has no link, is in the footer, is top level and is
  never the key link; every other row keeps a link (so every existing row is valid as it is).
  A column's links are the footer links whose parent is the heading (the existing `parent_id`).
- **At most four columns** per tenant: a BEFORE trigger (`navigation_footer_columns`, INVOKER,
  after the release guard by name) takes a transaction advisory lock per tenant, counts the
  tenant's other heading rows under the writer's RLS and refuses a fifth with 23514 naming
  `navigation_footer_columns_max` (the kernel maps it to a 422). Counting hidden headings too:
  a column hidden today is one shown tomorrow.
- **The release registry**'s `nav_item` row restated with `is_heading` appended (0038's row
  otherwise word for word), so a release stages and publishes a heading like any other column;
  the TypeScript registry derives the same list from the resource's fields.
- No grant changes: anon's table-level SELECT on `navigation` (0011) reads the new column as
  every other; staff write it under the table's RLS (`navigation_write`, Admin and Content
  Creator).
- **The help guide** `footer` (H11's put, revision 0, place 44, caps `settings.general` and
  `nav.edit`, screen `/admin/appearance/footer`).

## Departures

1. **Columns are navigation heading rows, edited through the navigation API** (AV-29), not a
   list on `site_profile`: the links are already navigation rows with RLS, history, releases and
   the Menus editor, and P-9 forbids splitting a row across two capabilities, so the columns are
   under `nav.edit` (Admin, Content Creator) while the basics are under `settings.general`
   (Admin, Developer). Each role sees only the cards it can save.
2. **A column's title, a link's words and address, adding a link and removing one stay on the
   Menus screen** (as E5's menu card): one navigation editor, not two.
3. **Removing a column removes its links** (`parent_id ... on delete cascade`, 0009, as a header
   link's sub-links). The screen and the guide say so ("choose No column for them first"). A
   guard that refuses removing a non-empty column, or moves its links out, is an owner question
   (below), not built here.
4. **The preview is a sketch, not the REL iframe** (as E5, departure 5): with releases off the
   iframe shows only what is saved; the sketch follows the form before the save and costs no
   Worker render. "Open the site" is in the page head.
5. **Hidden columns count toward the four**: a column hidden today is one shown tomorrow.
6. **A column with no link is not drawn** on the site (a title over nothing); the card says so.

## Owner question

- **Removing a non-empty footer column**: today it removes the links in it (the copy warns).
  Should the database refuse it until the column is empty, or move its links out of the column
  first? Either is a small follow-up (a BEFORE DELETE trigger plus a 409 on the Menus screen),
  but it touches the release apply path, so it is not in this slice.
