## Plan (written before the build)

Production's releases stay OFF until the owner runs runbook §6p; this PR merges, with every
required check green, BEFORE that switch. Nothing here changes what a page, route or write does
in either mode: it changes which mode CI proves, and two lines of copy.

### Decisions recorded (made before this slice, by the orchestrating plan and the owner)

1. **The required e2e job runs in release mode.** `perf-seo-a11y.yml`'s `e2e` job keeps its id
   and its name, so the required check is still exactly
   `perf-seo-a11y / E2E + axe + CSP + video bytes`; it sets `E2E_RELEASES: 'on'`, installs the
   psql client before the preview, and starts the preview with `--test-scheduled`, as the
   rehearsal did (the drill fires the minute cron through miniflare's
   `/cdn-cgi/local/scheduled`, R14a). `playwright.config.ts` then adds `releases-on` (the switch
   as the owner on the loopback database, after the sample rows) and `releases-mode` (the drill),
   and every spec runs in release mode. `supabase/seed.sql` is not changed: the switch stays the
   runbook's function, and the seed keeps refusing production.
2. **A releases-off run stays, as a SECOND job, not a matrix leg**, in the same workflow:
   `e2e-releases-off`, named "E2E with releases off". It is main's e2e job as it was, step for
   step (the design capture and its upload included), with `E2E_RELEASES` unset: the
   releases-off describes (`RELEASES_OFF_ONLY`) and every route's live path end to end, until
   the contract slice (R15) removes the live paths. It is **not** a required check
   (`.github/branch-protection.json` is unchanged; main's seven required checks keep their
   names: migrations, build-test, supply-chain, deploy-preflight, db-tests / pgtap,
   perf-seo-a11y / E2E + axe + CSP + video bytes, perf-seo-a11y / Lighthouse budgets).
3. **It runs on every PR and every push to main**, not weekly: decided from the measured
   durations below. The jobs of one run start in parallel on their own runners, so the
   releases-off job adds runner minutes but no wall-clock time to a PR while it is shorter than
   the release-mode job. And until the owner switches production on, releases off is the mode
   production runs: between this merge and the switch, it is the only end-to-end proof of what
   visitors and editors get.
4. **The rehearsal workflow is retired** (`releases-rehearsal.yml` deleted): the required job
   now does exactly what it did. Nothing only it did is lost: a hand run on any branch is
   `perf-seo-a11y.yml`'s own `workflow_dispatch` (both jobs, both modes).
5. **The design capture moves with the releases-off job.** The required job is then the
   rehearsal's job step for step (the run that passed), so no step the rehearsal never ran is
   added to the gate, and the capture's pictures stay what the mockup comparison has used.
6. **The admin visual baselines stay on releases off.** `admin-visual.yml` (hand-run, never
   required) is held equal to the e2e job up to the preview, env included; if it followed the
   required job into release mode the committed baselines (made releases off, #142) would no
   longer compare. It is now held equal to the releases-off job, so its file does not change
   and its baselines keep comparing. Re-baselining in release mode after the switch is an owner
   question (below).
