- **Lane:** Phase 3, page editing
- **Design:** README row E10 (dep E1): "New section types: Text block, Gallery, Video (showreel
  window, zero bytes before intersection)"; CLAUDE.md §8 "Section engine"; [ui.md](../ui.md)
  AV-33 (the textBlock type: heading, accent, prose body; SECTION_TYPES, schema, renderer,
  registry, SECTION_UI) and the prototype's section library (`data.js`: Text block "Small label,
  headline and paragraphs", Gallery "Borderless image grid with lightbox", Video "Full width clip
  from the brand film"); as-built E1, E2, F5b, F6, U4, U6
- **PR:** not opened (branch `feat/e10-section-types`, local commits)
- **Migration:** none (Plan step 6 held: no DB change was needed, so 0120 is not used)

## Plan (written before the build)

Three new types, each through the section engine's one list and nothing beside it:
`packages/schemas/sectionTypes.ts` (`textBlock`, `gallery`, `video`), their strict content schemas
in `packages/schemas/sections.ts`, `RENDERED_SECTION_TYPES` and the SectionRenderer map, F6's
`SECTION_COPY`, `SECTION_READS`, `SECTION_UI` and the page editor's `SECTION_KINDS`. Authored content
arrives as props, route data after the spread (none of the three takes route data).

1. **Text block** (`textBlock`): tag, heading, accent (a word range of the heading) and a body
   of rich text per language (`body: { en, ar }`, both required, Tiptap JSON). Sanitised on
   write: the body is held to a STRICT allowlist schema of exactly what the admin's Tiptap
   (StarterKit, headings 2 to 4) produces and the allowlist renderer emits (no image node, no
   unknown node or mark, a link only to an href `sanitizeHref` keeps, bounded depth and size), so
   a document the renderer would silently alter is refused with a 422 rather than stored.
   Sanitised on render: `renderTiptapToHtml` (`src/lib/content/tiptap.ts`) builds the HTML from
   the JSON on every render; `set:html` only ever receives its output; no `style=`.
2. **Gallery** (`gallery`): tag, heading, accent and up to 12 images from the media library
   (`items: [{ kind: 'image', mediaId }]`, U6's gallery field, the media picker). The images are
   read by `getSectionImages` (the 0024 anon read keyed on `$.**.mediaId`, PUBLIC_MEDIA_COLUMNS, the
   password-page path through `page_media_unlocked`), rendered by `MediaImage` (`<Picture>`, the
   file's width and height, lazy, so CLS 0), each with the library's alt text in the page's
   language. A borderless grid whose columns follow the count, computed on the server.
3. **Video** (`video`): tag, heading, accent, a lead line, a poster from the media library
   (`mediaId`, the same anon read) and a clip window of a site file (`clip`, a `/media/*.mp4`
   path only, EXC-009). Rendered by `MediaFrame` in `inview` mode, so the served HTML carries
   the poster only (no `<video>`), and `src/lib/client/clips.ts` creates the video when the frame
   is on screen: zero video bytes before intersection, none under reduced motion, with Save-Data
   or on touch, paused while `body.motion-paused` (EXC-007's wiring). No poster, no section.
4. **The page editor:** SECTION_UI fields per type (rich text, the gallery grid, the media
   picker and the clip field), each kind in Add section on every routed page (generic blocks,
   any number a page), with its icon, description, collection link (Media library) and honest
   route note; the live preview renders them through R9's preview route with nothing new.
5. **CSS:** the three blocks are shared blocks any page may use, so their rules go in
   `global.css` (CLAUDE.md §8 file conventions), class-based, no `style=`, RTL-aware, on paper
   with tokens the contrast gate knows.
6. **No migration expected:** `page_sections.type` is free text (validated by the Worker's
   `SectionWriteSchema`); the media read policy, `media_usage()` and `page_media_unlocked` find
   the gallery's and the poster's ids by the `mediaId` key already; the release registry stages
   `content` whole. If the build finds a DB change is needed it goes in `0120`.
7. **JSON-LD:** to be decided per type and recorded below (expected: none).
8. **Tests:** schema (allowlist, hrefs, sizes, strictness), the registries' parity specs, F6's
   copy specs, SECTION_UI agreement, the library spec, render snapshots in EN and AR, a markup
   spec for the video (no `<video>`, in-view clip surface, lazy sized poster), and an e2e
   project run alone that puts the three blocks on a seeded page and checks axe, the video's
   bytes and the page editor.

## What was built

The plan held, but for two changes found while building and reviewing: the Video gained its own
pause control (departure 1), and the body's write check became an iterative walk of the raw
JSON (departure 7). The second review (Review 2 below) changed three things this section
describes as built since: the Text block renders through `renderSectionDocToHtml`, a page's
section media are read once by SectionRenderer, and a page holds at most eight Galleries and
Videos together. No migration: 0120 is not used.

### The types and their content (`packages/schemas`)

- `SECTION_TYPES` gains `textBlock`, `gallery` and `video` (`sectionTypes.ts`), and with it
  `RENDERED_SECTION_TYPES` (`src/lib/sections/registry.ts`), the SectionRenderer map, F6's
  `SECTION_COPY` (one empty look each), `SECTION_READS` (`media:all` for the gallery and the
  video, none for the text block), `SECTION_UI` and the page editor's `SECTION_KINDS`. Every
  parity spec holds them.
- **Text block** (`TextBlockSectionContentSchema`, strict): `tag`, `heading`, `accent` (a word
  range of the heading) and `body`, `SectionBodySchema` (`packages/schemas/tiptap.ts`):
  `{ en, ar }`, both required, each a document `sectionDocProblem` finds nothing wrong with.
  The walk takes exactly what the admin's editor makes (StarterKit: paragraphs, headings 2 to
  4, bullet and ordered lists, quotes, code blocks with a short language name, rules, hard
  breaks; bold, italic, strike, underline, code and links) and refuses anything the allowlist
  renderer would drop or change: an image, an unknown node or mark, a level 1 or 5 heading, a
  link to an href `sanitizeHref` drops (`sectionHrefKept` restates it; the spec holds the two
  equal over 29 hostile and ordinary hrefs), a stray key, a line break or rule with anything
  inside it, a document with no words, more than 300 nodes or more than 8 levels. A line
  break may carry its words' marks (Bold over two lines marks it too; its `<br />` is the
  same either way; review R1). It reads the raw JSON iteratively and never runs zod's
  recursive node schema (departure 7). Since Review 2 it also holds StarterKit's content model
  (a list item only in a list and opening with a paragraph, lists of list items only, words and
  line breaks only in a paragraph or heading, plain text only in a code block), each node's and
  mark's attributes by name with scalar values only (a `mediaId` cannot ride in a body), and
  each mark once a word; its refusals are plain sentences (P-12).
- **Gallery** (`GallerySectionContentSchema`, strict): `tag`, `heading`, `accent` and `items`,
  1 to 12 `{ kind?: 'image', mediaId }` (U6's gallery field writes `kind`).
- **Video** (`VideoSectionContentSchema`, strict): `tag`, `heading`, `accent`, `lead`, `mediaId`
  (the still) and `clip` (VideoClipSchema less a Stream UID: a `/media/*.mp4` path and its
  window only, EXC-009).
- Every field is optional and none has built-in copy (departure 2): `content: {}` is valid and
  renders nothing.

### The public components (`src/components/sections/`)

- `TextBlock.astro`: on paper, the tag, the heading as an h2 with its accent (AccentText: text,
  never HTML), and the body of the page's language rendered by `renderSectionDocToHtml` on
  every render (the section walk, then the allowlist walk on the JSON, no zod parse; an empty
  heading or list item renders nothing; Review 2); `set:html` receives that output and nothing
  else. No id (a page may hold several).
- `Gallery.astro`: on paper, the tag and heading, then a borderless grid of the pictures that
  resolve through SectionRenderer's one read of the page's section media, handed over as route
  data (`getSectionImages`: 0024's and 0102's `$.**.mediaId` anon read, PUBLIC_MEDIA_COLUMNS, a
  locked page's `page_media_unlocked`; Review 2), each a lazy `MediaImage` `<Picture>` with the file's
  width and height, cropped to a cell of one shape (4:3; 16:9 when alone), the library's alt in
  the page's language. Columns follow the count (`galleryColumns`, `src/lib/sections/blocks.ts`:
  one, halves for two or four, thirds otherwise; two a row on a phone).
- `VideoBlock.astro`: on black, the tag, heading and line, then `MediaFrame` (new ratio `wide`,
  16:9) in `inview` mode at a third visible: the served HTML has the still only; `clips.ts`
  creates the muted, `aria-hidden` video when the frame is on screen and never under reduced
  motion, with Save-Data or on touch; it pauses off screen, with the tab hidden and under
  `body.motion-paused`. Beside it the block's own pause control (departure 1).
- CSS in `global.css` (`.blk-*`, `.mf--wide`): shared blocks any page may use (CLAUDE.md §8), so
  no route sheet and no route change; headings capped in `em`; Klein accents on paper, sky on
  black; long authored words wrap.

### The page editor

- `SECTION_UI`: the Text block's tag, heading, accent and a `richtext` body (the lazy
  `admin-rich` editor; the new `bothLanguages` flag makes an English body with no Arabic count
  in "Arabic missing", through `docHasWords`, `src/lib/admin/docWords.ts`); the Gallery's tag,
  heading, accent and U6's picture grid (the media picker, up to 12); the Video's tag, heading,
  accent, line, a `media` still and a `clip` field limited to site files (`pathOnly`).
- `SECTION_KINDS`: "Text block" (icon `type`), "Gallery" (`image`), "Video" (`film`), each
  with a plain description, no page list, no `once`, no group: Add section offers them on every
  routed page, Text blocks any number a page, Galleries and Videos up to eight together
  (`MEDIA_BLOCKS_PER_PAGE`, the API's own check too; Review 2). Honest route notes ("It shows only what you write in it",
  "Each picture shows with its alt text", "Visitors see the still first. The film plays only
  while the still is on screen"), and the Gallery and the Video link to the Media library.
- The live preview (E2) shows them with nothing new: R9's preview renders the public route.

## Departures from the design, and why

1. **The Video has its own pause control** (not in the prototype): an editor may add a Video
   to any page, and without a control each would be one more autoplaying loop under EXC-007
   (WCAG 2.2.2, Level A), widened from the admin with no review. It follows the testimonials
   carousel (compliant, outside EXC-007): a 44 px button over the frame's end corner, named for
   what it does next ("Pause the film" / "Play the film", in Arabic too), `hidden` in the HTML
   and shown by `clips.ts` (`wireToggle`) only where the film can play. A frame stopped with it
   stays stopped, in view or not, until pressed again; other clip frames are unchanged.
   Recorded in `docs/security-exceptions.md` (EXC-007, 2026-10-29) as compliant, scope and
   expiry unchanged.
2. **No built-in copy**: every other type renders its design copy with no content; a block has
   none, so its fields start empty and a block with nothing written, no picture or no still
   renders nothing. A block added and forgotten never puts placeholder words on a page. F6's
   specs say so field by field (`NO_BUILT_IN`) and the render spec checks the empty render.
3. **No lightbox in the Gallery** (the prototype's "with lightbox"): the case study's viewer is
   one dialog a page with its rules in `case-study.css`; sharing it is a public CSS change of
   its own (owner question 1).
4. **No caption per picture**: the grid field (U6) edits order and pictures; each picture
   carries the library's alt text in the page's language.
5. **The Video's film is a site file only** and the block needs a still: Stream is not set up
   (KAN-20), and the still is what shows first and all that shows with reduced motion.
6. **No background, spacing or reveal choice**: that is E9. Text block and Gallery on paper,
   Video on black.
7. **The body's write check walks the raw JSON, never zod's recursive node schema** (found in
   the self-review): inside the 64 KB payload a document can nest about 1,900 deep, where
   `TiptapNodeSchema` overflows the stack (a RangeError, so a 500, not a 422, and a page whose
   loader met it would fail whole), and even 500 deep cost it about 75 ms. The walk is bounded
   (300 nodes, 8 levels) and its output also passes `TiptapDocSchema` unchanged. The first
   build said 300 nodes was also a CPU bound on the renderer's zod parse; Review 2 measured
   that parse at 6 to 26 ms warm for one body at the cap, so it was not, and the Text block no
   longer runs it (`renderSectionDocToHtml`: 0.3 to 1.4 ms warm for the walk and the render
   together, E10-S3).
8. **No JSON-LD** for any of the three, by decision: no `VideoObject` (a muted window of a reel
   has no title, description or upload date of its own to state truthfully, and a VideoObject
   promises a watchable video), no `ImageGallery` (the pictures are `<img>` with alt text in
   the HTML), and the Text block's words are in the Tier A HTML. The page's own JSON-LD is
   unchanged.
9. **No help guide change**: `editing-pages` says Add section lists the kinds a page can take,
   which covers the blocks; a sentence for them needs a migration restating the help set.
10. **A Tier A stylesheet changed, no page's HTML**: the blocks' rules are in `global.css`, so
    every existing page's markup is byte-identical (the render snapshots of every page are
    unchanged) and only `global.css` grows (Sizes).

All of these are in the deviations register ([deviations.md](../deviations.md), "Section
blocks").

## Review (2026-10-31, resumed after the builder was cut off)

The builder stopped right after the note above; the slice was complete against the plan. A
second read of the diff and a trace of the e2e against the markup found four things, each
fixed:

- **R1, a marked line break was refused.** ProseMirror's `addMark` marks every inline node in
  the range, the line break included, so Bold over two lines (or a pasted `<b>a<br>b</b>`)
  stores `{ type: 'hardBreak', marks: [bold] }`, and the walk refused any node but text with
  marks: a 422 on an ordinary edit. A line break may now carry marks (each still checked, a
  bad link refused), and a line break or rule holding anything inside it is refused, since the
  renderer writes `<br />` and `<hr />` and drops it. Guarded by `sectionBlocks.spec.ts` (the
  editor's output now holds a bold line break; four new refusals); red without the fix.
- **R2, an emptied body made the section unsaveable.** Typed in and emptied, Tiptap holds one
  empty paragraph, which the schema refuses ("write some text"), with the Arabic half missing
  besides: the form could not save until both halves had words. `formPayload.ts` now leaves a
  `richtext` value out of section content when neither language has words (a body cleared, or
  touched and left empty, saves as no body); words in either language are sent as written, so
  the server still names a missing half. Guarded by `formPayload.spec.ts` ("a Text block body
  with no words is left out"); red without the fix.
- **R3, the zero-video-bytes battery did not fully reach the Video.** `media-bytes.e2e.ts` runs
  on seeded routes, and the blocks are not seeded, so the block's own spec carried a partial
  copy: no Save-Data run, no "nothing mounted off screen after load" and no Arabic page. The
  battery is now one module, `tests/e2e/videoBytes.ts` (moved out of `media-bytes.e2e.ts`
  verbatim, its test names unchanged), which `media-bytes.e2e.ts` runs on every seeded route
  and `section-blocks.e2e.ts` on `/about` and `/ar/about` with the three blocks on them, plus
  the below-the-fold check on `.blk-video__frame` in both languages.
- **R4, the control's e2e could not fail.** CI's Chromium does not decode the H.264 film, so a
  video's `paused` reads true whether or not the control works. The test now counts `play()`
  calls on the frame's video (an init script): one in view, none back in view once stopped, one
  more once pressed again; without `stopped` in `play()` the second count fails. The consent
  banner, pinned over the bottom of the screen where the control sits, is removed first (as
  `media-bytes.e2e.ts` does on `/services`).
