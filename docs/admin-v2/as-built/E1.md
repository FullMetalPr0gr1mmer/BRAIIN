## Plan (written before the build)

Releases stay off in production until R14. Everything this slice writes goes through the
resource kernel's existing routes (`/api/admin/pages/[id]`, `/api/admin/sections`,
`/api/admin/sections/[id]`, `/api/admin/sections/reorder`), so with releases off every save is
the live save it is on `main`, and with releases on the kernel stages it (R3a): there is no
second write path. No public file changes, so Tier A HTML is untouched.

**Scope (E1 only).** The pages list, the page editor's shell and its sections column, the typed
fields per section type prefilled with the built-in copy, add / rename / hide / delete / reorder
sections, the SEO drawer and the History drawer. Not the live preview column (E2), section
appearance (E9), new section types (E10) or New page (E11).

1. **The pages list** (`/admin/pages`, server-rendered, zero JS): a card per page (an icon tile,
   the status badge, Hidden / Link only / Password from page visibility, "Unpublished changes"
   while releases are on, the title, "<path> · N sections", "Edited <ago>", Open page in English
   and Arabic, a stretched "Edit <title>" link) and the two template cards (the service and the
   project page, with their counts), which open the Services and Projects areas until E3 builds
   the template editors. Who may open it: `pages.write` or `seo.entityMeta` (Admin, Content
   Creator, SEO); anyone else gets the layout's refusal and a 403. "New page" stays hidden
   until E11.
2. **The page editor** (`/admin/pages/[id]`): the server page reads the page, its sections in
   order, the built-in copy of every look of every type the page shows or may add (F6's
   `SECTION_COPY`, its `notVerbatim` fields left out: F5b's contract for the `builtIn` prop),
   the SEO drawer's setup (U10's `loadSeoPanelSetup`) and the role's access, and hands them to
   one island, `AdminPageEditor`:
   - **the bar:** the status badge (and the pending badge with releases on), English / العربية
     / Both with "Arabic missing: N", Visibility (a link to the visibility screen for
     `maintenance.manage`, the page's mode as a badge for everyone), SEO, History, Open page
     (English, Arabic), and with releases on Preview and Publish (`openPublishDialog`, R12);
   - **the sections column** (`aside aria-label="Sections"`): "Page details" (the title and the
     status), then a row per section: the Sortable handle and Move up / Move down, its label
     (the new `page_sections.label`, else the type's name), the type as a kicker, the eye
     switch ("Show <label> on the site"), `aria-current` on the open one; Add section (a modal
     of the types this page takes, each with its icon and a plain description, the ones it may
     not take disabled with the reason);
   - **the fields column:** the section's name, type and anchor, Rename (a dialog), Delete for
     an Admin (`content.archiveDelete`) or "Hide it instead" for a Content Creator, the honest
     notes on route data and the rows that link to the collections the section shows, then
     its typed fields (`SECTION_UI`) through `EditorForm`, prefilled with the built-in copy,
     storing only what differs (F5b's plumbing, wired here);
   - **SEO drawer:** the shared `SeoPanel` in a drawer, writable for Admin and SEO, read only
     for Content Creator (§5); SEO opens the editor with the SEO drawer only (it reads no
     section);
   - **History drawer:** the open item's numbered saves (R10's `GET /api/admin/history`) and,
     with releases on, the site versions that changed this page, with Preview and Restore
     (R10's routes) for a role that may publish them.
   - **Saving:** live with releases off (Save, version, the 409 banner; switching sections with
     unsaved changes asks first); with releases on the editor follows the server into draft
     mode (R12) with an 800 ms idle autosave.
3. **Migration 0113:** `page_sections.label` (text, null, at most 60 characters, no control
   character), the release registry's `page_section` row restated with the column, and one
   new guide (`editing-pages`) through H11's catalog.

## What was built

The plan held; what differs is under Departures.

### The data (0113, placeholder)

- `page_sections.label`: text, null, CHECK `page_sections_label_shape` (1 to 60 characters,
  trimmed, no C0/C1 control character), the same rules as `SectionLabelSchema`
  (`packages/schemas/admin.ts`, `SECTION_LABEL_MAX` in `packages/schemas/sectionTypes.ts`). No
  grant changes: staff write it under the table's RLS as every other column, and anon's
  table-level SELECT (0016) reads it on a visible section of a published page, as the
  verification accepted. No public file reads it.
- `app.release_entities`' `page_section` row restated with `label` appended to its columns
  (0038's row otherwise word for word; no later migration restated it), so a release stages a
  rename. `src/lib/release/registry.ts` derives the same list from the resource config.
- The `editing-pages` guide through H11's `app.put_help_guide` at place 41 (40 is
  saving-and-publishing, 42 U5 + U6's services-and-projects), the literal equal to
  `docs/admin-v2/guides/editing-pages.json`; `PAGE_GUIDES` maps `/admin/pages` to it.
- Rule 5: no reader's shape changes for the deployed Worker (explicit column lists; the
  preview's `PageSectionRowSchema` is not `.strict()`). The production read-back is the
  scratchpad's `readback_e1.sql` (written for 0113).

### The pages list (`/admin/pages`, server-rendered, zero JS)

`src/lib/admin/pages/list.ts` reads pages, their section counts, page visibility and the
pending changes of pages and sections (`content_drafts`, none while releases are off) under the
person's RLS, plus the published service and project counts for the two template cards. A card
per page: icon tile, status badge, Hidden / Link only / Password, "Unpublished changes" (releases
on), the title, "<path> · N sections", "Edited <ago>", Open page in English and Arabic, and a
stretched "Edit <title>" link. The template cards open the Services and Projects areas. Who opens
it: `mayOpenPages` (pages.write, or seo.entityMeta at any access: Admin, Content Creator, SEO);
Developer and Sales get `Refused.astro` and a 403 having read nothing (`LOCKED_SCREENS`).

### The page editor (`/admin/pages/[id]`, the `AdminPageEditor` island)

- **Server half** (`src/lib/admin/pages/editor.ts`): `pageEditorAccess` (sections, remove,
  publish, seo, visibility, from ROLE_CAPS, UX only), `builtInLooks()` (F6's `SECTION_COPY`, each
  look less its `notVerbatim` fields, handed over as props so the copy never ships in the
  bundle), `loadEditorPage` (page row and visibility mode, a UUID check first, 404 otherwise),
  and U10's `loadSeoPanelSetup` for a role with seo.entityMeta.
- **The bar:** All pages (back), status badge, the visibility badge when not public, English /
  العربية / Both with "Arabic missing: N" and Next gap for the whole screen (EditorForm's
  `languageBar: 'page'`), Visibility (a link to `/admin/visibility`, maintenance.manage), SEO,
  History, Open page (English, Arabic), and with releases on Preview and Publish (R12's
  `openPublishDialog`).
- **The sections column** (`SectionsColumn.tsx`, `aside aria-label="Sections"`): Page details,
  then each section in the site's order: Sortable handle (drag and keys) plus Move up / Move down,
  the label or the kind's name, the kind as a kicker, the eye switch ("Show <label> on the
  site"), `aria-current` on the open one; Add section (`AddSectionModal.tsx`: the kinds the page
  may take, each with its icon and description, the others disabled with the reason). Only the
  rows whose number moved are written (`orderChanges`, as the collections do).
- **The fields column:** `SectionPanel.tsx` (name, kind, anchor; Rename, a dialog that stays
  mounted so focus returns; Delete for content.archiveDelete, "Hide it instead" for a Content
  Creator; the route notes and the collection link rows from `library.ts`; then SECTION_UI's
  typed fields through EditorForm, accent word ranges and variant selects included, prefilled
  with the look's built-in copy through F5b's `builtIn`, storing only what differs) or
  `PagePanel.tsx` (the page's title, status and schedule: the legacy page form less the address).
- **Section library** (`library.ts`, pure): the kinds' names, icons, descriptions, which pages
  take each (the heading, form and projects groups take one member a page), anchors, the honest
  route notes and the collection links, held to the routes' own rules and to F6's `builtInLook`
  by `tests/lib/pageEditorLibrary.spec.ts`.
- **SEO drawer:** U10's `SeoDrawer`, writable for Admin and SEO, read only for Content Creator.
  SEO opens the editor on a card that offers the SEO drawer only and reads no section.
- **History drawer** (`HistoryDrawer.tsx`, `history.ts`): R10's `GET /api/admin/history` for the
  open item (the section or the page details), newest first, under the person's RLS; with
  releases on, Restore a save as an unpublished change, and the site versions that changed this
  page with Preview and Restore this page (R10's routes), for a role that may publish.
- **Saving:** every write is the resource kernel's (`/api/admin/sections`, `/sections/[id]`,
  `/sections/reorder`, `/pages/[id]`). Releases off: explicit Save with version and the 409
  banner (Ctrl or Cmd + S through `useEntitySave`), and switching sections with unsaved changes
  asks first. Releases on: the server puts the form in draft mode (R12) with an 800 ms idle
  autosave, a switch flushes it, and the column's writes name the row's pending change (or carry
  R12's release-mode marker, `?staged=1` on a removal) so one sent after a switch-off is refused,
  never written live. A column write to the open section moves its version; the open form
  follows it (`formSyncAfterWrite`: adopt the version with releases off, `rebase()` with them on,
  a new optional member of `EntitySave` that reads the record again and keeps what was typed).
- **EditorForm** gains `hidden`, `builtIn` and `languageBar`, each off unless asked for; without
  them the output is byte for byte what it was (`tests/lib/editorForm.spec.ts`).
- **Bundle:** the island and `screens/pageEditor/` are their own `admin-pages` group
  (`astro.config.mjs`, between `admin-content` and `admin-screens`), as the plan named; the SEO
  drawer and the collections' `reorder.ts`, which the editor shares with the SEO and collection
  screens, moved into `admin-fields`, so the editor loads no other screen group and no other
  screen loads the editor. `scripts/admin-bundle.mjs` holds it (a family group on its island
  only, never importing `admin-screens`, `admin-content` or `admin-leads`), tested in
  `tests/lib/adminBundle.spec.ts`. Tiptap is reached only through `admin-rich`.
- **CSS:** `public/styles/admin/pages.css`, listed in `src/lib/admin/stylesheets.ts`; no `style=`
  anywhere; one column below 1024 px, the sections above the fields.

## Departures from the design, and why

1. **`admin-pages` is a family group, not a member of `admin-screens`** (Wave 3 correction 7
   asks new islands to join the shared group by path): in the shared group the editor's code
   rode on every screen that loads it (the collections, SEO, media, General settings and four
   more: 212.6 to 222.0 KB eager each) and the editor loaded all of theirs. U5 + U6 set the
   precedent with `admin-content`. Measured below.
2. **Visibility is a link to the visibility screen**, not a drawer reusing AV-13: the setting has
   its own screen and API (maintenance.manage), so there is one write path. The page's mode
   shows in the bar as a badge.
3. **History's Restore exists only with releases on:** R10's restores stage a change, and with
   releases off there is nothing to stage into; a live restore would be a second write path. The
   list of saves shows in both modes.
4. **Collection link rows carry no item counts** ("Managed in Testimonials · 3 items"): a count
   per row would be one more read per section for a label; the link and its plain line remain.
5. **joinWhy and joinSteps items are SECTION_UI's inline repeater** (up to four, the steps' time
   label kept), not a collection-style list with a drawer: the repeater is the field kit's, and
   four short items do not need a drawer.
6. **SaveStatus sits with the form in the fields column**, not in the bar: each panel (a section
   or the page details) is its own save, so its state belongs beside it.
7. **The page's h1** is AdminLayout's title (the page's English title, `dir=auto`); the bar does
   not repeat it.
8. **Template cards open the Services and Projects areas** until E3 builds the template editors;
   **New page** stays hidden until E11; the live preview column is E2's; section appearance E9.

## Releases off means main

Every write is the existing resource routes', so with releases off the requests are main's,
except a rename's `label` key: the releases-off write snapshot
(`tests/lib/releaseOffWrites.spec.ts`) gains exactly that key for sections (`toRow` and the key
map) and nothing else moves. The pages list's `content_drafts` read finds no row while nothing is
staged. No public file changes, so Tier A HTML is untouched.

## Self-review (two lenses)

- **Security and authz.** The server page decides who opens the editor from ROLE_CAPS and reads
  only under the person's RLS; every button's route checks again. A Developer or Sales token
  gets a 403 before any read. No new route, no grant change; `label` rides the table's grants
  and RLS (pgTAP). Built-in copy is server data in props, no HTML is stored (accent ranges are
  word indices), and no `style=` is drawn.
- **Releases off.** Column writes send main's requests (no marker, no draft keys) while the row
  was read with no `draft` key (`columnWriteRef`, `pageEditorModel.spec.ts`). Residual, R12's:
  Add section and a reorder sent from a screen left open across a switch-off are POSTs, which
  R12's `releases-off` refusal does not cover (it guards PATCH and DELETE); a section so added
  is hidden and empty, and an order so written is the order the person chose. Raised for R12.
- **Found and fixed in this pass:** the editor's code rode on every `admin-screens` screen
  (departure 1); fixed with the `admin-pages` group, guarded by four new
  `adminBundle.spec.ts` tests that fail without it (checked by reversing the change).
